Windowed-MTP: Removing the Full-Context Draft-KV Tax at Million-Token Context

⭐⭐⭐⭐☆ (4/5)
作者: Alagappan Valliappan  |  机构: NVIDIA  |  分类: cs.LG  |  日期: 2026-07-25
arXiv · PDF
Speculative decoding 通过让廉价的 draft head 提出候选 token、再由 target 模型并行验证来加速自回归生成。前沿模型普遍内置 MTP/NEXTN draft head,前提是 draft 成本可忽略。但在百万 token 上下文下这一假设崩塌:MTP draft head 每步都要对整个 KV cache 做 full attention,读取量随上下文线性增长。本文对 draft attention 施加 StreamingLLM 式 sliding window + attention sink,验证保持 full attention 不变,training-free 且构造上无损。在三大架构族上 per-decode-step 成本降低 28%-44%,增益随上下文增长。

核心贡献

  • 识别并量化百万 token 上下文下 MTP draft head 的"全上下文 draft-attention 税":1M 时额外增加 +92% 到 +138% 开销,并给出预测 native draft 加速何时崩溃至平局或反转的 latency 模型
  • 提出 Windowed-MTP:对 draft 注意力施加 StreamingLLM 风格 sliding window + attention sink(W=4032),验证保持 full attention 不变,training-free、drop-in、构造上无损
  • 跨三大架构族(Qwen GDN-MoE 35B/122B、Mamba2-hybrid NoPE 120B)验证 +28%~+44% 输入不变 per-decode-step 成本下降,增益随上下文增长而扩大
  • 将 draft KV 池(1M 时占总 KV 7.7~11.1%)物理回收到 W+sink 的 compact ring buffer,零质量/速度代价释放 HBM 提升并发

主要结论

  • Windowed-MTP 保持 acceptance profile:逐位置 conditional acceptance 跟踪 native 在 95% Wilson 区间内;深位残差 acceptance 变化小、输入/模型相关且符号不定,始终被 per-step 加速抵消,端到端从不回归
  • 构造上无损:full-attention target 仍决定每个接受 token,经 windowed-vs-native output diff 验证(仅 bf16 验证噪声,无额外分歧),输出分布严格等于 target
  • 收益随上下文增长:261K→1M per-step 节省近乎翻倍,机制仅依赖 draft KV 长度 S,可移植至非 Blackwell 硬件(H100 复现)与 fp8 KV
  • 恢复硬任务/低 acceptance 区域的 deep speculation 净正值:native MTP 在 Qwen-122B code-QA 跌至 0.80× dense、Nemotron fwe 0.97×,windowing 在各处恢复正加速

实验结果

  • 1M context、B=1、d=7 上,windowed vs native MTP 端到端加速 +11%~+53%(TPOT ms:native→windowed,Qwen-35B 5.94→3.89、Qwen-122B 6.09→5.46、Nemotron 8.77→7.15),vs dense(无推测)1.58~2.55×
  • Cost-side per-decode-step 降幅 +28%~+44%(Table 1:Qwen-35B +44.3%、Qwen-122B +30.2%、Nemotron +28.3%);261K→1M 节省近乎翻倍
  • Best-depth 对比(各方法取自身最优 d∈{3,5,7,9}):windowed-MTP 在每个(model,task)单元严格快于 native(1.22~1.58×),含 code reasoning
  • Ring buffer 回收 7.7~11.1% draft KV 池,允许更高并发;单 B200 peak 473 tok/s/GPU、2.1× dense
  • TP2(2×B200)batch-concurrency sweep B=1..13:windowed-MTP 在每 batch Pareto-dominate native 与 dense,throughput 上限较 native 扩展 1.15~1.25×、较 dense 1.7~2.3×
为什么重要: 揭示了 MTP speculative decoding 在百万 token 上下文下的根本性瓶颈并给出 training-free 无损解法,对 SGLang/vLLM 等推理引擎在长上下文场景的落地有直接价值

Chemical Chain-of-Thought Functions as a Hallucination-Prone Molecular Scratchpad

⭐⭐⭐⭐☆ (4/5)
作者: Jiatong Li, Yuxuan Ren, Weida Wang  |  机构: National University of Singapore; Hong Kong Polytechnic University; Fudan University  |  分类: cs.CL  |  日期: 2026-07-25
arXiv · PDF
化学推理语言模型被期望通过忠实的思维链(CoT)推导分子答案。然而跨四个推理模型家族和十二个化学任务,幻觉普遍存在且与答案正确性基本解耦:正确答案常伴随虚构的结构性声明(在相关分子中不存在的官能团)。但这并不意味着推理轨迹计算上无关紧要。归因分析表明存在模型特异性的"分子草稿本"功能:Chem-R/ether-0 依赖碎片化 SMILES 草稿,ChemDFM-R 强调骨架、位置和命名线索。值得注意的是,扰动 Chem-R 的 SMILES 草稿会降低生成质量,说明结构草稿即使在文本声明大致无效时仍具有因果支撑作用。化学 CoT 既非忠实解释也非纯粹事后合理化,而是易产生幻觉的分子草稿本。

核心贡献

  • 提出分子 claim-grounding 框架,将化学 CoT 推理轨迹视为可验证的官能团声明集合,通过 RDKit SMARTS 精确匹配与分子图核对,并定义诊断性失败模式 extrinsic reasoning fabrication (ER,即在推理轨迹中断言但输入/预测/参考答案中均不存在的官能团)
  • 在 4 个推理模型家族和 12 个化学任务上系统证明幻觉普遍存在且与答案正确性基本解耦:正确答案常伴随虚构的结构性声明
  • 通过因果干预(扰动官能团声明 vs 输入、扰动 SMILES 草稿、注意力和梯度显著性分析)解析该悖论,揭示化学 CoT 既非忠实解释也非纯粹事后合理化,而是模型特异性的"分子草稿板"
  • 提供 verification-grounded RL 概念验证(Chem-R-Faithful,GRPO 训练并将答案精度奖励门控于 ER=0),在不损失报告任务指标下显著降低 ER 73-95%

主要结论

  • 化学 CoT 既非忠实推导也非纯事后合理化,而是一个"易产生幻觉的分子草稿板":其可读散文常缺乏依据,而草拟的结构片段即使在文本声明大致无效时仍对生成具有因果支撑作用
  • 仅基于答案的评估不足以评估化学推理(准确率与 ER 的 |Pearson|<0.02),因此不应将 CoT 视为忠实推理的直接证据,需要超越答案层面的过程级监督
  • 草稿板形式具有模型特异性,不应假设通用 CoT 格式,且仅针对 SMILES 的探针会遗漏 ChemDFM-R 中的候选信号
  • 在分子设计/逆合成/药物发现中,仅依赖自然语言推理进行人工审查存在风险,虚构官能团可能被误读为答案的证据

实验结果

  • 幻觉普遍:5 个模型平均 ER 跨任务为 7.6–26.4,声明级 fabrication 率为 14→23→38→55%,遵循发布模型排序;最忠实的发布模型仍有约 1/7 声明为虚构
  • 幻觉与答案正确性解耦:Chem-R(n=3300)正确与错误答案的 ER 分布几乎重合(均值 6.4 vs 6.8),|Pearson(ER,exact match)|<0.02;约 31% 正确响应含虚构;语义熵与幻觉反相关(Pearson -0.54),长度无法解释
  • 轨迹声明扰动 vs 输入扰动:扰动轨迹内官能团声明仅翻转 1–11% 原本正确答案(近义控制水平,Δlog p=-0.0007),而扰动输入翻转 16–79%(Δlog p 低 2-3 个数量级)
  • SMILES 草稿具因果载荷:用合法但错误的结构替换草稿 SMILES 翻转 Chem-R 11.4% 答案 vs 官能团名扰动 5.7%(2×),Chem-R-Faithful 31.9% vs 1.8%(18×);ChemDFM-R 作阴性对照
  • Verification-grounded RL:Chem-R-Faithful 在 4 任务家族上将 ER 降低 73–95%(caption-to-molecule 6.7→1.8,retrosynthesis 15.1→0.8),声明级 fabrication 率降至 4%,无报告任务指标损失
为什么重要: 首次系统揭示化学领域 LLM 推理轨迹中幻觉与答案正确性的解耦现象,并通过因果干预解析 CoT 的"分子草稿本"本质,为领域过程级监督提供了新的评估与训练范式

REFACT: Adaptive Fact Restatement for Compact and Faithful Chain-of-Thought Reasoning

⭐⭐⭐⭐☆ (4/5)
作者: Zhensheng Jin, Xin Dai, Zhenghao Liu  |  机构: Northeastern University (Shenyang); Tsinghua University  |  分类: cs.CL  |  日期: 2026-07-25
arXiv · PDF
大语言模型在复杂任务上越来越依赖长链推理,但当证据稀疏、噪声或与参数知识冲突时,推理轨迹可能偏离给定上下文。现有 grounding 方法要么在生成后附加引用,要么鼓励在轨迹内检索证据,但往往不能确保引用内容对局部推理和最终答案足够充分。REFACT 是一个自适应事实重述引用框架,训练模型决定何时需要 contextual grounding 以及以何种粒度重述源事实。通过两阶段 SFT-to-RL 管道优化,citation-utility 奖励鼓励引用事实格式良好、可溯源且答案充分。在 LongBench、LV-Eval 和 ConFiQA 上,REFACT 提升长上下文 QA 与反事实忠实性,同时大幅减少 token 消耗。

核心贡献

  • 提出 REFACT 自适应事实重述框架,教模型自主决定何时需要引用以及以何种粒度重述源内容,将引用转化为答案支撑的中间状态而非事后归因
  • 设计两阶段 SFT-to-RL 训练管道(GRPO),引入四维 citation-utility 奖励:format/accuracy/traceability/answerability,其中 answerability(引用内容足以回答问题)是核心创新
  • 构造长度多样化(32k/64k/128k)的引用增强推理数据集,利用教师模型生成、验证器模型筛选答案充分的轨迹
  • 在 LongBench/LV-Eval/ConFiQA 上系统验证长上下文 QA、引用质量与反事实忠实性的协同提升

主要结论

  • 自适应引用重述优于暴力引用:REFACT 以更少重述事实保留更多答案相关证据,推理轨迹"更密而非更长",证明紧凑性与忠实性可兼得
  • citation-utility 奖励(尤其 answerability)是关键训练信号——仅 SFT 或仅 format/accuracy 奖励收益有限,加入 traceability+answerability 后显著提升
  • REFACT 将引用转化为答案支撑的中间推理状态,从根本上区别于 post-hoc 引用与固定位置事实复述两种既有范式

实验结果

  • LongBench v1:Qwen3-4B/8B 上平均 F1 最佳(55.3/58.4),相比 Zero-Shot 平均推理长度约减半,相比 CARE 更短且更高分
  • LV-Eval(16k–128k 受控上下文):所有长度上平均 F1 均最佳,4B/8B 分别领先 CARE 5.1/2.4 点、LongFaith 4.0/4.6 点
  • ConFiQA 反事实忠实度:EM/PS 升、PO 降(4B 平均 PO 11.6 vs Zero-Shot 17.1),减少对参数知识的依赖
  • 引用质量:4B 平均 F1 45.2(vs CARE 44.0)但 #Facts 仅 9(vs CARE 32),实现"更少事实更高覆盖"
  • 消融:SFT(label) 几乎无效,加 RL 顺序 R_format/R_acc→R_trace→R_ans 逐步提升,最终 ReFact 4B/8B 平均达 55.3/58.4,验证 answerability 奖励的关键作用
为什么重要: 首次将引用建模为答案支撑的中间推理状态而非事后归因,通过 answerability 奖励实现紧凑性与忠实性的协同,为长上下文 RAG 推理的引用质量提供新范式

OpenForgeRL: Train Harness-native Agents in Any Environment

⭐⭐⭐⭐☆ (4/5)
作者: Xiao Yu, Baolin Peng, Ruize Xu  |  机构: Columbia University; Dartmouth College; Microsoft Research  |  分类: cs.CL  |  日期: 2026-07-25
arXiv · PDF
现代 AI 智能体依赖 Claude Code、Codex、OpenClaw 等复杂推理 harness 来驱动多轮推理、工具使用和外部系统访问。但这些复杂 harness 也使智能体难以用开源基础设施端到端训练(SFT/RL 栈无法原生表达有状态的多进程 harness 推理)。OpenForgeRL 是一个开源框架,用于在任何环境中端到端训练 harness-based 智能体。通过轻量级代理服务 harness 的模型调用并记录为训练数据(标准 RL 代码库如 veRL),配合 Kubernetes 编排器在每个 rollout 的独立远程容器中运行,实现任意 harness × 任意环境的规模化训练。在 ClawEval、OSWorld、Online-Mind2Web 等基准上超越同等规模开源基线。

核心贡献

  • OpenForgeRL:可扩展插件式训练基础设施,通过轻量级代理拦截 harness LLM 调用并重建训练轨迹,将真实 harness 生态与远程云沙箱(Microsoft Azure/Kubernetes)连接到标准 RL 代码库(veRL),每个 rollout 在独立远程容器中运行
  • 广泛的实证研究:涵盖文本工具/Claw 智能体(ZeroClaw、OpenClaw、Codex、ReACT)和多模态 GUI 智能体(Kimi-Agent 计算机使用、Molmo-Web 浏览器使用),在几乎所有基准上超越同等规模开源模型,部分超越大数倍模型
  • 基于真实部署 harness 训练的 harness 选择与 RL 行为塑造的新颖分析:更简单、对齐更好的 harness 更易学习;训练增益可跨 harness 迁移;RL 提高智能体可靠性(自我验证、工具覆盖、多步计划完成),但错误恢复仍然薄弱

主要结论

  • OpenForgeRL 将训练与推理解耦,任意 harness × 任意环境均可通过标准 RL 代码库端到端训练,可在真实部署环境中优化智能体而非简化重实现,消除训练-部署不匹配
  • 训练增益可迁移至训练期间未见过的 harness,且同时在多个 harness 上训练效果最佳(在 Codex +20.3 等更复杂的 harness 上增益最大)
  • RL 主要提高智能体可靠性:模型会验证自身行为,覆盖每项任务所需的更多工具,并完成多步骤计划;然而即使在 RL 之后,错误恢复仍然很弱,表明某些能力可能需要专门的数据

实验结果

  • OpenForge-Claw (30B-A3B MoE, Qwen3-30B-A3B-Thinking 主干, GRPO RL):ClawEval pass^3=31.7 且 pass@3=55.9,QwenClawBench pass@1=33.7,MCPAtlas pass@1=28.1,在几乎所有基准测试中均优于同等规模的开放基线
  • OpenForge-GUI (8B, Qwen3-VL-8B-Thinking 主干):OSWorld-Verified=37.7,Online-Mind2Web=63.0,WebVoyager=72.3,优于同等规模的基线,并达到/超过大数倍的模型
  • harness 难度分析(表 4):ReACT/ZeroClaw 达到最高性能(ZeroClaw pass@1=48.5, pass@3=67.1);OpenClaw/Codex 更难,SFT+RL 增益较小
  • 跨 harness 泛化(表 5):ZeroClaw-only 训练改进了未见过的 OpenClaw (+3.3) 和 Codex (+4.6);3 个 harness 训练产生最大增益(OpenClaw +9.5, Codex +20.3)
  • RL 行为效应:将通用 shell 调用从 22.6% 降低至 13.9%,加强了自我验证和工具覆盖,但错误恢复仍然很弱
为什么重要: 首个将任意部署 harness 与任意环境连接到标准 RL 代码库的开源训练框架,为 harness-native 智能体的端到端 RL 训练开辟了新路径,消除了训练-部署不匹配

MemTools: A Unified Research Framework for Interoperable Agent Memory

⭐⭐⭐⭐☆ (4/5)
作者: Chengfeng Zhao, Jinhui Chen, Sirui Liang  |  机构: Institute of Automation, CAS; University of Chinese Academy of Sciences; Beijing Academy of Artificial Intelligence; Zhongguancun Institute of Artificial Intelligence  |  分类: cs.CL  |  日期: 2026-07-25
arXiv · PDF
记忆系统是智能体架构的关键,但普遍的架构碎片化限制了系统研究。现有实现通常耦合记忆生命周期不同阶段、将评估逻辑与特定数据集纠缠、对异构记忆类型管理支持有限。MemTools 是一个互操作性研究框架,将记忆系统组件从底层部署环境解耦。通过声明式数据契约标准化记忆生命周期,使跨系统组件可互换组装;将基准数据集与执行协议正交解耦便于受控评估;提供统一计算接口协调符号、神经和多模态记忆表示在共享运行时内协同。跨系统组件集成、评估协议重组和异构记忆协调的实证评估表明,MemTools 能系统隔离分析记忆设计变量。

核心贡献

  • 通过声明式数据契约(declarative data contracts)标准化记忆生命周期接口,使跨系统的记忆组件(formation/retrieval/backend/evolution/utilization)可互换组装
  • 将基准数据集与评估协议正交解耦,把 protocol 作为可配置参数,便于隔离记忆设计变量与性能差异来源
  • 提供统一计算接口,协调符号、神经、多模态等异构记忆表示在共享运行时内协同
  • 构建可扩展的互操作研究基础设施,集成多个适配器(SimpleMem/Mem0/ExpeL/AWM/LightMem/StructMem/A-Mem 等)与 10+ 评估协议、8+ 基准

主要结论

  • MemTools 通过声明式数据契约、正交协议解耦与统一异构表示接口,有效将核心记忆管道与部署环境解耦,缓解 agent memory 研究的结构性碎片化
  • 案例研究(跨系统集成、协议重组、异构协调)证明框架可用于系统化隔离分析记忆设计变量
  • 局限:自动匹配引擎仅验证结构兼容性,可能存在行为对齐差距;抽象层带来轻微计算开销;大规模异构数据库与超长任务边界可能有性能瓶颈
  • 为 agent memory 系统化、比较性研究提供通用且可扩展的基础设施

实验结果

  • 跨系统组件集成:AWM formation + A-Mem backend/retrieval 混合管道在 ALFWorld 成功率 43.28,超过原生 AWM 的 40.30;pipeline 不兼容成因分布为 dataset-to-formation 37.0%、retrieval 23.9%、backend init 20.1%、utilization 19.0%
  • 协议解耦:同一 AWM 管道下 Batch 协议成功率 40.30 vs Stream 协议 33.58,差异完全归因于记忆形成时序而非算法
  • 异构记忆协调:Mem-Gallery 上 A-Mem+Omni-SimpleMem 协调 F1 35.3,超过单独 30.1/31.2;ALFWorld 上 AWM+NPM 51.5,超过单独 48.5/32.1

  • 提供 protocols×benchmarks 兼容性热图,揭示 agent-centric 环境与 user-centric QA 任务的二元聚类结构
