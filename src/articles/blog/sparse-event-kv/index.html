全局计算，局部物化
Sparse Event-KV 的内存契约

当长程 agent 把 KV cache 当作记忆复用，serving 系统只保留一部分行、丢弃其余——这隐含一个从未被直接验证的前提：被保留的 event 的 KV 行，在产生它的 source 已被丢弃后，是否还能独立承载那个 source 的状态？这篇论文直接测试它，并给出一个可编程的"语义物化"原语。

作者：Zefeng Cai, Zerui Cai 独立研究者 Qwen3-8B · Gemma-4 · Ministral-3 含动画可视化

01
Executive Summary

执行摘要：一个被默认的前提被直接验证

先给结论，再展开机制、契约与证据。

核心发现

被丢弃的 source 仍通过下游行回答

agent 历史 𝒯 = (e₁,…,eₙ) 中，某个 source event 设定了一个状态（如"寄存器 S 在线"），一个下游 event 只是说"M mirrors S"。当 serving 丢弃 source、只保留下游行时，问 M 的状态——答案仍然 99:0 跟随被隐藏的 donor，即使 没有任何被服务的 span 点名"online"。论文称之为 semantic materialization（语义物化）：下游 event 的 contextualized KV 行是"一个可独立服务的、对已消失输入的计算视图"。

可编程

不只是被动观察——可以主动写入

论文不仅发现这个现象，还把它做成一个原语。一个刻意措辞、不含答案的 carrier event（如"MM mirrors SS"），放在 source 之后，能把 donor 对齐恢复率从 6% 提升到 51%。而被动地从长程对话里收割自然提及，则检测不到任何收益。这意味着"记忆写入"是一个需要校准的、依赖措辞而非语义的写时操作。

边界

能携带什么：紧凑状态存活，大负载衰减

物化是有界且具体的。二值状态（online/offline）原生恢复到 .934；四向、八向负载向随机衰减；精确数字载荷几乎无法原生恢复；verbatim 字面措辞只在 9.7% 的配对中转移——和随机不可区分。所以这不是"任意信息都能塞进 KV 行"的万能通道，而是一条窄但因果可信的信道。

对 eviction 的推论

消融无精度损失 ≠ source 不必要

对任何做 eviction 的人，最直接的推论是：你丢掉一个 source event、观察到精度没掉，这不能证明 source 不必要——它可能已经把状态物化进了你保留下来的某一行里。经典"丢掉看精度"的消融在 sparse-KV serving 下系统性高估了可丢弃性。

一句话判断： 在 sparse event-KV serving 下，"选行"不等于"只选它的可见 token 内容"——contextualized 事件行可以携带被丢弃 source 的计算结果。论文把这套行为提炼成 trigger / landing / access 三段契约，让"写什么、落在哪、丢弃后存留什么"成为可工程化的接口。
02
The Serving Contract

服务契约：为什么这个问题不平凡

三条规则让"丢掉 source 还能答"成为一个有意义而非显然的实验。

论文把实验置入一个 serving contract：源事件被排除在服务集 Σ 之外；donor 对比只在"两个 donor 输出不同"的项上进行；readout 的放置是协议选择而非自然给定。三条核心谓词贯穿全文：

谓词 1

Materializes（物化）

一个被服务的 span e 对 readout q 物化了值 v，当它的 contextualized 行 KV(e) 相对于孤立重编码相同文本，诱导出 donor 对齐行为——即答案跟随被丢弃的 donor 而非它的反面。

谓词 2

Trigger / Carrier（触发/载体）

trigger 是让一个 event 做这件事的写时构造。carrier 是这样的一个 event——它的 KV 持有上游派生的状态，而文本里不点名该状态。"MM mirrors SS" 是一个典型 carrier：它读 SS 但不说 SS 是 online 还是 offline。

谓词 3

Conditional Landing（条件着陆）

一个 span 是 conditional landing，当它在 span 级消融下仍物化 v——即把它与固定的 donor 无关脚手架（decoy + 无关 register）一起服务时，它单独承载 donor 信号。

关键设计： query 的放置是协议选择，不是自然给定。retained 行始终保留原始位置 id；只有 query 放在哪是可调的。合成 arm 把 query 放在 carrier 之后的槽位——这与"把 query 放在 source 之前"不等价，后者会破坏因果方向。

03
Discovery

发现：一个被服务的行，能从被丢弃的 source 回答

论文的核心实验与 99:0 分裂。

具体场景（见下方动画）：一个 event 写"寄存器 S online"，一个后来的 event 只说"M mirrors S"。我们丢弃第一个、服务第二个，然后问 M——没有任何被服务的 span 说"online"。在 Qwen3-8B 上，分裂是 99:0（p = 3.2×10⁻³⁰）：99 个 donor-sensitive 项跟随我们丢弃的 source，0 个跟随反面。

图：语义物化的四步实验。① 全局 prefill 时 carrier 注意到 source，其 KV 行被"写入"source 的状态。② 丢弃 source 行。③ 只服务 carrier + decoy + query。④ 答案仍跟随被丢弃的 donor。

比例只数 donor-sensitive 项

99:0 不是整体恢复率。它只数两个 donor 输出不同的配对（donor-blind const 对被排除），所以报告的是方向而非恢复率。一个 256 配对复制给出了同样的分裂，排除了小样本偶然。

跨服务设置、模型、readout 都成立

无论 carrier 独自服务、还是与提及共服务、还是不同 readout 形式——donor-following 都成立。语义极性存活；verbatim 措辞很大程度上不存活。一个显式更新（后来 event 重置值）会覆盖被物化的状态——说明这条信道有"最后写入者"语义。

04
Trigger

触发：哪些 event 会物化状态

不是每个读上游状态的 event 都会写入它——写入取决于措辞，不取决于语义。

论文扫了 16 个 carrier 构造，分两族：8 个 mirror 构造（"register M ⟨relation⟩ register S"）和 8 个 flag 构造（"alert flag for sensor r ⟨relation⟩ check result"）——都不点名值。三个发现：

发现 1

同语义，不同命运

语义等价、模型同等理解的构造，write-through 率可差数十分。Qwen3 上 consist 写在 .94，而一个语义等价的变体写得更弱。这说明语义理解 ≠ 写入能力。

发现 2

没有通用构造

write aperture（在某模型上能写入的构造集合）随模型剧烈摆动：类总计 5/4/3 等。需要每模型校准，没有一个跨所有模型都能写的构造。

发现 3

logit 层面分裂

"理解但不原生生成"的类，在 forced-choice output-logit probe 下分裂为：有的构造 logits 里有信号但 top-1 不出，有的连 logits 都没有。校准而非通用——显式文本记录是唯一在所有模型上都恢复的 arm。

05
Landing

着陆：根承载，引用边路由

物化的值住在哪个 event 的行里？

当多个下游 event 都注意到 source 时，物化的值住在 root event 的行里；引用边（reference edge）大多只是路由到根。最锋利的情形是链式再延伸一跳：root "M mirrors S" 之后再来 "T mirrors M"——答案仍跟随 root donor。

图 2：root event 的行承载主导 donor 信号；引用边大多把它路由出去。稀疏服务（source 丢弃）下，服务 C₂ 单独仍能把读出路由到 root 已物化的状态。

服务集与措辞都在读时移动读出。 加一个 value-free 的 target 提及，会把 root 的 donor-sensitivity 率从 41% 降到 22%——这个下降追踪的是"被服务 span 调制另一个 span 的读出"，论文在 §7 单独报告。
06
Access

访问：二值状态恢复，大负载衰减

原生恢复能读到多少被携带的状态？

在单一 menu-form readout + 独立 decoy 下，二值状态恢复远高于随机（.934，95% CI [.896, .968]）。但负载类型很关键：

query 形式与 store 同等重要。 一个首位数字探针 (.20) 或分位查询 (.62) 的读出远高于精确数字召回——两个紧凑 binding 可以并行携带。这意味着"KV 行里有什么"部分取决于你怎么问。
07
Programming the Primitive

编程这个原语：刻意写入 vs 自然收割

这是从"观察"到"工程接口"的关键一步。

论文不仅观察物化，还主动构造它。在 donor-paired 合成轨迹里，作者自己发射 carrier——source 之后一个 answer-free event，五个 arm 从"被动提及"到"显式 compute 指令"。

主动 arm

刻意 carrier 显著提升

一个刻意措辞、不含答案的 carrier 把 donor 对齐恢复率从 6% 提升到 51%——从不点名值。一个写时的 compute 指令（"在写入时计算判定"）把派生恢复从 .542 提到 .703。

被动 arm

自然对话收割无收益

在 REALTALK 和 LoCoMo 长程对话上，从全历史 cache 里收割 answer-free 晚期提及，相对孤立重编码相同文本，端到端检测不到任何收益。Gemma-4 原生服务时甚至更差。被动收割不是可靠的写入接口。

更新状态成本是一个 patch，不是重算。 修正很便宜——作为新 event 追加服务，而非 cache 编辑：对 full-attention 层，追加一个 p-token patch 就能在不重算整段 prefill 的情况下修复状态。这把"记忆更新"从"重算整段"降为"追加一小段"。
08
Implications & Boundaries

推论与边界：对 eviction 的警告

这条信道窄但因果可信；消融无损失 ≠ 可丢弃。

对任何做 eviction 的人的直接推论： 一个消融——丢掉 source event、观察到精度没掉——没有证明 source 不必要。它可能已经把状态物化进你保留下来的某一行里。经典"丢掉看精度"的消融在 sparse-KV serving 下系统性高估了可丢弃性。

donor swap 只认证紧凑状态信道

donor swap 认证的只是紧凑状态：verbatim 载荷很少转移（9.7%），精确数字不原生恢复，派生结论需要写时 compute 指令。这不是"任意信息都能塞进 KV 行"的万能通道。

trigger 是表层形式属性，不是语义

trigger 是表层形式的属性，不是语义。两个模型同等理解的措辞可以剧烈分化。物化与读出必须per-model 校准——没有通用构造。

Related Work

相关工作：修理被保留的行 vs 审计被丢弃的 source

Models Take Notes (Li, 2026)

最近的机制工作：prefill 写入 memoized 下游结论、字段级 note 编辑、append-only erratum、patch 更新。本文与此在"prefill 写入"上同向，但审计的是被丢弃 source 留下了什么，而非修理被保留的行。

KV reuse & repair 线（CacheBlend 等）

这一线修理它保留的行；本文审计被丢弃 source 留下什么。四条工作线管理/修理/组合复用 KV：cross-chunk recomputation、cacheblend、sparse attention reuse、composed KV repair。

EpiCache (Kim et al., 2025)

memory 系统建外壳；本文量基底。EpiCache 在相同 REALTALK/LoCoMo 分布下选择并压缩 episodic KV，但报告的是端到端精度，不直接测试"被丢弃 source 是否物化"。

10
Limitations & Scope

局限与范围

所有实验在冻结开源模型上用 greedy decoding 跑；donor pair、leak assertion、echo control 在代码里强制。标题结论基于三个近期 checkpoint——Qwen3-8B、Gemma-4、Ministral-3——三个家族。Qwen3.6-27B 因基底原因超出范围（§9）。donor swap 认证的只是紧凑状态信道：verbatim 与精确数字载荷不原生恢复。

所有实验在 greedy decoding 下进行；sampling 下的行为是开放问题。长上下文力学（position-budgeted assembly、reorder）是工程现实，但论文不主张比特级可复现，只主张行为级兼容性。

Glossary

术语表

semantic materialization（语义物化）
写时把上游派生状态承诺进下游 event 表示，不要求 event token 重复该状态。下游 event 的 KV 行成为"对已消失输入的可独立服务计算视图"。
carrier（载体）
一个 event，其 KV 持有上游派生状态，而文本里不点名该状态。"M mirrors S" 是典型 carrier。
trigger（触发）
让一个 event 做物化的写时构造。是表层形式属性，非语义。
donor（供体）
被丢弃的 source event，它定义了被查询的状态。donor-sensitive 项 = 两个 donor 输出不同的配对。
conditional landing（条件着陆）
一个 span 在 span 级消融下仍物化 v——与固定 donor 无关脚手架共服务时单独承载 donor 信号。
write aperture（写入孔径）
在某模型上能物化状态的构造集合。随模型剧烈摆动，需 per-model 校准。
serving contract（服务契约）
三条规则：source 排除在服务集外；donor 对比只在 donor-sensitive 项上；query 放置是协议选择。

Bilingual Abstract

附录：论文摘要双语对照

鼠标悬停英文段落显示中文翻译（原文译自 arXiv 2607.23693 abstract）。

Long-horizon agents increasingly reuse their KV cache as memory: a serving system keeps a subset of cached entries and drops the rest. Eviction and episodic-memory schemes therefore rest on a premise rarely tested directly, that a retained event is still informative once the observations that produced it are gone.

We test it by omitting one earlier observation from what is served, across otherwise identical agent histories. Among items sensitive to that observation, the answer overwhelmingly follows the omitted value, though no served span says which value is correct.

We call this semantic materialization: a downstream event's cached rows act as an independently servable view of computation whose inputs are gone. It can also be written on purpose.

A deliberately phrased, answer-free event raises donor-aligned recovery from 6% to 51% on Qwen3-8B without ever naming the value, whereas passively harvesting natural mentions from long-term dialog yields no detected advantage.

What such a row carries is specific and bounded. Compact state survives, larger payloads decay toward chance, and whether a construction writes at all turns on phrasing rather than on meaning alone, so two phrasings the model comprehends equally well can diverge sharply.

The result is a memory contract for sparse event-KV serving: what to write, where it lands, and what survives once the source is gone. For anyone who evicts the corollary is that dropping a source event and observing no accuracy loss does not show the source was unnecessary.

使用方式： 鼠标悬停（或长按）任一英文段落，中文翻译会以浮卡形式跟随光标显示。这是原文摘要的完整双语对照，与上方各 section 的中文深度解读互补——解读是我重新组织的机制叙事，此处是原文逐句翻译。
