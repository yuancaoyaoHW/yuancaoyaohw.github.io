Speculative Correction

Draft-then-Refine Decoding for Diffusion Language Models

扩散语言模型（DLM）可双向修订 token，但标准解码流程将其适配为逐块从左到右生成，限制了全局修订能力。本文提出先草稿后精修：先用 block-AR 快速生成完整草稿，再用双向扩散精修整个响应。

GSM8K-512: 0.850→0.907, 1.22× HumanEval: 0.415→0.622 NUS · arXiv 2608.02625

背景：扩散语言模型与 Block-AR 解码

扩散语言模型（DLM, 如 LLaDA）是一种非自回归生成范式：它从全掩码出发，通过迭代去噪同时预测整块 token，天生具备双向上下文感知能力——每个位置的生成可参考左右两侧的 token。

Block-AR：将 DLM 适配为自回归

为了让 DLM 生成任意长度的响应，标准做法是Block-AR 解码：将响应划分为若干固定大小的块（block），按从左到右的顺序逐块生成。每个块内部用扩散去噪并行生成，但块与块之间是严格串行的——第 $k$ 个块以第 $1,\ldots,k-1$ 个块的输出为条件，一旦生成便不可回溯修订。

Block-AR 的本质： 它把一个双向的生成模型"压"成了单向流水线。块内享有扩散的双向优势，块间却退化为自回归的逐块推进——前面块里的错误会传播到后面，且无法回头修正。

问题：逐块生成限制了全局修订

Block-AR 解码的根本局限在于：DLM 的双向修订能力被块边界切断。每个块生成完毕后即被"冻结"，后续块只能以它为条件往前推进，无法回头修订。这意味着：

  • 块内最优 ≠ 全局最优： 每个块在生成时只看到左边的已确定块，看不到右边的未来块。一个在局部看来合理的 token，放在全局上下文中可能是错的。
  • 错误传播不可逆： 第一个块中的错误会条件化地影响后续所有块，而 DLM 本有的双向能力无法跨块行使纠错。
  • 浪费了 DLM 的核心优势： 扩散模型的价值在于"可以同时修订所有位置"，Block-AR 把这个能力限制在了块内。

方法：先草稿后精修（Draft-then-Refine）

Speculative Correction 的核心洞察是：Block-AR 的正确角色不是"最终生成器"，而是"快速初始化器"。与其逐块生成并冻结，不如先用 Block-AR 快速跑完整个响应得到一个完整草稿，然后用 DLM 的双向扩散能力对整个草稿做全局精修。

两阶段流程

  1. 草稿阶段（Draft）： 用 Block-AR 解码快速生成 $K$ 个块的完整草稿。每个块仅用少量去噪步 $T_d$ 做粗略初始化——不需要完美，只需提供一个合理的全局结构起点。
  2. 精修阶段（Refine）： 对整个草稿（所有 $K$ 个块同时）执行 $T_r$ 步双向扩散去噪。此时所有位置都能同时看到左右上下文，DLM 的双向修订能力得以充分发挥。

成本模型与加速条件

总去噪步数为 $K \times T_d + T_r$（$K$ 个块各 $T_d$ 步草稿 + 全局 $T_r$ 步精修）。对比标准 Block-AR 的 $K \times T_{\text{block}}$（$K$ 个块各 $T_{\text{block}}$ 步），加速条件为：

$$K \cdot T_d + T_r \lt K \cdot T_{\text{block}}$$

由于草稿阶段每块只需很少的去噪步（$T_d \ll T_{\text{block}}$），而精修阶段全局 $T_r$ 步的代价不随块数 $K$ 线性增长，在 $K$ 较大时容易满足加速条件。

为什么这样更有效： 标准解码的每个块在生成时只能看到左边已冻结的块，是局部最优；而精修阶段所有位置同时去噪，每个位置都能参考全局上下文做修订——DLM 的双向能力终于在整个响应上行使，而非被块边界限制。草稿提供了一个让全局精修快速收敛的良好初始化。
与投机解码（Speculative Decoding）的区别： 投机解码是token 级的接受/拒绝——起草器生成若干 token，目标模型逐个验证并接受或拒绝。而 Speculative Correction 是完整草稿 + 全局双向修订——先有一个完整的草稿响应，再用扩散模型对整个响应做迭代精修，不存在 token 级的接受/拒绝机制。名称中的"投机"指的是"投机地先用低成本跑一个完整草稿，再用高成本精修全局修订"。

配置一：Flash-Flash 自精修

最直接的配置是用同一个 DLM（LLaDA2.1-Flash）既做草稿又做精修。这验证了一个关键假设：同一个模型可以先快速生成草稿，再对自己的输出做全局双向精修，从而显著提升质量。

配置二：Mini-Flash（投机纠正）

更具实用价值的配置是异质模型分工：用轻量的 LLaDA2.1-Mini 快速起草，用更强的 LLaDA2.1-Flash 做全局精修。这类似于经典投机解码中"小模型起草、大模型验证"的分工，但机制完全不同——这里没有 token 级的接受/拒绝，而是"小模型快速跑完整草稿，大模型对整段做双向精修"。

因果消融：为何有效

为了理解 Speculative Correction 的有效性来源，论文设计了系统的因果消融实验，逐一拆解"完整草稿"和"全局精修"各自的贡献。

消融设置

  • 完整草稿 + 全局精修： 标准流程（上文描述的方法）。
  • 全掩码精修（无草稿）： 跳过草稿阶段，从全掩码直接做双向扩散精修——相当于让 DLM 从零生成整个响应。
  • 局部精修： 有完整草稿，但精修时每个块只在自己的块内做双向修订（不跨块）。
  • 全局精修： 有完整草稿，精修时所有块同时做双向修订（跨块全局）。

完整草稿是有效初始化： 从全掩码直接精修的得分仅 0.004——几乎完全失败。这说明双向扩散精修不能从零开始，需要一个结构合理的完整草稿作为初始化。草稿阶段虽快，但提供了让全局精修快速收敛的起点。
全局精修的决定性作用（GSM8K）： 局部精修已达 0.872（接近全局的 0.899），说明块内双向修订已能修复大部分错误。全局精修额外贡献 +0.027——在数学推理任务（GSM8K）上，跨块上下文修订对涉及多步推理的题目的修正具有决定性意义。
任务差异： 在 MBPP 和 MATH 上，全局精修相比局部精修的增量较小。这说明这些任务的结构更"局部"——块内修订已足够。因此，对于异质配置（Mini-Flash），MATH 更适合理解为快速 Pareto 前沿点（草稿质量已接近 Flash），而 GSM8K 的全局精修收益最显著。

纠错诊断：修了多少，引入了多少？

Speculative Correction 的精修阶段不是"只修好不修坏"——它既修复草稿中的错误，也可能引入新的错误。论文统计了 Mini-Flash 配置下精修阶段"修复 vs 引入"的错误数：

净收益显著为正： 所有任务上修复数远超引入数（MBPP 净收益 +258）。这说明全局双向精修确实在系统性地修正草稿错误，而非随机扰动。引入的少量新错误可视为精修过程中"为了修正 A 处错误而连带影响的 B 处"——整体净收益始终为正。

总结

Speculative Correction 的贡献可以用一句话概括：让 Block-AR 从"最终生成器"退居为"快速初始化器"，把 DLM 的双向修订能力释放到整个响应上。

核心要点

  1. 重新定位 Block-AR： Block-AR 适合快速生成结构合理的草稿，但不适合作为最终输出——它的逐块冻结限制了全局最优。
  2. 全局双向精修： 对整个草稿做扩散去噪，所有位置同时参考全局上下文修订，DLM 的双向能力得以充分发挥。
  3. 两种配置覆盖不同场景： Flash-Flash（同模型自精修）追求质量+加速双赢；Mini-Flash（异质投机纠正）在 Pareto 前沿上用可接受的质量换大幅加速。
  4. 完整草稿不可或缺： 全掩码精修几乎完全失败（0.004），证明草稿提供的初始化是精修收敛的必要条件。
  5. 与投机解码的区别： 不是 token 级接受/拒绝，而是完整草稿+全局双向修订。
一句话记忆： 先投机地跑完一个草稿，再让扩散模型带着全局上下文做双向精修——把 DLM 的双向能力从块内释放到全局。
