FlashAttention-V

让 FlashAttention 吃下超长向量：用 head 间并行填满 RVV / SVE 的空转车道

RVV 和 SVE 把向量寄存器做到了 4096 位甚至更宽，可注意力的 head 维度只有 64 或 128——现有向量化 FlashAttention 全部限制 VL ≤ D，多出来的车道整段空转。FlashAttention-V（arXiv 2608.18656，Chalmers / Glasgow）的答案朴素而有效：注意力头之间彼此独立，把多个 head 打包进同一个寄存器。真实硬件 prefill 对标量最高 14×，gem5 模拟 512 位 VL 下最高 42×；同样宝贵的是一节诚实的负面结果——Q8_0 量化布局与长向量结构性不兼容。

Chalmers / Glasgow prefill 最高 42×（模拟） RVV 1.0 + Arm SVE

问题：向量机越宽，注意力越浪费

FlashAttention 的向量化只有一个天然可展开的维度：head 维 D。而 D 在真实模型里通常是 64 或 128。FP16 精度下 D=64 意味着一个 head 的数据只有 1024 位——机器给你 4096 位的向量寄存器，你也只能填满四分之一，剩下的车道里没有任何可算的东西，因为单个 head 内部再没有并行度可挖。

这不是某个实现的疏忽，而是整条技术路线的共同上界：llama.cpp 的两套向量化 FlashAttention 内核（归约式与 GEMM 式）都限制 VL ≤ D；Titopoulos 等人在 RVV 上的工作明确针对 VL ≤ D；NEON 上的 MEATTEN 沿 $d_k$ 向量化，继承同一约束。与此同时，RISC-V 向量硬件正在往宽里走——Vitruvius+ 是 8 lane × 64 位，Ara2 到 16 lane，AraXL 最高做到 64 lane。软件的上界和硬件的走向正面相撞。

作用域先划清：作者在 Banana Pi BPI-F3 上用未向量化的 llama.cpp 做 profiling——prefill 阶段 FlashAttention 占单层时间约 50%，decode 阶段只占约 10%（那里由线性投影和前馈层主导）。这个比例预先解释了两件事：为什么端到端收益远小于内核收益，以及论文为什么要额外去啃量化线性层（Q8_0 那一节）。

方法：inter-head packing

关键观察朴素得近乎显然：注意力头之间彼此独立——各算各的 Q、K、V 投影，没有跨 head 依赖，它就是一个还没被用掉的并行轴。更巧的是，ggml 的内存布局里 Q、K、V 跨 head 本来就是连续存储的，只是原本的循环顺序没去利用。

于是方法分两步。第一步重排 head 循环：空间局部性变好，访问变成单位步长，itr = VL / D 个 head 自然落进同一个向量寄存器。第二步按 head 展开：让多个向量寄存器同时活着，换来指令级并行和访存延迟隐藏。

打包之后的三个配套手法

掩码归约替代逐个提取。一个寄存器里躺着 4 个 head 的点积中间结果，怎么分别归约出各自的分数？朴素做法是反复 vslidedown 把每段挪出来，代价随 head 数线性增长。论文用带掩码的归约 vfredusum_m 直接在打包寄存器上就地取出各 head 的部分和，完全绕开滑移提取。记住这个手法——它在 Q8_0 那一节会以反面角色再次出现，同一个技巧换个场景就从解药变成毒药。

GQA：一次加载，滑移铺满。MHA 下 K、V 跨 head 连续，一条 vle 按满 VL 加载即可。GQA/MQA 下多个 query head 共享同一组 KV，论文只加载 avl = D 个元素，再用 vslideup 把它复制铺满整个寄存器——4:1 的 head 比例下一次加载加三次滑移就填满，共享 KV 的重复访存被天然消除。

online softmax 全程留在寄存器里。running max、running sum、VKQ 累加器三个状态量都以向量寄存器形式存在，每个 lane group 对应一个 head，跨 k-tile 循环直接携带，不来回落内存。向量化指数函数取自 SIXTE，作者改造它以处理 FP16 精度、无穷值和掩码。

展开因子有解析式

不是拍脑袋调出来的：$U = \dfrac{VL}{D \cdot b} \times R$，其中 $b$ 是元素位宽，$R$ 是"寄存器利用因子"，反映 head 数量富余时还能额外展开多少。论文给的算例：TinyLlama 的 D=64、共 32 个 head，8192 位 VL 下 8 个 head（8×64×16 位）刚好填满一个向量；用掉 8 个之后还剩 24 个 head，允许把展开从 8 提到 32，于是 R=4。

实测调优最终全程采用 U=4、block 64×64：16×16 分块会掉到 0.50×，128×128 与 64×64 基本持平（0.97×），U 超过 4 则因寄存器溢出退化。

实测：256 位的 BPI-F3

真实硬件是 Banana Pi BPI-F3（SpacemiT X60，RVV 1.0），向量长度只有 256 位。这个数字很关键：256 位小于 D·b，这块板子落在 VL ≤ D 分支，用不到 inter-head packing——起作用的只有 head 循环重排和 U=4 展开。

方法论缺口：论文的核心贡献 inter-head packing（VL > D 分支）在真实硅片上从未被执行过——BPI-F3 的 256 位落在 VL ≤ D 分支。所有 VL > D 的数字都来自 gem5 模拟，读下一节时请带着这个前提。

decode 是另一个世界

512 位下有 8–11×，但往上几乎不再涨——4096 位最多再拿 1.2×，Qwen2.5 和 Pythia 干脆没有额外收益。原因很直接：单 token 执行没有 token 间复用，寄存器一旦宽于一个 head，每次迭代的工作量就不足以摊销打包与拆包的开销。在真实缩放延迟下，decode 性能对向量长度和 lane 数几乎完全不敏感。

一个有意思的细节：FP16 相对 FP32 的优势高度依赖向量长度——8192 位下约 2×，512 位下只有 11%（decode 里是 1.5× 与 7%）。因为 512 位属于 VL ≤ D 分支，两种精度用同一展开因子且不打包，FP16 只是每次操作多算元素，并没有多算出注意力分数——瓶颈卡在 softmax，不在算术吞吐。

负面结果：Q8_0 与长向量结构性不兼容

这是全文最有价值的一节，因为它是一个被认真做完、并且诚实报告出来的失败。ggml 的 Q8_0 把 32 个 INT8 权重和一个 FP16 scale 连续交错存放，是典型的 Array-of-Structures 布局。向量加载权重时会连带取到 scale，必须先显式分离才能计算——这个布局细节直接破坏长向量执行。作者试了三条路，动画一步一条：

策略一的微基准（2048 位 VL）给出了决定性的周期归属：vslideup 打包 28% + 掩码归约 32% + 向量 MAC 仅 40%——打包加归约合计 60%，超过算术本身，把长向量的好处全部吃掉。作者在 Arm SVE 上用 svcreate4、svst4、svld1 重做同一件事，最好的 svld1（llama.cpp 在 512 位下的方式）在 2048 位 VL 下仍有约 20% 开销——开销与架构无关。

结构性论点：交错的 scale–weight 布局强迫你二选一：非单位跨步访问，或者显式打包。两者的代价都随 VL 增长——打包与归约的开销与算术开销同步放大，于是"更长的向量能摊销算术成本"这个通常成立的论证直接崩塌，开销永远摊销不掉。作者的建议因此很明确：随着量化格式成为常态，需要重新设计量化格式或内存布局本身。

边界与总结

该记住的限制

  • 性能评估仅限 RVV；Arm SVE 只做了 QEMU 功能正确性验证和打包微基准，没有完整性能数据。
  • 乱序 gem5 因内存耗尽无法运行，全部模拟结果建立在 in-order 核加一个解析式缩放延迟模型之上，而非经过验证的乱序模型。gem5 25.0.0.1 对 RVV 给出不准确结果，全程用 24.0.0.1。
  • gem5 不支持加宽指令的 LMUL=8，最强基线 ggml-vec-fp16 在所有模拟对比中缺席。
  • 模拟只跑单层，不含预处理和前馈层；batch size 恒为 1；RISC-V 无 BF16，只用 FP32/FP16。
  • 结论里称 512→4096 token 区间内 8192 位相对 512 位的加速比保持稳定，但正文没有对应的图表支撑。

端到端：为什么收益缩水

llama-simple 上 TinyLlama_Q4_K_M 达 6 T/s，Q8_0 约 3 T/s；llama-bench 的 128 token prefill 下 Qwen2.5_Q4_K_M 提升 4%（3.52 T/s），TinyLlama 和 Llama-3.2 与基线持平，Qwen2.5_Q8_0 未能跑完。收益之所以微小，正是开头那组 profiling 数字的回响：线性层和 FFN 完全没动，而 FlashAttention 只占 prefill 约 50%、decode 约 10%。

可迁移性证据：循环重排和 inter-head 展开这两个核心手法不绑定具体执行策略。作者把它们套到 llama.cpp 较新的 tiled GEMM 版 FlashAttention 上，在 BPI-F3 拿到 5% 提升——不大，但说明原理是通用的。
一句话总结：FlashAttention-V 把"head 间独立"这个被忽略的并行轴变成长向量机的填充材料，方法干净、分析诚实；它同时用一个负面结果提醒整个社区——软件技巧救不了为短向量设计的量化内存布局，下一步该动的是格式本身。
