LiLiCorr：把并行草稿的边际分布相互关联起来

DFlash 这类扩散式块草稿头一次前向就能吐出整块未来 token，但它是在逐位置边际上训练的——每个位置单看都合理，连起来读却不通。LiLiCorr 的解法不是去建模那个 $V^B$ 大小的联合分布，而是：每个位置留 top-$K$ 候选，用一次轻量前向给每个候选配一对 in / out 向量，相邻候选之间的余弦相似度就是它们的相容分数。

① 前置：块草稿头与前缀接受这两条约束

投机解码的账很简单：让一个便宜的 drafter 提前猜 $B$ 个 token，target 模型一次前向把它们全部验证，保留最长正确前缀，剩下的丢掉。收益完全取决于「平均每次能被接受多长」，也就是 acceptance length。

本文的 drafter 是 DFlash——块扩散式的草稿头，一次前向直接输出块内每个位置（论文里叫 slot）的分布。这比 EAGLE 那种逐 token 自回归展开便宜得多，因为不用在草稿阶段串行 $B$ 次。

代价藏在训练目标里。DFlash 的监督是逐 slot 的边际交叉熵：slot 3 学的是「在这个上下文下，第 3 个位置该是什么」，而不是「在 slot 1、2 已经确定成某个具体取值的条件下，第 3 个位置该是什么」。于是每个 slot 各自取 argmax 时，得到的是一串各自最像、彼此不一定搭的 token。

为什么不干脆建模联合分布？组合爆炸。$B$ 个位置、词表 $V$，联合分布有 $V^B$ 个取值。这是离散扩散文献里的老问题，不是 DFlash 的实现缺陷。

还有一条约束容易被忽略，但它决定了 LiLiCorr 后面几乎所有设计选择：接受是前缀式的。slot 1 错了，后面 $B-1$ 个 slot 猜得再准也一分不得。这条约束会在第 ⑥⑦ 节反复出现。

② 病因：边际可信，联合不可信

先把病症看清楚。下面这一幕演示同一个上下文下，各 slot 的边际分布分别都很像样，但逐 slot 取 argmax 拼出来的串在 target 眼里第二个 token 就崩了。

动画 1 · 逐 slot argmax 为什么会拼出不通的句子
边际分布 被接受 被拒绝 联合不相容

关键观察是：正确的 token 通常并没有从候选集里消失，它只是没排在第一。这句话是整篇论文的立足点——如果真值连 top-$K$ 都进不去，任何重排都救不回来；而实测它大多在里面。于是问题从「生成」降级成「重排」，而重排的搜索空间只有 $K^{B-1}$，还能进一步用一阶结构砍成线性。

同期工作的两条路。一条是把边际展开成草稿树（DDTree、Trees-from-marginals），让 target 一次验证多条续写——赢在不用改 drafter，输在 target 侧算力。另一条是在草稿时就恢复连贯性（Domino、D-PACE）。LiLiCorr 属于后者，对手也主要是后者。

③ 骨架：把 top-$K$ 候选摆成一张格

LiLiCorr 的数据结构简单到可以画在纸上。块长 $B=16$，其中 slot $1,\dots,B-1$ 是要草拟的位置，slot $0$ 是锚点——已经被 target 验证通过的上一个 token，所以它只有一个取值（$K_0=1$，其余 $K_s=K=8$）。

每个待草拟 slot 从 drafter 自己的边际里取 top-$K$ 保留下来，于是得到一张 $(B-1)\times K$ 的候选格（lattice）。整块的候选组合是 $K^{B-1}$ 条路径，但 LiLiCorr 不去枚举路径，它只给相邻两列之间的每一对候选打一个分。

动画 2 · 从边际分布到候选格
锚点（已验证） 保留的候选 被截掉的尾部 相邻对

候选格里每个格点还要变成一个向量喂给打分头。论文的构造是四项相加（都投到头的隐藏宽度 1024）：

  1. target 的输入词嵌入——该候选 token 在 target 词表里的 embedding，冻结不训，降维投影后使用。这一项让打分头共享 target 的词义空间。
  2. drafter 在该 slot 的隐藏状态——降维投影，由该 slot 的 $K$ 个候选共享。它携带位置级的上下文。
  3. 五个置信度标量过一个两层小网络——全部从 drafter 在该 slot 的分布里读：全词表下的 log 概率与概率、与该 slot 最可能 token 的 log 概率差、归一化到 $[0,1]$ 的排名，以及分布的熵。这让打分头知道「drafter 自己有多确定」。
  4. 两张可学习查表——一张按 slot 索引，一张按排名索引。

另外单独构造一个「target 状态」向量与每个候选融合：取产生最后一个已验证 token 的 target 隐藏状态，跨五个采样层折叠、归一化、投到同一宽度。

④ 创新一：每个候选带一对 in / out 向量，配对靠余弦

这是全文最巧的一步。打分头是一个两层双向 Transformer，跑在这 $(B-1)\times K$ 个候选向量上（外加锚点）。它为每个候选输出两个 $d_e=1024$ 维向量：

  • out 向量 $\mathbf{o}$：这个候选向后期待什么。
  • in 向量 $\mathbf{i}$：这个候选向前要求什么。

相邻 slot 的一对候选 $(k, k')$ 的相容分数就是「前者的 out」与「后者的 in」的余弦，乘一个标量 $\sigma$：

$$\phi^{\mathrm{p}}(s,k,k')=\sigma\,\cos\!\big(\mathbf{o}_{s,k},\;\mathbf{i}_{s+1,k'}\big),\qquad s=0,\dots,B-2$$ $\sigma=8.0$，所以每个分数被硬性夹在 $[-\sigma,\sigma]$ 内。$s=0$ 时只有锚点一个 out 向量。
余弦不是审美选择，是稳定器。论文明确写了：如果不用余弦而让分数自由取值，向量模长就成了一个无约束的自由度，联合训练时会出现分数量级失控，进而污染乃至彻底毁掉共享的 DFlash 骨干。余弦把每个学到的因子锁进 $[-\sigma,\sigma]$，代价是牺牲了模长这个表达维度。这是把「能不能联合训练」换来的。

局部因子，全局信息

值得单独说一句：因子化是局部的，信息不是。分数只连接相邻 slot，看起来像一阶马尔可夫；但产生这些向量的是一次双向 Transformer 前向，注意力覆盖整张格。所以 slot 5 和 slot 6 之间那个分数，实际上已经「看过」slot 1 到 slot 15 的所有候选。这正是它敢用一阶结构去逼近联合分布的原因——一阶只是读出方式，不是表示能力。

⑤ 创新二：一次前向、全部分数批量算完，只留一段廉价串行

论文对延迟的处理值得抄。整个解码只有两个阶段，而网络只跑一次：

并行阶段

一次 LiLiCorr 前向产出所有候选的 out 和 in 向量（含锚点的 out）。块内有 $B-1$ 个相邻 slot 对，其中第一对是「锚点 × $K$」，其余 $B-2$ 对是「$K \times K$」，所以总分数个数是

$$(B-2)K^{2}+K \;=\; 14\times 64 + 8 \;=\; 904$$ $B=16$、$K=8$。904 个余弦，写成一批 batched matmul 一次算完。

这里的工程要点是：所有分数没有依赖关系，因为它们只依赖向量，不依赖「上一个 slot 选了谁」。所以它们能一次性并行算掉，形状规整、全是矩阵乘，GPU 上极友好。

串行阶段

剩下的串行部分只有一次贪心走链：从锚点出发，每到一个 slot 就在 $K$ 个已经算好的分数里取 argmax。$B-1$ 步，每步一个 $K$ 元 argmax——这是查表，不是前向。

动画 4 · 一次前向 + 904 个分数批量算完 + 廉价串行
并行：向量与矩阵 串行：argmax 查表 LiLiCorr 头开销 对手（Domino）开销
账面结果。在同一条 SGLang 服务栈上、都做过 kernel fusion 与 graph capture 之后，LiLiCorr 打分头是 0.28 ms / 块，Domino 的头是 0.67 ms（约 2.4 倍），LiLiCorr 只占单块墙钟的 2.8%。头本身 36.76 M 参数。

这个拆解是在「把头单独拎出来」的流水线上量的；论文其他所有吞吐数字都是把头折进 drafter 之后测的，两者的单块墙钟不是同一个数——论文自己在脚注里点明了这一点，算是比较诚实。

⑥ 创新三：局部归一化，配一条贪心走链

有了 904 个分数，怎么读出一条序列？LiLiCorr 的选择是逐 slot 局部 softmax：

$$P(c_{s}\mid c_{s-1})=\mathrm{softmax}_{k}\big(z_{s}[k]\big),\qquad z_{s}[k]=\phi^{\mathrm{p}}(s-1,\,c_{s-1},\,k)$$ 给定上一个 slot 选定的候选，本 slot 的 $K$ 个分数过一次 softmax。这是一条建在候选格上的一阶链。

服务时用的是它的 argmax 版本，与训练目标严格对齐：

$$\hat{c}_{s}=\arg\max_{k} z_{s}[k]=\arg\max_{k}\phi^{\mathrm{p}}(s-1,\,\hat{c}_{s-1},\,k)$$

注意这里的自洽性：训练时的局部归一化目标，和推理时的贪心走链，是同一个东西的两面。训练教「给定正确前驱，把真值排到第一」，推理就做「给定已提交的前驱，取第一」。没有 train/serve 目标错配。

⑦ 为什么不要「最优路径」——这一节是我最欣赏的部分

看到「相邻打分 + 一阶链」，任何做过序列标注的人第一反应都是 Viterbi：把整条路径的分数加起来，取全局最大。

$$g(c)=\sum_{s=1}^{B-1}\phi^{\mathrm{p}}\!\big(s-1,\,c_{s-1},\,c_{s}\big)$$ 动态规划求 $\arg\max_c g(c)$ 的复杂度是 $O(BK^{2})$，在这个规模下几乎不要钱。

论文明确拒绝了这个更强的优化器，理由不是算不起，而是目标错了：

全局最优可能牺牲一个靠前的 slot 去换一条更肥的尾巴。但在前缀接受下，那条尾巴永远走不到。每个 slot 只有在它之前所有 slot 都命中的条件下才贡献长度，所以靠前的 slot 承担了绝大部分期望接受长度；丢了第一个 slot 的块，后面全对也是零。

消融数据支持这个判断：把贪心换成精确最优路径，接受长度 −2.44%。也就是说，在「更会优化的解码规则」和「与接受方式对齐的解码规则」之间，后者赢。这是一条值得记住的一般性教训——解码规则该匹配奖励结构，不是匹配模型的似然。

⑧ 训练侧：三个不那么显然的设计

8.1 Oracle-prefix 监督：哪些 slot 才配拿到梯度

LiLiCorr 按 teacher-forced 重排器来训，所以监督必须复刻服务时的条件。两个筛子决定一个 slot 有没有学习信号：

  1. 覆盖：真值 token 必须在 drafter 的 top-$K$ 里。不在的话重排怎么排都救不回来，这个 slot 给梯度只是噪声。
  2. 前缀条件：每个转移都条件在真值前驱 $g_{s-1}$ 上，而不是条件在模型自己上一步选了什么上。这直接来自前缀接受——服务时只有前面全对，本 slot 才有意义。

把这两条合起来，监督集合 $\mathcal{S}$ 就是「真值在候选池内、且以真值前驱为条件」的那些 slot，损失是

$$\mathcal{L}_{\mathrm{CE}}=-\frac{1}{|\mathcal{S}|}\sum_{s\in\mathcal{S}}\log P_{\theta}\big(c_{s}=g_{s}\mid c_{s-1}=g_{s-1}\big)$$

8.2 Target 加权的干扰项惩罚：把 target 讨厌的候选按下去

光有交叉熵不够。交叉熵只管把真值的概率抬高，但它对「排在真值后面的那些候选到底有多糟」是无感的。LiLiCorr 加了一项：

$$\Omega_{s}=\sum_{k}P_{\theta}(k)\,w_{k},\qquad w_{k}=\mathrm{relu}\!\left(c_{k}-c_{g_{s}}\right),\qquad \mathcal{L}_{\mathrm{dist}}=\frac{1}{|\mathcal{S}|}\sum_{s\in\mathcal{S}}\Omega_{s}$$ $c_k$ 是 target 给候选 $k$ 的代价（负对数概率），$c_{g_s}$ 是真值的代价。只惩罚那些「比真值更贵」的候选，$\mathrm{relu}$ 把比真值更便宜的候选放过。

论文给了一个漂亮的等式：当所有候选的代价都不低于真值时，

$$\Omega_{s}=\sum_{k}P_{\theta}(k)\big(c_{k}-c_{g_{s}}\big)=H(P_{\theta},q)-c_{g_{s}}$$ $q$ 是 target 分布。由于 target 冻结、$c_{g_s}$ 是常数，$\nabla_\theta\Omega_s=\nabla_\theta H(P_\theta,q)$——所以它不是在做分布匹配，而是在最小化「LiLiCorr 分布下的期望 target 代价」。
两项为什么互补。交叉熵的梯度 $\propto$ $1-P_\theta(g)$，真值一旦排到第一就快速衰减，此后梯度都花在已经定了的决策上。干扰项惩罚的梯度不看真值排第几，只看「还有多少概率压在 target 讨厌的候选上」，所以在 $P_\theta(g)\to 1$ 之后仍然有力。论文的定位是代价感知的交叉熵整形，不是替代品。

消融很干净：把干扰项去掉、同时保持重排器目标的总权重不变（所以是重新分配预算而非缩减预算），九个 benchmark 上接受长度全部下降，幅度 1.5% ~ 8.9%。这一项基本撑起了整个套件的收益。

8.3 与 drafter 联合训练：怎么穿过不可微的 top-$K$

LiLiCorr 不是扣在冻结 drafter 上的后处理，而是和 DFlash 一起训，让 drafter 学会「提出能被关联成长前缀的候选池」。问题是 top-$K$ 选择不可微。处理办法朴素但有效：候选索引固定住不求导，梯度走候选的草稿 log 概率和产生它们的隐藏状态。

drafter 自己那份 DFlash 逐 slot 块交叉熵保留，并且带靠前 slot 权重更大的衰减——又是前缀接受在起作用。总损失是三项相加：

$$\mathcal{L}=\mathcal{L}_{\text{DFlash}}+\lambda\big(\mathcal{L}_{\mathrm{CE}}+\lambda_{\mathrm{dist}}\mathcal{L}_{\mathrm{dist}}\big)$$ $\lambda_{\mathrm{dist}}=1.0$。这里余弦的 $[-\sigma,\sigma]$ 界回过头救了这一步：没有它，重排器的梯度会把共享骨干带崩。

8.4 附录里的第四项：长上下文用的 margin hinge

服务时的规则是 argmax——决定一个 slot 的是「谁分最高」，不是「真值拿了多少概率」。交叉熵在真值已经排第一之后还在花梯度。而决策间隙窄的那些 slot，恰恰是长 prompt 会更多产生的。于是附录加了一个 hinge：

$$\Delta_{s}=z_{s}[g_{s}]-\max_{k\neq g_{s}} z_{s}[k],\qquad \mathcal{L}_{\mathrm{margin}}=\frac{1}{|\mathcal{S}|}\sum_{s\in\mathcal{S}}\mathrm{relu}\big(\rho-\Delta_{s}\big)$$ $\rho=2.0$，权重 $\mu=0.5$。

效果有明确的方向性：在训练长度范围内它略微有害，范围外越长越有用。加上它之后，长输入吞吐扫描从「54 个操作点里赢 46 个」变成「54 / 54 全赢」，接受长度领先的点数从 38 升到 44。

⑨ 实验复盘：口径比数字更值得看

先说口径，因为这篇的口径做得比多数投机解码论文严格：

  • target 冻结的 Qwen3-8B / Qwen3-4B；单张 H100；块大小 16；并发默认 1。
  • 所有系统跑同一条 SGLang 服务栈，都按 DSpark 的做法把投机头折进 drafter、做 kernel fusion 与 graph capture；Domino 也被移植到同一栈上——不让任何一方因为实现拖后腿。
  • 三个系统用同一批约百万级训练样本（Nemotron Post-Training Dataset V2 的 code / math / STEM / general-chat 切片）。
  • benchmark 用 SPEED-bench 的九个类别，两种解码（greedy 与温度 1，后者用精确拒绝采样验证）。

长上下文外推

训练序列长度远短于测试：吞吐扫描里有比训练范围长一个数量级的输入块。所有 drafter 在这些块上都掉接受长度，而且掉得很一致——因为被要求注意的位置超出了训练范围。统一用 YaRN 在推理时扩展位置编码后（对所有系统一视同仁），LiLiCorr 的领先保持。

一个诚实的说明。论文点出在最高并发档，测的其实是「offered load」而不是「resident concurrency」——单张 H100 的 KV cache 装不下那么多长请求，超过容量后吞吐就不再提升。愿意在正文里写这句话的论文不多。

⑩ 局限与我的存疑

论文自己承认的一条是设计内生的：LiLiCorr 只重排 top-$K$。真值掉出候选池的 slot，它无能为力——这个上限由 drafter 的边际质量决定，重排器再强也碰不到。联合训练能部分缓解（drafter 学着把真值留在池子里），但改变不了这是个硬天花板。

我自己会追问的几点：

  • $K$ 的敏感性没展开。$K=8$ 时 904 个分数几乎免费，但 $K$ 增大时分数数量按 $K^2$ 涨，覆盖率与延迟的交换曲线长什么样，论文没给扫描。
  • 一阶因子化的极限在哪。「局部因子、全局信息」这个论证很有说服力，但它是定性的。如果块内存在真正的长程约束（比如括号配对、JSON 结构），双向注意力产生的向量能不能靠相邻余弦读出来，我不确定，也没有实验去针对性地测。
  • 余弦的代价没量化。论文说不加界会毁骨干，这是很强的经验陈述，但没有给「不加界时训练崩溃」的曲线，也没试过别的稳定手段（比如谱归一化或直接裁剪）。$\sigma=8.0$ 这个值怎么来的也没说。
  • margin 项被放在附录，方向性却很强。训练范围内有害、范围外有益，说明它其实在补一个位置泛化的洞。把位置外推问题交给一个损失项来打补丁，感觉像是权宜之计而不是根治。
  • 都是自家 baseline 的移植。把 Domino 移到同一栈上是加分项，但移植者是本文作者，调优程度终究难以对称核验。

⑪ 一句话总结

LiLiCorr 的三个动作：（1）承认联合分布不可建模，把问题降级为 top-$K$ 重排；（2）用一次双向前向给每个候选配 out / in 向量，相邻余弦即相容分数——因子化局部而信息全局，且余弦的有界性是联合训练能成立的前提；（3）读出时不求全局最优，而是用与前缀接受对齐的贪心走链，把靠前的 slot 摆在最重要的位置。

它真正可迁移的那条经验，跟投机解码没什么关系：当奖励是前缀式的时候，更强的优化器会给出更差的结果。解码规则要匹配奖励结构，而不是匹配模型似然。这一点在 −2.44% 那个消融里说得比任何论述都清楚。
