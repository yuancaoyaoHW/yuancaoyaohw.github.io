SSR：把思维链本身当作投机解码的草稿源

推理模型的长思维链换来了质量，也换来了让人等不起的延迟。既有加速方法都在 token 层面做文章，没人动过推理流程本身的结构。SSR 的想法极简：同一个模型、同一份权重，只在两个不同的思考预算上求值——短预算那次的答案当草稿，长预算那次的答案当验证器。草稿的算力开销藏在还在继续的思考背后，几乎不额外增加墙钟时间。

① 前置：看懂 SSR 只需要两个式子

第一个是投机解码（speculative decoding）的验证规则。有一个便宜的提议分布 $d$ 和一个昂贵的目标分布 $p$，草稿 token $\hat a_t$ 按下式接受：

$$\alpha_t=\min\!\left(1,\ \frac{p(\hat a_t\mid q,r,a_{一旦某位被拒，就从残差分布里补一个 token，然后丢弃草稿剩余部分。
$$a_t\sim\frac{\max\big(p-d,\,0\big)}{\sum_v\max\big(p(v)-d(v),\,0\big)}$$ 接受规则加残差采样合起来保证：最终输出分布与目标模型 $p$ 完全相同，与草稿质量无关。这是 2023 年那两篇奠基工作的核心结论，也是「无损加速」这个说法的全部依据。

第二个是预算强制（budget forcing）。推理模型的输出可以拆成思维链 $r$ 与最终答案 $a$。给定一个思考预算 $b$，我们可以在 CoT 只写了 $b$ 个 token 时就强行让它作答：

$$p_\theta(a\mid q,b)\ \triangleq\ p_\theta\big(a\mid q,\ r_{\le b}\big)$$ 实现上需要在 $r_{\le b}$ 后面追加一个「思考结束」标记（Qwen 系是 </think>，Gemma-4-E4B-it 用原生的 <channel|>），某些设置里还要再加一段打断串把模型逼进作答模式。
把这两件事叠在一起，SSR 的全貌就出来了：令 $d=p_\theta(a\mid q,b_d)$、$p=p_\theta(a\mid q,b_v)$，其中 $b_d<b_v$。提议分布与目标分布来自同一份权重，差别只是「想了多久」。不需要训练、不需要辅助参数、不需要改目标模型的架构——这三点是 SSR 相对 EAGLE / Medusa 一类方法最直接的差异。

② 关键观察：partial CoT 不是无意义的中间态

自投机解码不是新东西，但此前的做法都是用目标模型的有损近似去起草：提前退出中间层、稀疏 attention、量化 KV cache。论文对这一整类方法的批评只有一句话，但很准：

"they do not fully take advantage of the structure of reasoning language models. Reasoning language models expose an additional source of signal for speculation: the chain-of-thought itself."

论证链条是这样接上的：test-time scaling 那一支研究已经表明，CoT 长度可以被控制，而且思考预算越长，答案质量普遍越好（至少在某个点之前）。既然「预算 → 质量」是一条单调曲线而不是随机噪声，那么曲线上的每一个中间点都对应一个有意义的答案分布，而不是随便一个残缺状态。原文：

"Answers sampled early in the CoT might be incomplete or inconsistent, but as reasoning progresses they improve in quality and become increasingly similar in content and surface form to the final answer."
"content and surface form" 就是摘要里 semantic / lexical overlap 的出处。
这里要先说清楚一件事：这个观察在论文里是纯定性的。全文没有任何 ROUGE / BLEU / 嵌入余弦 / token 一致率的测量，也没有一张「重叠度随 CoT 长度上升」的曲线图（全文只有 2 张图，都是流程示意）。唯一半定量的支撑是 §4.3 的一句 "a substantial fraction of final-answer tokens stabilize at relatively small budgets"。真正可核实的重叠证据来自实验里的两个复用指标——平均被接受的 prefix token 数与 suffix token 数，见第 ⑧ 节。

但这个观察带来了一个真正新的东西：草稿的算力开销可以被隐藏。传统投机解码里，起草和验证是串行的两拍，起草再便宜也要占墙钟时间。而 SSR 的起草与「继续思考」是并发的——模型一边往 $b_v$ 推进思维链，一边用 $r_{\le b_d}$ 这个已经算完的前缀起草答案。

③ 创新一：同一个模型的两个预算，就是 drafter 与 verifier

整个流程分四相：

  1. 生成思维链直到抵达草稿预算 $b_d$；
  2. 以 $r_{\le b_d}$ 为条件并发采样一份草稿答案 $\hat a$，同时思维链继续往 $b_v$ 走；
  3. 思维链抵达 $b_v$ 时收齐草稿；
  4. 用高预算分布验证草稿，保留被接受的前缀，再采样续写。

并发要成立，有一个硬性可行条件——思维链总长必须容得下起草这段时间：

$$|r| \;>\; b_d + m$$ $m$ 是草稿的最大长度。若不满足，草稿还没写完思维链就结束了，并发的前提破产。这是全文唯一一个关于开销与收益的关系式——论文没有给延迟模型，也没有期望加速比的解析式。

而 $b_d$ 的取值有一个内在张力：太小则 partial CoT 还没收敛，草稿与最终答案分道扬镳；太大则违反上面的不等式。论文自己的表述是 "$b_d$ should be a substantial fraction of the total CoT length for drafts to be useful"——而总长度事先并不知道。这个矛盾直接催生了第 ⑥ 节的多阶段变体。

④ 验证层：两套不对称的规则

草稿收齐之后，SSR 用两个阶段消化它，而这两个阶段的验证标准不一样——这是读这篇论文最容易漏掉、也最影响结论解读的一点。

阶段验证规则分布性质
prefix 阶段标准投机解码拒绝采样，$\alpha_t=\min(1,p/d)$，失配处走残差分布严格保分布
suffix 阶段与验证器的贪心预测逐位精确匹配，不匹配即停近似，不保分布

prefix 阶段做的事情很干净：把草稿 $\hat a_{1..m}$ 作为一个「提示的延长部分」一次性喂进高预算上下文，拿到每一位的 prompt logprobs，与起草时记录的 draft logprobs 逐位比对，求出最长被接受前缀 $k_{\text{acc}}$。这一步只需要一次前向（并行验证 $m$ 位），这才是投机解码省时间的来源——把 $m$ 步串行解码压成 1 步并行打分。

为什么 prefix 阶段是无损的：接受概率 $\min(1,p/d)$ 与残差分布 $\propto\max(p-d,0)$ 拼起来，边缘分布恰好等于 $p$。这个恒等式对任意 $d$ 成立，所以草稿再差也只是「白算一场」，不会让输出变差。SSR 的 $d$ 恰好是同一个模型在更短预算上的答案分布，这一点在理论上完全不需要额外假设。
动画 3 · 拒绝采样：接受、失配、残差补位
接受 拒绝 草稿分布 $d$ 目标分布 $p$

问题出在「一旦被拒就丢弃草稿剩余部分」这条规则上。对普通投机解码，草稿模型是自回归展开的，失配之后的内容确实已经建立在错误的历史上、不值得保留。但 SSR 的草稿有个特殊性质：它是同一个模型在同一道题上写出来的完整答案，失配往往只是局部措辞或某个中间数值不同，后面大段结构、公式、代码骨架仍然一致。全部丢掉太浪费了。

⑤ 创新二：越过第一个失配——把草稿当后缀词典

SSR 的第二个创新是把被拒之后的草稿残余再利用一次，办法是接一层 suffix decoding。

suffix decoding 本身不是这篇论文的发明（它是「用已有文本建后缀结构、按上下文后缀检索候选续写」这一类无模型起草方法），但 SSR 用它的方式很特别：后缀缓存只用草稿 token $\hat a_1..\hat a_m$ 构建，prompt 和已生成内容的缓存都被显式关掉。也就是说，这一层的唯一职责就是「从草稿里找还能用的片段」。

参数取值含义
后缀缓存来源仅草稿 tokenprompt / 内部缓存关闭
上下文匹配深度4用最近 4 个 token 做检索键
最大投机 token 数16单次最多提议这么长的片段
max spec factor4限制提议长度相对匹配长度的倍数

续写的每一步都是：取当前已生成序列的末 4 个 token，在草稿构成的后缀结构里找最长匹配，把匹配位置之后那一段（最多 16 个 token）当作提议，交给模型贪心校验；对上多少算多少，对不上就退回普通解码一位。

代价说清楚：这一层的验证是贪心精确匹配，不是拒绝采样。所以开启 suffix decoding 之后，SSR 整体不再是分布无损的——它退化成「近似等价于贪心解码的加速」。论文全文没有测量任何质量指标（准确率、pass@1 都没有），因此「保持输出质量」这个说法在 prefix 阶段有理论依据，在 suffix 阶段则是未经检验的。

消融实验给出了本文最反直觉的一组数字。在 Qwen3-8B / ClassEval 上：只开 prefix 验证，加速比 1.086、延迟降 7.9%；只开 suffix 解码，加速比 1.318、延迟降 24.1%——而且此时被接受的 prefix token 数是 0。换句话说，在这个设置里 SSR 的全部收益都来自「越过失配点复用草稿片段」，严格的拒绝采样那一层一个 token 都没贡献。

⑥ 创新三：多阶段自举，让草稿自己滚起来

回到第 ③ 节末尾那个矛盾：$b_d$ 该设多大，取决于思维链最终会有多长，而这个长度事先不知道。单阶段 SSR 只能赌一个值。多阶段变体（论文 Algorithm 2）的做法是不赌——设一串递增预算 $b_1<b_2<\dots<b_T$，每一站都起草一次，每一站都用下一站的分布来验证并延长上一站的草稿。

$$\hat a_{i+1}\ \sim\ p_\theta\big(\cdot\mid q,\ r_{i+1},\ \hat a_{i,1:k_i}\big)$$ 第 $i+1$ 站不从零起草：它以第 $i$ 站已被接受的前缀 $\hat a_{i,1:k_i}$ 为条件继续写。这就是自举（bootstrap）——每一轮的成果都成为下一轮的起点，草稿在推理推进的过程中逐步「凝固」。

这带来两个好处。一是不再需要预知 CoT 总长：无论真实长度落在哪一段，总有若干个中间站落在「partial CoT 已经足够收敛」的区间里。二是每一站的验证工作量都变小了——只需要验证增量部分，而不是每次都验证一份完整的答案。

动画 5 · 多阶段自举：草稿在思维链推进中逐步凝固
思维链推进 本站草稿 已凝固前缀 验证并延长
论文用 Qwen3-8B / AIME-2024 报了一组多阶段结果：端到端延迟从 18.58 s 降到 16.37 s，−11.9%。注意这个降幅比单阶段最好的 −24.1% 小——多阶段解决的是「不用调 $b_d$」这个鲁棒性问题，不是把加速比推得更高。论文自己把这一小节（§5.3）标注为 preliminary。

⑦ 系统实现：在 vLLM 里，两个预算就是父子两个请求

SSR 没有改模型，也没有改 attention kernel，它改的是调度器。当一个请求的思维链写到 $b_d$ 时，调度器把它复制出一个子请求；子请求的 token 序列是父请求当前序列加上一个「思考结束」标记，于是 vLLM 原生的 prefix caching 直接命中——prompt 与 partial CoT 的 KV 完全复用，起草的预填充成本接近零。

三种请求形态

  1. Drafting：子请求，前缀 = prompt + $r_{\le b_d}$ + </think>，输出草稿 $\hat a$ 并记录每位的 draft logprobs；与父请求并发。
  2. Verification：把 prompt + $r_{\le b_v}$ + </think> + 草稿 token 当成一整个 prompt 提交，靠 vLLM 的 prompt logprobs 一次前向拿到目标分布在每一位上的取值，与 draft logprobs 逐位比对。这是把「并行验证」用现成接口实现的巧办法：不需要写任何 speculative kernel。
  3. Continuation：从最长接受前缀处继续生成，此时挂上以草稿为词典的 suffix decoding。
不要把它理解成「免费」。在起草窗口内，父请求与子请求同时在服务中，瞬时 batch size 上升、KV 显存占用上升。SSR 省下来的是墙钟时间，不是 FLOPs——收益来自把原本串行的开销塞进已有的等待里。论文的吞吐表也确认了这一点：在高并发场景下，多出来的算力不再是空闲资源，SSR 的优势会被吃掉。它是一个低负载、低延迟取向的优化，batch size = 1 是全部实验的设定。

⑧ 实验复盘：数字读到什么程度算读懂了

设定：Qwen3-8B / Qwen3-14B / Gemma-4-E4B-it，任务覆盖 AIME-2024、GPQA-Diamond、ClassEval、LiveCodeBench 一类推理与代码基准，batch size = 1，单卡。基线是同一模型的朴素自回归生成——没有 EAGLE、没有 Medusa、没有独立的 suffix decoding 或 lookahead 对照。

三条值得记住的结论

第一，加速幅度落在 1.1×–1.3× 这个量级，最好的一格是 ClassEval 上的延迟 −24.1%。这不是数量级式的提速，但对一个不训练、不改架构、纯调度层的改动来说是合理的量级。

第二，两条复用通道的贡献严重不均衡。前面提过的那组消融是全文最有信息量的地方：prefix 验证在 Qwen3-8B / ClassEval 上贡献为 0 个 token，全部收益来自 suffix 解码。这说明「短预算答案与长预算答案逐位对齐」这个强假设在实践中经常不成立，成立的只是弱得多的那个版本——局部片段会重复出现。

第三，吞吐是要付代价的。并发起草抬高了瞬时负载，吞吐表里能看到这一项。论文没有回避，但也没有给出「多大并发下 SSR 由赚变亏」的临界点。

⑨ 论文没给的东西（读完这篇再读原文会省很多时间）

  • 没有任何质量评测。全文没有一个准确率 / pass@1 数字。prefix 阶段的无损性是从投机解码理论继承来的，而一旦开启 suffix decoding（贪心精确匹配），这个保证就失效了——恰恰所有最好看的加速数字都开着 suffix decoding。
  • 核心观察没有被测量。「partial CoT 的答案与最终答案重叠度随预算上升」是本文的立论基础，但没有 ROUGE / 余弦 / 一致率曲线，只有一句定性描述。唯一可核实的证据是接受 token 计数，而那组计数在某些设置里是 0。
  • 基线过弱。唯一对照是朴素自回归。SSR 用的 suffix decoding 是已有方法，理应单独作为基线跑一遍——否则无法回答「收益里有多少是 SSR 的贡献、多少只是 suffix decoding 本身的功劳」。这是本文方法论上最大的空白。
  • 没有 $b_d$ 的敏感度扫描。论文明确指出 $b_d$ 难选，却没有给出一条「加速比随 $b_d$ 变化」的曲线，也没有自适应选取策略。
  • 没有延迟模型、没有期望加速比公式。全文只有 4 个式子，唯一的成本关系是 $|r|>b_d+m$，其余全靠实测。
  • 没有显存分析。并发两个请求必然增加 KV 占用，论文没有量化。
  • 只测了 batch size = 1。而这恰恰是「空闲算力可以白拿」这个前提最成立的场景。
这些空白不否定这个想法。SSR 的贡献是指出了一个之前没人用过的信号源：推理模型自己的思维链就是一个免费的、逐步收敛的草稿生成器。这个观察是对的、是新的、而且实现代价极低。要把它做成一个可靠的系统组件，还需要有人补上质量评测、强基线对照和 $b_d$ 的自适应策略。

⑩ 一句话总结

SSR = 同一个模型 × 两个思考预算 × 两层复用。短预算那次的答案当草稿（成本藏在还在继续的思考背后），长预算那次的答案当验证器；先用拒绝采样吃掉逐位对齐的前缀，再用后缀检索捞回失配之后仍然可用的片段。不训练、不改架构、只改调度器，在低并发下换来 1.1×–1.3× 的端到端加速——代价是瞬时算力峰值，以及第二层复用让「无损」的说法不再成立。
