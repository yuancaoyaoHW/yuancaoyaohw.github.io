Stage 1 / index

PackGQA

把同一 KV group 的 query heads 打包到一个 tile，让 staged K/V 在 shared memory 中被整个 group 复用。

Q ∈ R^(L×Hq×d) → Q′ ∈ R^((gL)×Hkv×d)
  • 索引按 KV head 保存，元数据缩小约 g 倍
  • 尾部 tile 的空转行数被 PackGQA 摊薄
  • 为后续稀疏 CSR traversal 准备统一 work unit
部署边界： sparse prefill 走 paged KV 路径；decode 因单 token query 回退到 dense attention。
网格是结构示意；密度、RULER 分数和 speedup 曲线取自论文 Table 1/3。图中 speedup 的基线是 FlashAttention-2，论文另报告 128K 下相对 FA3/4-aligned dense 的 BF16 17.54x、FP8 30.49x。

怎样读这张图

1. 先做索引

PackGQA 把同一 KV group 的 query heads 打包；block-mean pooling 只保留每个逻辑块的均值；单 pass score + threshold 再把 survivor 写成按 KV head 组织的 CSR。默认实验使用 B=128、sink=256、window=512、alpha=0.1。

2. 再做精确计算

选中的块走 exact QK/PV；未选中的块不再简单置零，而是以 |B_J| exp(s-bar_J) (v-bar_J, 1) 注入同一个 online softmax。这个零阶修正是 V2 在极端稀疏率下守住准确率的关键。

3. 最后看部署

H20 上 128K 的 V2 attention speedup 相对 FA2 为 BF16 27.19x、FP8 47.26x；SGLang 的连续批处理端到端 TTFT 改善最高约 3.4x/4.8x。短上下文时，索引和修正开销会吃掉部分收益。

论文：Qihang Fan 等，FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving，arXiv:2608.19758 · 官方实现。所有曲线中的演示网格用于解释执行路径，不冒充逐 token 的原始 attention map。
