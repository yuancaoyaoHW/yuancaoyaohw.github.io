MoE 上的投机解码：专家字节、核带宽与最佳草稿长度

稠密模型上，验证 k 个草稿和解码 1 个 token 读的是同一份权重，所以投机几乎是白赚。MoE 不一样：每个 token 选不同的专家，一次验证要多读多少专家字节，取决于路由；这些字节读得多快，又取决于读它们的那个 kernel。这篇论文把「投机在 MoE 上到底快不快、草稿该多长、能快多少」写成了字节 ÷ 有效带宽的一套闭式结论，用 Lean 4 证明，再在 llama.cpp（CUDA / Metal）和 MLX-LM 上逐条对账。

① 为什么 MoE 上投机常常不赚

投机解码的账很简单：草稿模型一次猜 $k$ 个 token，目标模型一次前向把这 $k$ 个加上当前 token 共 $n=k+1$ 个位置一起打分。batch=1 的 decode 是读内存受限的，一次前向的时间主要是「把权重从显存读一遍」。稠密模型里 $n$ 个位置共享同一份权重，读一次就够，所以验证 $n$ 个 token 的时间接近解码 1 个 token。

MoE 把这个前提打破了。每层有 $N$ 个专家，每个 token 只选其中 $m$ 个。$n$ 个 token 一起验证时，它们选中的专家并集可能接近 $nm$ 个，也可能因为相邻 token 爱选同一批专家而小得多。验证一次要读的专家字节，是路由的函数。

论文开篇给了一个很扎心的实测：在 llama.cpp Metal 上用真实草稿模型跑 MT-Bench，37 个 prompt 里有 33 个是普通解码最快。投机解码在 MoE 上并不是默认赚钱的。

论文要回答的三个问题，全部写成步长时间 $V(k)$ 的函数：
  1. 投机什么时候比不投机快（接受率 $a$ 的阈值）？
  2. 最佳草稿长度 $k^*(a)$ 是多少？
  3. 最多能快多少？
而 $V(k)$ 又被拆成「要读的字节 ÷ 读这些字节的 kernel 的有效带宽」。前者由路由决定，后者只能测。

已有工作的成本模型大多只有一个带宽：Leviathan 等人的仿射步长 $1+\chi k$（当且仅当 $a>\chi$ 时有加速）；MoESD 在均匀路由下算出 $n$ 个 token 的不同专家数 $N(1-q^n)$；S2-MoE 按新引入专家数乘每专家延迟计费；SpecFit 把一次 cycle 写成截距加系数乘专家并集。它们都默认所有专家字节用同一个带宽读，也都没推出下面要讲的「阶梯」结构。

② 两种专家核与字节账

一次验证前向要处理 $n$ 个 token、每个 token $m$ 个专家，共 $nm$ 个「槽位」（slot）。读这些专家权重有两种 kernel 写法：

  • 逐槽核（per-slot）：每个槽位各读一次自己的专家。两个 token 选了同一个专家，就读两遍。llama.cpp 和 MLX 在 $n\le 8$ 或 $9$ 时默认走这条路。
  • 去重核（dedup）：先把 $n$ 个 token 选中的专家取并集，每个不同的专家只读一次，再把对应 token 的激活拼起来做一次小矩阵乘。

论文先定义「复用率」。第 $l$ 层、第 $j$ 个位置上 token 选中的专家集合记作 $S_{l,t+j-1}$，它和前面 $j-1$ 个 token 已选专家的重叠比例是

$$\rho_l(n)=\frac{1}{m}\,\mathbb{E}\Big|S_{l,t+n-1}\cap\big(S_{l,t}\cup\cdots\cup S_{l,t+n-2}\big)\Big|$$(1) 第 n 个 token 的 m 个专家里，平均有多大比例已经被前面的 token 选过

于是 $n$ 个 token 的专家并集大小是把每个新 token 带来的「新专家」累加起来：

$$U_l(n)=m\sum_{j=1}^{n}\big(1-\rho_l(j)\big),\qquad \rho_l(1)=0$$(2) 并集大小；均匀路由下 $1-\rho(n)=q^{n-1}$，$q=1-m/N$

每个专家占 $w_l$ 字节，层数求和后，两种核要读的专家字节分别是

$$E_{\text{slot}}(n)=nmW,\qquad E_{\text{dedup}}(n)=\sum_l w_l\,U_l(n)$$(3) $W=\sum_l w_l$；记 $\bar u=E_{\text{dedup}}/E_{\text{slot}}$ 为「不同专家占比」

只看字节，去重核永远不比逐槽核多读（$\bar u\le 1$），而且 $n$ 越大省得越多。如果故事到这里就结束，大家早就全换成去重核了。动画 1 演示这本账，以及它为什么不够。

③ 路由复用：实测比均匀假设高 3–8 倍

MoESD 等前作用均匀路由估算并集：每个 token 独立、等概率地选 $m$ 个专家。真实模型里相邻 token 的路由高度相关。论文在 WikiText-103 上实测了第二个 token 的复用率 $\hat\rho(2)$：

第二个 token 就有 36–49% 的专家是前一个 token 已经选过的，是均匀假设的 2.9 倍（OLMoE）到 7.7 倍（Qwen3）。到第 9 个 token，新 token 的专家有 76–86% 已在并集里。这与其他工作测到的 Qwen3 相邻 token 复用 44–48%、0.444 一致。

复用越高，并集越小，$\bar u$ 越低，去重核在字节上的优势越大。Table 1 里 $n=8$ 时 OLMoE 的 $\bar u=0.50$，gpt-oss 只有 $0.36$：去重核只需读逐槽核三分之一出头的专家字节。

复用率是一个序列：论文的阈值和节省公式都写在 $\rho_l(j)$ 上，而不是一个标量「平均复用率」。下文第 ⑦ 节会看到，这一点决定了「复用高于某个常数就赚」这种单一规则不存在。

④ 带宽反转：去重核反而更慢

字节少不等于时间短。论文给每个 kernel 单独测了有效带宽：读到的专家字节除以 kernel 耗时。Table 1 把两种核的带宽并排放（单位 GB/s，$r=\beta_{\text{dedup}}/\beta_{\text{slot}}$）：

每一行都是 $r<1$：去重核的有效带宽只有逐槽核的 32–75%。原因有两层：

  • 逐槽核重读便宜。同一个专家被两个槽位选中时，第二次读常常命中缓存。论文用拟合 (4) 估出重读一份专家相对首读的成本 $c_{\text{re}}/c_u$：CUDA 0.18–0.34，MLX 0.27–0.40，Metal 0.88–1.04。RTX 4070 Ti SUPER 有 48 MiB L2，从 $n=4$ 起逐槽核的「有效带宽」甚至超过 672 GB/s 的 DRAM 峰值，因为重复槽位由 L2 供数。Metal 上重读几乎不打折。
  • 去重核本身更慢。它需要额外的 gather/scatter、更多 launch（CUDA 上一次前向 160 次 launch 对 64 次，约多 0.1 ms），每个专家只拿到少数几个 token 的激活，矩阵乘形状更差。MLX 的 issue 4509 也记录过：gather qmm 在 M=1 时带宽只有 M=4 的一半左右。

所以两个比值在打架：$\bar u$ 说去重核少读多少字节，$r$ 说去重核每字节慢多少。动画 2 把两者摆在一起。

⑤ 节省公式：ū 与 r 比大小

论文把一次 $n$-token 前向在 kernel 选择 $p\in\{\text{slot},\text{dedup}\}$ 下的时间写成

$$\tau_p(n)=t_0+\frac{D(n)}{\beta_D}+\frac{E_p(n)}{\beta_p(n)}+\varphi_p(n)$$(5) 固定开销 + 稠密部分（注意力、共享专家等）字节 ÷ 带宽 + 专家字节 ÷ 该核带宽 + 其余项

两种核只在专家项上不同。把专家项相减并提出逐槽核的时间：

$$S(n)=\frac{E_{\text{slot}}}{\beta_{\text{slot}}}-\frac{E_{\text{dedup}}}{\beta_{\text{dedup}}}=\frac{E_{\text{slot}}}{\beta_{\text{slot}}}\Big(1-\frac{\bar u}{r}\Big)$$(6) 去重核相对逐槽核省下的时间
$$S(n)>0\iff \bar u(n)<r(n)$$(7) 去重核更快，当且仅当「不同专家占比」小于「带宽比」

如果只有一个带宽（$r\equiv 1$），因为 $n\ge 2$ 时总有 $\bar u<1$，去重核在每个 $n\ge2$ 上都更快。这正是单带宽模型的结论，也正是它错的地方。Table 1 里：

  • CUDA OLMoE：$n=2$ 时 $1-\bar u/r=1-0.82/0.75=-0.093$，逐槽核更快；$n=8$ 时 $1-0.50/0.58=+0.138$，去重核更快。中间某个 $n$ 发生交叉。
  • CUDA DSV2-Lite：$n=8$ 时 $1-0.62/0.59=-0.05$，在测到的范围内去重核一直更慢。
  • Metal Qwen3、Metal DSV2-Lite、MLX OLMoE 在 $n=8$ 时 $\bar u/r$ 分别是 1.23、1.48、1.56，去重核依然明显更慢。
这就是 llama.cpp 默认在小 $n$ 用逐槽核的原因。PR 30047 靠手工调参决定 per-slot/dedup 的切换点；公式 (7) 说，这个切换点就是 $\bar u(n)$ 曲线穿过 $r(n)$ 曲线的那个 $n$，而两条曲线都能在一小时内测出来。

⑥ 最佳草稿长度是一道阶梯

有了步长时间 $V(k)$（$k$ 个草稿的一轮总时间，$V(0)$ 是普通解码一步），几何接受率 $a$ 下一轮期望产出 $G_a(k)=(1-a^{k+1})/(1-a)$ 个 token，吞吐是 $T_a(k)=G_a(k)/V(k)$。投机比不投机快的条件和加速比是：

$$T_a(k)>T_a(0)\iff V(k)-V(0)<(a+a^2+\cdots+a^k)\,V(0)$$(8) 多花的时间，要少于「期望多接受的草稿数 × 一步普通解码的时间」
$$\frac{T_a(k)}{T_a(0)}=\frac{G_a(k)\,V(0)}{V(k)},\qquad a_0=\frac{V(1)}{V(0)}-1$$(9) 加速比；$a_0$ 是 1 个草稿开始赚钱的接受率

注意 $V(k)$ 里的带宽是在 $k+1$ 个 token 的前向上测的，$V(0)$ 里的是 1 个 token 前向的带宽，两者不要求相同。这正是 MoE 和稠密模型的差别：稠密模型的 $V(k)$ 几乎是平的，MoE 的 $V(k)$ 随 $k$ 明显上升。

第 3.3 节的阶梯定理说：

  • 单调：$a\le a'\Rightarrow k^*(a)\le k^*(a')$。证明只用到 $i<k$ 时 $G_a(k)/G_a(i)$ 关于 $a$ 不减，不需要 $T_a$ 关于 $k$ 单峰，所以阶梯可以一次跳过不止一级。
  • 台阶位置精确可算：$a_j=\max_{i<j}\min_{k\ge j}\alpha_{k,i}$，其中 $\alpha_{k,i}$ 是草稿长度 $k$ 开始胜过 $i$ 的最小接受率。
  • 凸步长时的简化：若增量 $c_i=V(i)-V(i-1)$ 满足 $0\le c_1\le c_2\le\cdots$，只需比较相邻两级：
$$k^*(a)\ge j\iff a^j\,V(j-1)>G_a(j-1)\,c_j,\qquad a_1=\min\!\Big(\frac{c_1}{V(0)},1\Big)$$(10) 第 j 个草稿值不值：它被接受的概率 × 前 j−1 级的步长，与前 j−1 级产出 × 它新增的时间比大小

这一节和上一节的代数只用到 $V>0$，Lean 中也是在这个一般性下证明的。动画 3 用一组示意参数画出两道阶梯：MoE 型 $V(k)=1+0.12k+0.01k^2$ 与稠密型 $V(k)=1+0.02k$。前者 $a_1=0.13$，接受率 0.8 时 $k^*=4$、加速 2.05×；后者 $a_1=0.02$，同一接受率下 $k^*=11$、加速 3.8×。这两组数字不是论文的测量，只用来说明形状。

⑦ 复用阈值

对于验证时全程走去重核的引擎，第 3.4 节把条件 (8) 改写成对路由的要求。先定义 $k$ 个草稿 token 的字节加权平均复用率

$$\bar\rho_k=\frac{1}{kW}\sum_l w_l\sum_{j=2}^{k+1}\rho_l(j),\qquad E_{\text{dedup}}(k+1)=mW+mWk(1-\bar\rho_k)$$(11)(12) 专家字节只由路由决定

草稿长度 $k$ 比不投机快，当且仅当 $\bar\rho_k>\rho^*_k(a)$，其中（$B_k=\beta_{\text{dedup}}(k+1)$）

$$\rho^*_k(a)=1-\frac{B_k}{mWk}\Big[(G_a(k)-1)\tau(1)-\frac{\Delta D_k}{\beta_D}-\Delta\varphi_k\Big]-\frac1k\Big(\frac{B_k}{\beta(1)}-1\Big)$$(14) 方括号是草稿在专家读之外可以多花的时间；最后一项在去重核比 1-token 前向更慢时要求更多复用

在单一带宽、零固定开销下它退化为纯字节形式 (16)：$\rho^*_k(a)=1-\big[(G_a(k)-1)V_{\text{dedup}}(0)-(kv(k)-kv(0))\big]/(mWk)$。这是「只数字节」能给出的阈值。

三个性质值得记住：

  • 阈值随 $a$ 上升而下降：接受率越高，越不需要复用来帮忙。
  • 更多复用只会降低每个 $E_{\text{dedup}}(k+1)$，所以在一种路由下成立的加速，在任何复用更多的路由下都成立。前提是去重核在固定 $n$ 下的带宽和固定开销不依赖于哪些专家重复。
  • 路由只通过 $(\bar\rho_1,\dots,\bar\rho_{k_{\max}})$ 这个序列进入结论，不存在一条对所有路由都成立的单一规则「$\bar\rho_k>c$ 就赚」（附录 B.2）。

⑧ 带宽误差怎么传到结论里

整套理论里唯一需要测量、又测不准的量是带宽。论文假设每个带宽的估计 $\hat\beta=\beta(1+e)$，$|e|\le\varepsilon<1$，其余项精确，然后证明了五条误差界（Table 2，全部在 Lean 中验证）。记 $M_p(n)$ 为 $\tau_p(n)$ 中的内存部分，$M^e_p(n)$ 为其中的专家部分：

预测量误差界含义
验证时间 (17)$|\hat\tau_p-\tau_p|\le\frac{\varepsilon}{1-\varepsilon}M_p\le\frac{\varepsilon}{1-\varepsilon}\tau_p$相对误差不超过 $\varepsilon/(1-\varepsilon)$
节省 (18)$|\hat S-S|\le\frac{\varepsilon}{1-\varepsilon}\big(M^e_{\text{slot}}+M^e_{\text{dedup}}\big)$分子是两项之和，$S$ 是两项之差
哪个核更快 (19)$|\ln r-\ln\bar u|>\ln\frac{1+\varepsilon}{1-\varepsilon}$ 时符号可靠交叉点附近判不准
最佳草稿长度 (20)$T_a(\hat k^*)\ge\frac{1-\delta}{1+\delta}T_a(k^*)$选错最多损失 $2\delta/(1+\delta)$ 吞吐
最佳加速比 (21)介于 $\frac{1-\delta}{1+\delta}$ 与 $\frac{1+\delta}{1-\delta}$ 倍之间$\delta\le\varepsilon/(1-\varepsilon)$

10% 的带宽误差给出 $\delta\le 0.111$，加速比最多偏 $1.111/0.889-1=25\%$。三类预测的敏感度排序很清楚：

  • 节省最敏感。误差界相对于 $S$ 本身的放大倍数是 $(M^e_{\text{slot}}+M^e_{\text{dedup}})/|M^e_{\text{slot}}-M^e_{\text{dedup}}|$，在交叉点处趋于无穷。实测放大倍数：MLX 3.2–3.8×，CUDA 6–220×，Metal 3.2–340×，最大值都出现在交叉点。
  • 验证时间居中。它多乘了一个 $M_p/\tau_p\le1$。
  • 最佳草稿长度最不敏感。所有 $V(k)$ 共享的公共误差因子不改变 $\arg\max$。

各引擎的 $\varepsilon$ 取两种核拟合误差的较大者：llama.cpp CUDA 0.054，llama.cpp Metal 0.031，MLX-LM 0.148。

⑨ 实验复盘

实验设置

  • 硬件：Apple M4 Max（546 GB/s，跑 llama.cpp Metal 与 MLX-LM）；RTX 4070 Ti SUPER（672 GB/s，48 MiB L2，跑 llama.cpp CUDA）。
  • 引擎改动：每个引擎只加一个开关，把小 $n$ 的验证前向送进它已有的去重核。开关关闭时保持默认（$n\le9$ 逐槽，CUDA 上 $n\le 8$）；打开时从 $n=2$ 起走去重核。附录 E 核对了两种设置输出一致。
  • 配置：OLMoE、Qwen3、gpt-oss × 上下文深度 $d\in\{512,4096\}$ × 引擎，共 12 个配置；6 个 WikiText-103 验证集 prompt（与提供路由 trace 的测试集文档不相交）。
  • 草稿：oracle 草稿，提出目标模型自己的贪心 token，再以概率 $1-a$ 破坏，使接受率恰为几何分布。$k=0..8$，11 个接受率取值 0.2–0.98。
  • 预测怎么来：按 (22) 把每层专家算子的时间加到实测的单 token 时间上：$\hat\tau_p(n)=\tau^{\text{meas}}(1)+\sum_l(\bar t_{p,l}(n)-\bar t_l(1))$。专家算子时间来自字节拟合，在 WikiText 路由 trace 的每个窗口上求值，不用任何整模型运行的数据。「实测时间版」跳过拟合，直接用每层算子在路由窗口上的实测中位时间。
唯一一次事后修改：第一次计算时，单 token 时间 $\bar t_l(1)$ 取自去重核的拟合，结果 12 个配置里有 10 个交叉点放错。因为引擎在 $n=1$ 时无论开关都走逐槽核，作者改用逐槽核拟合。论文明确说这是与测量对比后做的唯一改动。OLMoE、Qwen3、gpt-oss 的预测都是在整模型数据已经存在之后算的。

字节：去重核读的就是并集

在 OLMoE 和 gpt-oss 的一层上，用 Nsight Compute 跑了 $n=2..8$ 共 70 个 profile。去重核从 DRAM 读到的字节与并集字节 $Ub$ 相差 0.2–2.5%。逐槽核请求 $nmb$ 字节，实际 DRAM 读取在 $Ub$ 到 $2.35\,Ub$ 之间（Figure 3），多出来的部分被 L2 吸收。验证文本上的不同专家占比 $U/(nm)$ 与 WikiText 相差不超过 0.06，只有 gpt-oss 在 $d=4096$ 时低 0.08–0.16：那组文本里 81% 的 4-gram 是重复的（$d=512$ 时 48%）。

⑩ 论文没给的东西

  • 只有 batch=1。服务端的 MoE 推理通常是多请求合批，此时不同请求之间的专家重叠、逐槽核的 L2 命中、去重核的矩阵形状都会变，(7) 的两边要重新测。论文把 batch>1 列为后续工作。
  • 带宽不可预测。理论把带宽当成测量输入。作者试过用其他模型的拟合去预测一个留出模型，误差 9–206%。换模型、换量化、换引擎版本，都得重新花一小时测。
  • 草稿是 oracle，草稿成本取零。几何接受率和 $h(k)=0$ 让阶梯定理干净可用，但真实草稿模型的接受率随位置衰减、按 token 难度波动，草稿本身也要时间。开篇那个 33/37 的 MT-Bench 结果用的是真实草稿，正文验证用的却是 oracle，两者之间没有对接。
  • 大部分验证是事后的。OLMoE、Qwen3、gpt-oss 的预测在整模型数据存在后才算，还做过一次对照测量后的修正。真正预注册的只有 DeepSeek-V2-Lite 一个模型，而且 Metal 上六条规则只过了三条。
  • Metal 需要校准。Metal 在 $d=512$ 时有一个「慢 GPU 状态」，跨运行偏移明显，实测时间版吞吐损失超过 20%，要靠校准版才降到 6–8%。
  • 覆盖面窄。每个平台一台机器，模型 7–30B，DRAM 字节计数只在 CUDA 上有。
  • 可复现性。代码和数据「按需提供」；论文说明代码、图、Lean 证明和初稿由 AI agent 完成，单一作者负责指导和审阅。
对引擎开发者最有用的一条：不要用单一带宽的成本模型决定 per-slot/dedup 的切换点，也不要只看并集字节。对每个 $n$ 测一次 $r(n)$ 和 $\bar u(n)$，切换点就是两条曲线的交点；如果 $|\ln r-\ln\bar u|$ 小于 $\ln\frac{1+\varepsilon}{1-\varepsilon}$，说明两种核差不多快，选哪个都行。论文的结论里把 $r(n)$ 称为 kernel 工作的杠杆：把去重核的带宽做到接近逐槽核，MoE 投机的收益才会出来。

⑪ 一句话总结

MoE 上投机解码快不快，由「不同专家占比 $\bar u$」和「去重核相对逐槽核的带宽比 $r$」谁大决定；在这个字节 ÷ 带宽的步长模型上，最佳草稿长度是一道单调、可跳级、台阶点可精确计算的阶梯，带宽误差 $\varepsilon$ 对它的影响最小，对两种核的节省影响最大。
