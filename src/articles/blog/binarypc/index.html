BinaryPC

无训练、数据感知的哈希稀疏注意力：用二值 PCA 给 KV 缓存配一把"位运算钥匙"

解码时注意力是内存带宽瓶颈——KV 缓存越长，每个新 token 越要搬完整个缓存。BinaryPC 用二值主成分给 key 生成 64-bit 紧凑哈希码，让"找最相关的 KV"变成 XOR + popcount 位运算，解码吞吐最高 3.56× FlashAttention，精度追平全注意力，且不需要任何训练。

为什么：解码的瓶颈是内存带宽，不是算力

长上下文推理分两段：prefill（输入并行处理、建 KV 缓存，高利用率）和 decoding（自回归逐 token 生成）。解码的问题在结构上：每生成一个 token，都要重新读取全部 KV 缓存——缓存的长度就是内存搬运量，而 per-token 计算本身又少得可怜。序列越长，GPU 利用率越低，注意力层的成本几乎全部是"把 KV 从 HBM 搬进 SM"。

稀疏注意力的思路：只让少数 KV 参与计算。但"选哪些 KV"成了新的问题——选择本身要准（不能丢关键证据）、要便宜（不能比省下的还贵）、要快（每步都做）。

核心判断： 解码注意力是 memory-bound 问题。优化它的正确姿势不是让 GEMM 更快，而是减少要搬进 SM 的 KV 字节数——哈希注意力正是在这个维度上做文章：用紧凑二值码做"粗筛"，只把 top-k 的完整 KV 真正搬进来。

哈希注意力三分天下：随机、学习、以及空缺

哈希注意力的思路：把 query 和 key 都映射成紧凑二值码 $h \in \{-1,+1\}^H$（$H \ll D$），让哈希码的内积 $h_q^\top h_k$ 成为全精度内积 $q^\top k$ 的高保真代理，然后用位运算（XOR/AND/popcount）快速找出 top-k。现有两条路线都有硬伤：

投影来源数据无关随机超平面MLP，ranking 目标训练数据主方向，无训练
码长>1000 bit~128 bit64 bit
训练开销无8K 上下文训 8 小时/每模型零（一次前向或离线校准）
精度128K 时比 oracle TOPK 低 6.5pt好追平全注意力
吞吐0.42–0.50× FA-2（GPU-CPU 协作）—1.05–3.56× FA-2

为什么随机投影不行：LLM 的激活落在低维流形上，随机超平面与这个内在结构不对齐——哈希分区的边界经常把"本来就该在一起"的 token 切开。为了补偿，只能把码拉长到 1000+ bit，还附带 GPU-CPU 协作解码这种吞吐杀手。

为什么学习式也不行：MLP 哈希能拟合数据分布，但每换一个模型就要重新校准训练（8K 上下文、8192 样本、约 8 小时），作为 drop-in replacement 不现实。

空缺：既要数据感知（对齐激活流形）、又不能要训练。二值 PCA 恰好同时满足——主方向是数据的固有几何，不需要梯度。

方法：二值 PCA 哈希——用重建误差定义"好哈希"

BinaryPC 的目标函数是一个重建问题：给定 $N$ 个 key 向量 $\mathbf{K} \in \mathbb{R}^{N \times D}$，找二值哈希码 $\mathbf{H} \in \{-1,+1\}^{N \times H}$ 和实值投影 $\mathbf{P} \in \mathbb{R}^{H \times D}$，最小化

$$\min \|\mathbf{K} - \mathbf{H}\mathbf{P}\|_F^2$$

这个形式与 PCA 同构：PCA 找的是最小化重建误差的实值主方向，这里把编码系数强行二值化成 $\{-1,+1\}$。为什么非对称设计：key 的数量远多于单个 query，KV 的内存传输占主导，所以只对 key 做二值编码；query 侧用 $q\mathbf{P}^\top$ 投影后量化（H 个 sign 位 + H 个 7-bit 幅值，打包成 64-bit word），哈希分数完全用位运算算。

重建公式给出直接的代理：因为 $\mathbf{k} \approx \mathbf{h}\mathbf{P}$，对任意 query $q$：

$$q^\top k \approx q^\top \mathbf{P}^\top h = (q\mathbf{P}^\top) \cdot h$$

即"全精度内积 ≈ 投影后的 query 与二值码的相似度"——后者能用位运算算。

为什么这个形式有价值： 把"哈希"从启发式（随机投影）升级成了有明确目标的优化——重建误差有界，哈希码的保真度可度量。更妙的是这个误差信号是免费的：哪个 token 哈希得不好，重建误差直接告诉你。这为后面的 EAS 保险丝铺了路。

算法：迭代 rank-1 二值分解（Algorithm 1/2）

最小化 $\|\mathbf{K} - \mathbf{H}\mathbf{P}\|_F^2$ 的经典做法是 PCA 的迭代式：找最大奇异向量 → 从信号里扣掉这个分量 → 再找下一个。BinaryPC 把"主分量"换成二值主分量：

  1. 发现方向：从随机向量 $v^*$ 出发，反复计算 $\mathbf{R} v^{*\top}$——奇异值随迭代次数指数增长，最大奇异向量最终主导。由于要的是二值分量，直接用 $u = \text{sign}(\mathbf{R} v^{*\top})$ 作为二值主分量（最大奇异值保证它大概率偏向主方向，省掉精确 SVD）；
  2. 定幅值：$v = \mathbf{R}^\top u / \|\mathbf{R}^\top u\|$（u 是方向，v 是幅值）；
  3. 扣除：$\mathbf{R} \leftarrow \mathbf{R} - u^\top v$，迭代 $H$ 次得到 H 对 $(u, v)$，即哈希码 H 和投影 P。

Algorithm 2（推理时算单 key 哈希）：P 的行不保证正交，所以算一个新 key 的码要逐行迭代：残差 $r$（初始 $r = k$），对 P 的每行 $v$，取 $h = \text{sign}(r v^\top)$，然后 $r \leftarrow r - h v$。论文图的右半显示残差范数随码长稳定下降——两种算法在所有测试数据上都收敛。

OPC（离线投影校准）：投影 P 可以在线构造（prefill 时对每层 key 做一次 Algorithm 1），也可以离线用小校准集先算好。校准集刻意跨域：PG19（文学）+ ProofPile（数学/推理）+ CodeParrot（代码）各 60 样本。消融里只用 PG19 校准、在 LongBench 全任务上评估（含代码/合成推理等校准集没有的域），得分 30.43 vs 全注意力 30.57 vs 混合域 30.39——域迁移几乎无损，说明主方向是 LLM 激活的通用几何，不是特定语料特征。

为什么"随机向量 + 迭代"能行： 幂迭代的收敛来自奇异值谱的指数级分离——只要最大奇异值严格大于次大值，迭代几步后向量方向就几乎贴着主奇异向量。二值化（sign）非但没破坏收敛，反而因为最大奇异值的主导性，"大概率偏向主方向"就够用了，省掉精确 SVD 的成本。这是"估计够用即可"的工程哲学。

检索打分（Algorithm 3）

query 投影 $qP^\top \in \mathbb{R}^H$ 后转成 H 个 sign 位 + H 个 7-bit 幅值，打包成 H-bit sign word 和 7H-bit 幅值 word。哈希分数 = 位运算组合（XOR、AND、NOT、popcount、位移），top-k 候选进入稀疏注意力。64-bit 码恰好塞进一个 int64，是最优的精度/效率权衡点（消融：32-bit 在 104K 上下文掉到 86.37，64-bit 90.18，128-bit 90.00）。

EAS：重建误差是一根白送的保险丝

哈希检索有精度损失，但 BinaryPC 的重建形式给了它一个别人没有的东西：逐 token 的可解释误差信号。对 token $k$，重建误差 $\|k - hP\|$ 大，说明这个 token 难被二值码表示，它的检索保真度存疑。

Error-Aware Safeguard（EAS）：prefill 阶段用这个误差挑出 top-m 个最难哈希的 token，记为 $\mathcal{S}_{err}$；解码时最终参与注意力的集合是

$$\mathcal{S}_{attn} = \mathcal{S}_{hash} \cup \mathcal{S}_{err}$$

即"哈希检索到的 ∪ 预判难哈希的"。为什么必须：passkey 这类 token 与周围上下文高度不相似，是投影构造时的 outlier，二值码天然抓不住它——消融里去掉 EAS，R.PK 从 99.00 崩到 64.00，而只要 2% 的预算就完全恢复。且 EAS 预算比例 2%~15% 性能几乎不变（47.42~47.63），说明它是稳健组件而非脆弱超参。

为什么这是亮点： 大多数稀疏注意力靠"启发式挑选"兜底，EAS 靠的是优化目标的副产物——重建误差不需要额外计算，是 Algorithm 1 本来就有的量。用最少的预算（默认预算的 10%）兜住最坏情况，是一种"知道自己的哈希哪里会错"的自我认知。

GPU 实现：三阶段检索流水线

为榨干硬件，BinaryPC 写了自定义 CUDA kernel：key 经投影矩阵转成 64-bit 二值码；query 的 8-bit 量化元素拆成 8 个 bit-plane，打包成 64-bit word。检索分三个阶段：

  1. Searching：CUDA kernel 算投影 query 与全部二值 key 码的哈希分数——纯位运算（XOR + popcount），内存搬运从 D 维浮点变成 64-bit 整数；
  2. Selection：torch.topk 选 top-k；
  3. Gathering：torch.gather 取对应的 KV 对，喂给 FlashAttention。

512K 上下文的具体账：FlashAttention kernel 调用从 1.814 ms 降到 163 µs（单注意力层 4.0×），检索三阶段合计 295 µs。注意——检索开销已经超过 FA 本身了，但相对总解码延迟仍小，端到端依然净赚 3.56×。

诚实的账本： 单层总时间 = 163 µs（稀疏 FA）+ 295 µs（检索）= 458 µs，对比原 1.814 ms 是 3.96×——4.0× 只是 FA 部分的口径。检索流水线（topk/gather 用 torch 而非融合 kernel）是明显的优化空间，融合后还能再压。

实验与诚实的解读

精度

模型：Llama-3-8B、Llama-3.1-8B-Instruct、Mistral-7B-Instruct-v0.3、Qwen2.5-7B-Instruct-1M（附录含 70B）。基准：短上下文（GSM8K-CoT/MMLU/CoQA）、LongBench、InfiniteBench、LongBench v2、RULER 与 NIAH（8K→128K）。注意力预算 2%（其中 10% 留给 EAS）。

场景结果
短上下文 (Llama-3-8B)BinaryPC 59.31 平均，超 MagicPIG 与 Spotlight；OPC 变体 63.82 逼近全注意力
LongBench 2% 预算持平全注意力；1K 预算在 Mistral/Qwen 上反超全注意力
InfiniteBench / LongBench v2近乎等价全注意力（平均序列 >100K）
RULER / NIAH 8K–128K追平全注意力，NIAH 全针位全长度匹配；逼近 oracle TOPK（MagicPIG 低 6.5pt）

效率

Llama-3.1-8B，8 张数据中心 GPU（另测 8 张消费级卡），对比 FlashAttention-2：

配置加速
batch=2，长上下文最高 3.56×
batch=1，长上下文最高 3.17×
batch=16, 64K / 128K（FA-2 回退场景）4.25× / 5.04×
短上下文持平（检索固定开销不划算）

batch=16 的 5.04× 有个有趣的机制：FlashAttention-2 内部在 batch > 15 时会从 Split-K kernel 切回标准 kernel，吞吐暴跌；BinaryPC 虽然也调用 FA-2，但输入只剩 2% 的 KV，暴跌被大幅缓解。

诚实的解读（坑）： ① 2% 预算意味着 98% 的 KV 不参与注意力，精度保持主要靠检索类任务（NIAH/RULER）"答案集中"的特性，复杂推理类（如 En.Dia）增益有限；② 短上下文无增益——哈希检索的固定开销在短序列不划算；③ 在线投影构造有 prefill 成本，实际部署形态是 OPC；④ MagicPIG 对比含"队友因素"（其 GPU-CPU 协作解码本身是吞吐杀手）；⑤ 与全注意力对比的"1K 预算反超"需要谨慎看待（可能是任务噪声）。

总结

  • 一句话：BinaryPC 用二值 PCA 把"哈希注意力"从随机投影/学习式两条路之外开出第三条——数据感知、无训练、64-bit 码，解码吞吐最高 3.56× FlashAttention 且精度追平全注意力。
  • 可迁移的洞察：① 把哈希定义为重建优化（而非启发式），让哈希码的保真度可度量、误差可解释；② 重建误差是免费的检索质量信号，EAS 用最小预算兜住 outlier——"知道自己哪里会错"比"试图全对"更工程；③ 非对称编码（只编码 key）精准命中 memory-bound 瓶颈的搬运方；④ 幂迭代 + 二值化省掉 SVD，"估计够用即可"。
  • 局限：检索流水线还有融合空间（topk/gather 未融合）；在线投影的 prefill 开销未与 OPC 仔细对比；复杂推理任务上的增益弱于检索任务；2% 预算是激进假设，需要真实 workload 验证。
