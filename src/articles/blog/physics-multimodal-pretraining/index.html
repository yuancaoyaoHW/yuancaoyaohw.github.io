多模态预训练的物理

Knowledge Flow · Modality Synergy · Early Unification · Recipes——用三层证据把统一预训练从 heuristics 推向 phenomenology

Meta FAIR + 牛津用"控制变量实验 + 合成数据因果消融 + 13.5B MoE × 2T token 规模验证"，拆出四条规律：知识流不对称（语言是万能助推器，生成是中性乘客）、复杂度决定协同/竞争、早期统一必要（否则触发视觉懒惰）、非对称配方 70/25/5——只用 5% 生成预算就达到强生成。

实验设计：为什么这套证据可信

这篇工作的分量不在某个惊人的数字，而在证据链的完整性——每一条规律都走完"真实数据发现 → 合成数据因果验证 → 规模单变量对照"三步：

  • 框架：Transfusion（文本 next-token 预测 + 视觉连续 flow matching 统一建模），Llama-3 式主干（SwiGLU/RoPE/GQA/QK-norm），默认 1.5B 模型 + 模态专属 split FFN ≈ 2.3B 参数；
  • 真实数据：语言 DCLM + 视觉 SSTK（约 350M 图文对），预算扫 100B 到 2T token；
  • 合成数据：CLEVR 扩展（百万场景、五概念轴），可逐概念从单模态流中删除——把真实数据上的相关关系变成因果陈述；
  • 规模验证：13.5B MoE（256 experts、top-16、1.5B active），2T token，三个单变量对照（配方/架构/时机）。
为什么可信： 视觉理解用 16 基准四轴（General / Knowledge / OCR&Chart / Vision-Centric）评估，生成用 GenEval / DPG-Bench / CLIP 相似度 / 扩散 loss / FID 多口径——避免"单个基准上的偶然胜利"。所有结论还在四种视觉 tokenizer（RAE / Raw Pixels / CLIP+VAE / AR UniTok）上复现，确认规律来自学习目标本身而非表示空间。

规律一：知识流不对称——语言是司机，生成是乘客

统一模型同时训练三种能力：语言、视觉理解（图→文）、视觉生成（文→图）。它们之间的知识传递是严格不对称的：

传递方向强度证据
语言 → 视觉理解 / 生成万能助推器语言比例 0%→80% 单调提升全部视觉理解轴 + 生成质量（conditional/unconditional 扩散 loss 双降）
理解 → 生成强先验理解 token 比例提升显著改善生成指标、大幅降低扩散 loss
生成 → 语言 / 理解中性生成比例扫描只引起无方向的小波动；flow matching 与 next-token 不冲突但几乎不反哺

为什么语言是万能助推器：论文援引 Platonic Representation Hypothesis——成熟的语言流形天然捕获模态无关的世界结构，视觉学习被它 bootstrap。为什么生成中性：flow matching 目标学到的是 dense pixel-level 细节，对稀疏语义理解任务大多是冗余信息。

直接推论： 谁是 driver、谁是 passenger 决定了算力预算怎么分。生成是"被引导方"——想让模型会画，先让它读得懂。这为后面的 70/25/5 配方埋下伏笔。

概念依赖：CLEVR 合成数据把相关变成因果

真实数据混杂了太多因素。论文用 CLEVR 做了一个干净至极的测试：百万场景、五条概念轴（颜色、形状、空间关系、大小、计数），对每个概念生成三条平行模态流（文生图对、图生文描述、VQA 问答）。然后从一个模态流里精确删掉某个概念（正则过滤 + 渲染器元数据双重校验），观察另一个模态是否零样本迁移——任何差异只能归因于知识传递。

零样本迁移：低层概念双向失败，结构概念单向成功

  • 低层概念（颜色、形状）：双向零样本迁移完全失败——从生成流删颜色，生成崩到零暴露基线；从理解流删颜色，VQA 崩。视觉词汇必须在每个任务目标内显式学习。这直接实证支持解耦架构设计（生成要 dense pixel-level、理解要 sparse semantic，共享表示难两全）；
  • 结构概念（空间关系、大小、计数）：非对称——只在理解流里保留，模型能零样本生成它们（空间/组合知识可引导生成）；但只在生成流里保留，VQA 基本崩（计数是唯一例外）。

Latent prior：方向反转

零样本失败不等于没有留下潜伏知识。用消融 checkpoint 微调 2000 步，测量概念恢复速度：

  • 生成 → 理解：强 latent prior——先前只通过生成接触过颜色/形状的模型，理解恢复显著更快（Δmean acc +0.133 ~ +0.273）。生成目标强迫模型学精确像素分布，一旦教会映射到语言就极速复用；
  • 理解 → 生成：几乎无 prior（颜色恢复曲线与对照组重叠，Δ≈0）——判别特征太抽象稀疏，撑不起 dense 重建。
这把行业悖论解释清楚了： 为什么联合生成训练对标准理解任务"没用"、却对空间/几何/物理推理任务"有用"？标准基准只要求稀疏语义分类，生成学到的 dense 细节是冗余；而空间推理任务要精确的深度/边界/透视——生成目标恰恰强迫模型学会这些。潜伏的几何基础在零样本时休眠，遇到需要 dense 特征的任务时被瞬间激活。

规律二：复杂度决定协同还是竞争

统一模型把一套参数分给三个目标。什么时候互相成就（synergy）、什么时候抢容量（competition）？决定因素首先是数据/任务复杂度。论文固定 100B 预算、50/50 模态分账，把视觉目标沿 7 级复杂度阶梯（纯背景 → 图案 → 噪声 → 文字渲染 → OCR → 视频 → SSTK 自然图像）逐级升级，语言流保持 DCLM 不变；对称地，把语言沿 3 级（单个字母 → 乱码 → DCLM）升级，视觉保持 SSTK。

视觉复杂度对语言 ppl 的影响 (Δ)结论
纯背景 / 噪声−0.211 / −0.183（提升！）简单任务 = 跨模态助推器
图案 / 文字渲染 / OCR过渡区间协同逐渐衰减
视频 / SSTK+0.052 / +0.075（恶化）复杂分布 → 竞争压过协同

反直觉的核心发现：让模型学一个极简单的对方模态任务，反而提升本模态——纯背景视觉任务比纯语言模型的语言困惑度还好（Δ−0.211）。对称地，最简单的语言分布给视觉生成带来最大提升（Δ−0.0153 conditional）。但当两边都是高熵复杂分布时，有限参数容量被激烈争夺，竞争最终盖过协同。

机制画面： 统一预训练是两种相反力的叠加——跨模态协同（底层结构共享）与容量竞争（高熵分布争夺参数）。两者在同一训练循环里共存，谁占上风由任务复杂度决定。架构要做的事：放大协同、隔离竞争。

架构解剖：共享注意力 + 解耦 FFN = 最优分工

复杂度之外，参数共享方式决定协同/竞争在网络内部哪里发生。论文把 Transformer block 拆成三个可配置参数组（FFN / Attention / FinalNorm），训练五种配置（都用简单语言 + 纯背景放大信号）：

配置语言 ppl 变化视觉 loss 变化解读
dense（全共享）+0.272+0.0537强制不同模态进同一参数子空间 → 严重竞争
split_ffn（只拆 FFN）−0.211−0.0168隔离计算容量 + 保留跨模态注意力 → 最优
split_ffn_attn（再拆注意力）−0.045−0.0064去掉跨模态语境化 → 收益大减
split_ffn_norm（拆 norm）明显缩水明显缩水去掉尺度对齐 → 收益大减
split_all（全拆）≈0≈0等于两条独立网络 → 回到基线

机制假设：共享注意力让模态在联合表示空间里互相语境化（协同的桥）；共享 normalization 对齐特征尺度；FFN 则充当模态专属专家，吸收各自独立的计算需求，防止在共享基底上互相破坏。这为 MoT（Mixture-of-Transformers）和带模态专属专家的 MoE 架构提供了直接实证。

泛化：四种视觉 tokenizer（RAE / Raw Pixels / CLIP+VAE / AR UniTok）上协同现象全部复现——预对齐的共享表示空间不是跨模态协同的绝对前提（但仍是加分项，能减少表示摩擦、放大协同幅度）。

规律三：早期统一是机械必然，晚了对齐触发"视觉懒惰"

时机：存在一个"统一窗口"

固定 1T 预算，扫描纯语言 warm-up 0 → 200 → 400 → 600 → 800B：语言侧收益在 600–800B 后平台，但所有视觉能力随 warm-up 拉长陡降。结论不是"0B 最优"——一个最小限度的语言预热可以提供基础文本先验而不重伤视觉；但把统一推得越晚，对语言收益越小，对视觉伤害越大。

顺序：6 种模态顺序全部输给联合训练

固定 50/25/25 mix，测试全部 6 种模态顺序（含人类式的 vision-first：生成→理解→语言），带或不带 12.5% replay 缓冲：任何顺序的隔离训练都输给联合训练。replay 只缓解灾难性遗忘，追不上协同——模态不是共存，是共同进化。

Vision Laziness：四个机械测量

为什么晚对齐伤视觉？论文用同一组 checkpoint、每次都随机初始化图像侧 FFN（img_ffn，保证测量公平），沿四轴探测：

  1. A. 训练时激活：img_ffn 的 L2 激活范数随语言 warm-up 拉长而"越来越安静"——视觉通路投入的学习量实际在减少；
  2. B. 嵌入范数：图像 wrapper token（<begin_of_img> 等）的嵌入范数缩小——硬化后的语言通路拒绝为图像重塑自身，把 wrapper 挤到远离正常词表尺度；
  3. C. 推理时激活：真实视觉前向中 img_ffn 的逐元素 RMS 暴跌——用到视觉时视觉分支做得越来越少；
  4. D. 注意力分配：推理时投向图像 token 的注意力比例骤降（生成侧图像 query 看其他图像 patch 的比例、理解侧文本 query 看图像 patch 的比例）——模型干脆不看图了，默认依赖周围文本。
为什么这解释了"强 MLLM 也失明"： 语言主干越强，越擅长用语言先验 shortcut 视觉问题。当语言通路过早优化完毕，联合优化 landscape 被既有语言先验主导，视觉通路从未被真正逼着成熟——所以很多强大多模态模型仍犯低级视觉错误（MMVP 类失败）。视觉通路只是"没被充分训练"，不是"没这个能力"。早期统一不是调度偏好，而是迫使模态从零共同进化的机械必然。

规律四：配方 70/25/5——生成只要 5% 预算

知识流不对称的直接推论：最优预算分配应该极度偏斜。三轴网格搜索（1T token）：Fix MM 扫语言比例 10%–90%，Fix Lan 锚定语言 50% 扫理解/生成内比，Next 锚定语言 70% 精调——最优出现在 70% 语言 / 25% 理解 / 5% 生成。

反直觉的点：生成只要 5% 就接近峰值——把生成从 25% 砍到 5%，通用 VQA 反而涨到 48.3，同时生成评测分数最高。原因正是规律一：生成无反向迁移，均衡混合是在浪费算力在低收益 token 上；语言 + 理解先验直接驱动生成。

诚实的解读：这套规律的边界在哪

  • 证据域：文本 + 静态图像为主，视频/音频未验证。动态模态引入时间维度，复杂度与计算需求都变，协同/竞争平衡可能重排；
  • 规模外推风险：13.5B 的规律在 1T 参数前沿可能失效——作者自己承认，容量足够大时生成可能反哺理解（emergent bidirectional flow），当前"生成中性"可能是容量不足的产物；
  • 5% 生成不是免费的：FID 5.234 vs 5.131（略差），且作者建议后期加生成比例或加专门的生成 midtraining stage 来补足；
  • MoE vs Dense 对比的口径：是 1.5B active vs 3.5B dense，总参数 13.5B vs 3.5B——严格说不是同 compute 对比，"1.5B 赢 3.5B"很大程度来自总参数量优势；
  • 语言轻微下降的归因：被归为 VL 数据文本分布与纯语言分布不同的 artifact——这个归因略轻巧，也可能是理解任务对语言容量的真实挤占；
  • 合成世界的干净：CLEVR 概念可精确消融，但真实世界的"概念"不这样干净可分——低层/结构的二分在真实场景是连续谱。

总结

  • 一句话：多模态统一预训练不是玄学——知识流不对称（语言/理解是司机，生成是乘客）、复杂度决定协同/竞争、早期统一是机械必然、70/25/5 配方用 5% 生成预算达到强生成，四条规律在 13.5B MoE × 2T token 上全部验证。
  • 可迁移的洞察：① 预算分配跟着知识流走——先让模型读得懂，再让它会画；② "简单任务助推器"提示：低复杂度模态数据可能是免费的跨模态正则；③ vision laziness 用四个机制测量把"MLLM 失明"从轶事变成可验证机制——检查视觉通路是否真的被训练到了；④ split_ffn ≈ MoE 模态专属专家，给架构选择提供了实证锚点。
  • 一句话点评：这篇的价值不在某个数字，而在于把多模态训练从"加什么数据、怎么接 encoder"的 heuristics 推向"模态如何互动"的 phenomenology——为下一代统一基础模型（any-to-any）提供了可检验的底层假设。
