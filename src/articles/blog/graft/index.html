GRAFT

Adaptive DLM-Based Draft Tree Construction with Target-Distilled Edge Scoring

扩散草稿模型一次前向就吐出所有未来位置的分布，这让传统「按父路径逐层展开」的建树方式彻底失效。GRAFT 补上两块拼图：边打分要看父子搭不搭（TDES），树多大要看当前解码状态（SABA）。

端到端 2.13×–6.36× 吞吐 +19.4% vs DDTree 额外开销 < 0.5 ms / 轮 arXiv 2608.20375

前置一：投机解码在优化的到底是什么

自回归解码慢，不是因为算得多，而是因为算得太零碎。生成一个 token 就要把整个模型的权重从显存搬进计算单元一次，batch size 为 1 时算力几乎全闲着，瓶颈在显存带宽。换句话说：一次前向能顺手算完几十个 token，可我们每次只要了一个。

投机解码就是来填这个空的。一个便宜的草稿模型先猜 $K$ 个 token，然后目标模型把这 $K$ 个位置塞进同一次前向里并行验证，把与目标模型自己会产生的输出一致的最长前缀留下。

$$\hat{y}_{t,d} \sim P_{\text{draft}}\big(\cdot \mid x^{(t)},\, \hat{y}_{t,$x^{(t)}$ 是第 $t$ 轮开始时的前缀，$\hat{y}_{t,<d}$ 是本轮已经草稿出来的 token。注意条件里带 $\hat{y}_{t,<d}$——这正是后面所有麻烦的来源。

关键指标叫平均接受长度（MAT, mean accepted tokens）：设第 $t$ 轮接受了 $a_t$ 个 token，则

$$\text{MAT} = \frac{1}{T}\sum_{t=1}^{T} a_t$$ 一次目标模型前向换来 $a_t$ 个 token。MAT 越大，摊到每个 token 的目标模型前向次数越少。论文原话是加速比「largely driven by」MAT。
但 MAT 不是目标函数。真正要最大化的是吞吐（TPS）。MAT 上去了、每轮的验证也变贵了，净收益可能是负的。这句话记住，它是理解 GRAFT 第二个创新点（SABA）的全部前提——也解释了后面实验里为什么 GRAFT 有时 MAT 反而低于 DDTree，速度却更快。

前置二：为什么要把草稿从一条链变成一棵树

草稿是一条链时，只要第一个 token 猜错，后面全废——接受长度直接归零。既然目标模型的一次前向本来就有余力，不如让它一次验证多条候选路径：在同一个位置放几个候选 token，把它们组织成一棵前缀闭合的树，用 tree-attention mask 让每个节点只能看见自己的祖先，一次前向验证整棵树，最后接受最长的那条被认可的路径。这就是树形投机解码，MAT 因此显著上升。

问题是树怎么建。自回归草稿模型的标准做法叫父路径条件展开（parent-conditioned expansion）：选中一个叶子，把它的整条路径喂回草稿模型，再前向一次，拿到的分布就是「在这条路径之后」的下一个 token 分布。两种基本操作是加宽（给同一个父节点加兄弟候选）和加深（把选中的叶子往下长）。EAGLE、SpecInfer、OPT-Tree 都在这个框架里做取舍。

前置三：DFlash 一次前向吐出所有位置，建树框架随之失效

扩散语言模型（DLM）不按从左到右一个个采样，它一次前向就把整块位置的分布同时算出来。用作草稿模型的代表是 DFlash：给定前缀 $x^{(t)}$ 以及当前目标模型的状态，它一次前向输出每个深度 $d = 1,\dots,D$ 上的词表分布 $q_{t,d}(\cdot)$。朴素用法就是每个位置取 argmax，串成一条链：

$$\hat{y}_{t,d} = c_{t,d}^{(1)} = \arg\max_{c \in V} q_{t,d}(c)$$ $c_{t,d}^{(r)}$ 记深度 $d$ 上分数第 $r$ 高的 token。$q_{t,d}$ 是边缘分布——它不知道深度 $d-1$ 上最终会落哪个 token。

这个「一次前向出全部」的性质让 DFlash 非常快，但也正是它和父路径条件展开的冲突所在。要给一条新的父路径求下一个 token 分布，就得让草稿模型以那条路径为条件重跑一次；而 DFlash 的前向条件里含有当前目标模型的状态，那条假想路径的目标模型状态在验证之前根本不存在。

死结在这里：你不能为每个候选父节点重跑一次草稿模型。手上只有一组与父节点无关的、逐位置的边缘分布，建树问题于是从「怎么展开」变成了「怎么在给定的候选节点之间连边」。

DDTree：能建树，但有两处糙

DDTree 是这条路上的第一个方案，思路直白：把每个深度的高概率 token 当作候选节点，然后在相邻深度之间选边，凑够固定的节点预算 $B$ 为止。候选前缀 $u = (u_1,\dots,u_\ell)$ 的路径分数是各位置对数概率之和：

$$S_{\text{DD}}(u) = \sum_{d=1}^{\ell} \log q_{t,d}(u_d)$$ 实现上用一个最大堆：反复弹出分数最高的前缀加入树，并把它的兄弟与孩子压回堆，直到选够 $B$ 个节点。

看出问题了吗？把 token $c$ 接到深度 $d$ 上，贡献恒为 $\log q_{t,d}(c)$，和父节点是谁完全无关。DDTree 的边打分是「父节点无感的」（parent-agnostic）。

糙处一：父子错配

路径分数只反映草稿模型对每个 token 的孤立置信度，不反映这个孩子跟这个具体父亲搭不搭。后果是：一个目标模型确实会产生的 token 已经在树里了，却挂在了错误的父节点下面——树里有这个 token，但没有那条路径。论文测出这类父子错配在 GSM8K 上高达约 45%。

糙处二：预算给死了

DDTree 每轮都用同一个预算（论文图中标注 Fix Budget = 128，Qwen3-8B 上实测平均树大小 110.2 个节点）。但节点的边际价值是随状态变的：

  • 简单的轮次本来就能接受很长一段（接受长度 15 左右），再加节点只是白交验证成本——论文测得这类轮次的最优预算就是搜索下界 32。
  • 困难的轮次确实需要更大的树（最优预算约 96），但收益也会饱和，继续加照样掉吞吐。

同一条固定预算既服务不好简单轮，也服务不好困难轮。这就是 GRAFT 要动的第二个地方。

创新一：TDES——把「这个孩子配这个爹吗」学出来

TDES（Target-Distilled Edge Scoring）不推翻 DDTree 的打分，而是在它上面加一个残差修正项。对一条从父 token $p$ 指向深度 $d$ 上的子 token $c$ 的边 $v = (p, c, d)$：

$$S_{\text{TDES}}(v) = \log q_{t,d}(c) + \beta \cdot \tilde{f}_\theta(p, c, d)$$ $$\tilde{f}_\theta(p, c, d) = f_\theta(p, c, d) - \frac{1}{|\mathcal{C}_{p,d}|}\sum_{c' \in \mathcal{C}_{p,d}} f_\theta(p, c', d)$$ $f_\theta$ 估计父子兼容度；$\mathcal{C}_{p,d}$ 是父节点 $p$ 下考虑的孩子集合；$\beta$ 控制残差强度，默认 $\beta = 0.2$。

第二个式子是重点，容易被跳过：$\tilde f_\theta$ 是在同一个父节点的兄弟集合内做了中心化的。为什么必须减掉均值？因为 $f_\theta$ 会带有父节点自身的偏置——某些 token 天生「后面接什么都像」，它给所有孩子的打分都偏高。不减掉这个偏置，比较的就不是「哪个孩子更配这个父亲」，而是「哪个父亲整体分高」，那又退回到与父节点无关的排序了。减掉均值后保留的是同一父节点下孩子之间的相对偏好，正好是选边需要的信息。

路径分数依然是沿边相加，所以最大堆展开的逻辑一行都不用改：

$$S_{\text{TDES}}(u) = \sum_{d=1}^{|u|} S_{\text{TDES}}(v_d)$$ 建树器仍是贪心最优先的堆展开——弹出分数最高的前缀、加入树、压回兄弟与孩子。没有动态规划，没有 beam search，换掉的只是排序键。
这个设计的克制之处：它没有试图重建一个「条件分布」，只在既有的边缘概率排序上叠一个小的、有界的偏移量。$\beta$ 一旦太大就会出事——见后面的敏感性实验，$\beta = 0.4$ 时错配率降到 79%，MAT 和吞吐却掉到了 $\beta = 0$ 以下。

TDES 打分器长什么样，以及怎么从目标模型里蒸出来

结构：一个可缓存的双塔

这个打分器每轮堆展开要被调用成百上千次，所以它的代价必须相对草稿/验证前向可以忽略。论文选了最省的形式——双塔内积，输入只有（直接父 token、子 token、深度）三样：

$$f_\theta(p, c, d) = s \cdot \frac{\big(g_p(e_p) + u_d\big)^{\top}\big(g_c(e_c) + u_d\big)}{\sqrt{m}}$$ $e_p, e_c \in \mathbb{R}^E$ 是目标模型的词嵌入（冻结不训）；$g_p, g_c : \mathbb{R}^E \to \mathbb{R}^m$ 是两个线性投影；$u_d \in \mathbb{R}^m$ 是可训练的深度嵌入，同时加到父、子两侧；$s > 0$ 是可学习的缩放。可训练的只有两个投影、深度嵌入和 $s$。

为什么能这么便宜？因为 $g_p(e_p)$ 与 $g_c(e_c)$ 只依赖 token id，可以在解码开始前一次性预计算好、整轮复用；运行时每条边只剩一次 $m$ 维内积。实测 TDES 的总开销约 0.3 ms/轮，约等于目标模型验证时延的 1.3%。（论文未给出 $E$、$m$ 的具体数值与总参数量。）

三级监督：从目标模型的轨迹里学偏好

训练数据是用 DDTree 跑投机解码时收集的目标模型轨迹，来自 3046 条留出 prompt（取自七个非 AIME 基准；AIME24/25 因样本太少整体留作评测）。监督分三个粒度，各管一件事：

① 分布级：让排序对齐目标模型的 logit

$$\pi^{\text{tgt}}_{p,d}(c) = \operatorname*{softmax}_{c \in \mathcal{C}_{p,d}}\big(z^{\text{tgt}}_{p,c}\big),\qquad \pi^{\theta}_{p,d}(c) = \operatorname*{softmax}_{c \in \mathcal{C}_{p,d}}\big(\log q_{t,d}(c) + f_\theta(p,c,d)\big)$$ $$\mathcal{L}_{\text{KL}} = \mathbb{E}_{(p,d)}\big[\, \mathrm{KL}\big(\pi^{\text{tgt}}_{p,d} \,\big\|\, \pi^{\theta}_{p,d}\big) \,\big]$$ $z^{\text{tgt}}_{p,c}$ 是目标模型在父节点 $p$ 下对孩子 $c$ 的 logit；只在被接受的父节点上取样，且两个 softmax 都限制在候选集 $\mathcal{C}_{p,d}$ 内——学的是候选之间的排序，不是整个词表。注意 $\pi^\theta$ 用的是未中心化的 $f_\theta$ 且不带 $\beta$：$\beta$ 与中心化是推理期的使用方式，不进训练目标。

② 成对级：直接压住错配这一种错误

$$\mathcal{L}_{\text{pair}} = \mathbb{E}_{(v^+, v^-)}\big[\, \mathrm{softplus}\big(\gamma - f_\theta(v^+) + f_\theta(v^-)\big) \,\big]$$ 从每条错配轨迹里构造一个正边 $v^+$ 与一个负边 $v^-$。负边有两种取法：同一个孩子挂到错误的父节点上，或正确父节点下的竞争孩子。这两种恰好对应「树里有这个 token 但路径不对」和「路径对但选错了孩子」。$\gamma$ 是 margin，论文未给数值。

③ 边级：给每条边一个绝对的对/错标签

$$\mathcal{L}_{\text{BCE}} = -\,\mathbb{E}_{(v, y_v)}\big[\, w_1 y_v \log \sigma(f_\theta(v)) + (1 - y_v)\log\big(1 - \sigma(f_\theta(v))\big) \,\big]$$ $y_v = 1$ 当且仅当在父节点 $p$ 下 $c$ 就是目标模型的下一个 token。正样本极稀疏，用正类权重 $w_1$ 平衡（数值未给出）。
$$\mathcal{L} = \lambda_{\text{KL}}\mathcal{L}_{\text{KL}} + \lambda_{\text{pair}}\mathcal{L}_{\text{pair}} + \lambda_{\text{BCE}}\mathcal{L}_{\text{BCE}},\qquad \lambda_{\text{KL}} = 1,\ \lambda_{\text{pair}} = 1,\ \lambda_{\text{BCE}} = 0.25$$ 训练：8 epoch，AdamW，学习率 $2\times10^{-3}$，weight decay $10^{-4}$。
三个损失的分工值得琢磨：KL 管「候选之间谁该排前面」，是主信号；成对 margin 直接针对失效模式造样本，把最该修的那类错误显式压住；BCE 提供一个绝对尺度，避免打分器只会做相对排序、跨父节点之间数值不可比。$\lambda_{\text{BCE}}$ 只给 0.25，说明它是校准用的辅助项而非主力。

创新二：SABA——每轮重新决定树该多大

SABA（State-Aware Budget Allocation）把预算变成一个每轮求解的小优化问题，目标不是 MAT 而是吞吐效用：

$$B_t = \arg\max_{B} U_t(B),\qquad U_t(B) = \frac{G_t(B)}{C_t(B)}$$ $G_t(B)$ 是期望草稿收益，$C_t(B)$ 是本轮解码代价，比值即「单位代价换来的收益」。

状态：三个信号，其中一个是 DLM 特有的

$$\text{conf}_t = \frac{1}{D}\sum_{d=1}^{D} q_{t,d}\big(c_{t,d}^{(1)}\big),\qquad \text{hist}_t = \frac{1}{w}\sum_{i=1}^{w} a_{t-i}$$ $$\text{degen}_t = \frac{1}{D-1}\sum_{d=1}^{D-1} r_{t,d} \;+\; \big(r_{t,D-1} - r_{t,1}\big),\qquad r_{t,d} = \cos\big(h_{t,d},\, h_{t,d+1}\big)$$ $h_{t,d}$ 是 DFlash 在深度 $d$ 的隐状态。状态向量 $s_t = [\text{conf}_t, \text{degen}_t, \text{hist}_t]$。$w$ 为接受长度历史窗口（数值未给出）。

置信度和接受历史是自适应树工作里的常规代理量，$\text{degen}_t$ 才是这篇针对 DFlash 加的东西：它度量表征退化——相邻位置的隐状态越往后越相似，靠后的草稿 token 就越难区分。式子里两项各有分工：前一项是平均相邻相似度（整体退化水平），括号里那项是从早到晚的增量（退化的斜率）。只看平均会漏掉「起点就平但没继续变差」的情形，加上斜率才能判断继续往深处加节点是否还有意义。

收益模型：一条会饱和的曲线

$$G_t(B) = 1 - \exp\!\left(-\frac{B}{\varphi^{\top} s_t}\right)$$ $\varphi$ 是与 $s_t$ 同维的三维参数。$\varphi^{\top}s_t$ 是饱和尺度：它大，说明加节点在更宽的预算范围内都还有用；它小，说明很快就边际递减。状态就是通过这一个标量进入收益曲线的。

代价模型：一条仿射的直线

$$C_t(B) = c_0 + c_1 B + c_2 B \cdot \text{prefix}_t$$ $c_0$ 是每轮固定开销；$c_1 B$ 是多出来的节点带来的近似线性工作量；$c_2 B\,\text{prefix}_t$ 是把一棵树对着更长的前缀做注意力时增长的那部分成本。在关注的预算区间内，建树与验证都近似随 $B$ 线性增长，所以仿射就够了。

$\varphi, c_0, c_1, c_2$ 在一个小的留出验证集上用同前缀预算重放拟合，评测时冻结。每轮 SABA 做的事非常朴素：把 $B$ 从 32 到 512、步长 16 全试一遍（31 次标量计算），取 $U_t(B)$ 最大的那个。没有闭式解，也没有查表。所有状态信号本来就在手上（来自草稿模型输出和上一轮验证结果），所以 SABA 只花约 0.1 ms/轮。

效果的上界在哪？论文做了一个 oracle 对照：固定前缀、KV cache 和 DFlash 输出，把同一轮用各个预算重放一遍，取真实吞吐最高的那个作为 oracle。SABA 平均保住了 oracle 吞吐的 94.1%，并在 64.1% 的轮次里达到 oracle 的 95% 以上。

一轮完整的 GRAFT

两个组件是正交的，在建树器这一处汇合：TDES 决定哪些边排在前面，SABA 决定什么时候停止展开。论文没有给编号的伪代码块，按正文与流程图，第 $t$ 轮做这些事：

  1. 草稿模型跑一次：DFlash 以 $x^{(t)}$ 与当前目标模型状态为条件前向一次，得到 $d = 1,\dots,D$ 的边缘分布 $q_{t,d}(\cdot)$ 与隐状态 $h_{t,d}$。
  2. 取候选节点：每个深度取分数最高的若干 token $c_{t,d}^{(r)}$。
  3. 算状态：由分布得 $\text{conf}_t$、由隐状态余弦得 $\text{degen}_t$、由 $a_{t-w},\dots,a_{t-1}$ 得 $\text{hist}_t$；SABA 另读 $\text{prefix}_t$。
  4. SABA 定预算：在 $B \in \{32, 48, \dots, 512\}$ 上网格搜索 $U_t(B) = G_t(B)/C_t(B)$，得 $B_t$。
  5. TDES 打边分：用预计算好的投影嵌入算 $S_{\text{TDES}}(v)$。
  6. 建树：最大堆按 $S_{\text{TDES}}(u)$ 排序，反复弹出最高分前缀加入树、压回其兄弟与孩子，直到选满 $B_t$ 个节点。
  7. 验证：目标模型用 tree-attention mask 一次前向验证整棵树，提交最长被接受路径，记下 $a_t$，进入下一轮。
整篇论文没有任何定理、命题或证明。唯一的形式化内容是收益/代价模型背后的两条建模假设：收益饱和、代价仿射。这不是缺陷，但读的时候要清楚——$G_t$ 和 $C_t$ 是拟合出来的工程近似，不是推导出来的。

三个值得停下来看的地方

一、DLM 草稿这条线整体领先一个量级。EAGLE-3 和 OPT-Tree 的 MAT 在 3–4 之间，DFlash 链式已经到 5.8–7.0，DDTree/GRAFT 到 8–9。更刺眼的是在 Qwen3-4B 上 EAGLE-3 与 OPT-Tree 有几组加速比掉到 1.0 以下（0.95–0.99）——小模型上自回归草稿的开销吃掉了全部收益，而这正是投机解码在小模型上一直没那么好用的原因。

二、GRAFT 在全部 27 个模型×数据集组合里加速比都最高。各模型上的最佳值：Qwen3-4B 的 Math500 6.36×、Qwen3-8B 的 Math500 6.17×、Qwen3-Coder-30B 的 HumanEval 6.01×。标题里 2.13×–6.36× 的下界来自 Qwen3-Coder-30B 的 Alpaca。

三、GRAFT 的 MAT 有时比 DDTree 低。看 Qwen3-8B 的 Alpaca：4.26 对 4.46，MAT 输了，加速比 2.80 对 2.38 却赢了 18%。这不是瑕疵而是设计的直接体现——SABA 优化吞吐，会主动放弃那些「能让 MAT 涨一点、但验证成本涨得更多」的节点。如果只看 MAT 这张榜，会得出完全错误的结论。

顺带一提任务间的落差。Math500 能到 6.17×，Alpaca 只有 2.80×，SWE-bench 3.13×。数学推理的输出格式化、可预测，草稿好猜；开放式指令跟随和仓库级代码修改的下一个 token 熵高得多。任何投机解码方案的收益都强烈依赖任务分布，看单一数字容易高估。

这张表是全文信息量最大的一处，三行读出三件事：

  • TDES 提升的是树的质量，不是尺寸：节点数一个不变（110.2），MAT 从 7.53 涨到 8.00。同样大小的树，边连对了就多接受半个 token。
  • SABA 单独上，MAT 反而掉了（7.53 → 7.18），树砍掉一半多（110.2 → 49.1），吞吐却涨 12.8%。这等于直接量出了固定预算的浪费程度：一半以上的节点对吞吐没有贡献。
  • 两者叠加不是简单相加（5.7% + 12.8% ≠ 19.4%，实际略超）。原因是在 SABA 砍小后的预算下，TDES 把 MAT 从 7.18 又拉回 7.62——树越小，每条边选得对不对就越关键。这是一种真实的互补：SABA 制造了让 TDES 更值钱的条件。

打分器学到的是通用偏好还是数据集捷径

论文用一个干净的实验回答：只用 GSM8K 轨迹训练打分器，去测 MBPP、SWE-bench、Alpaca 三个不同类别的任务（两个变体都开 SABA）。结果三个任务上错配都下降、归一化吞吐都提升——只训 GSM8K 的版本在 MBPP 上错配下降约 37.5%（完整版约 56%），SWE-bench 约 32.5% 对 41.5%，Alpaca 上约 30.5% 甚至超过完整版的 24.5%。说明 $f_\theta$ 学到的父子兼容度有相当的跨任务可迁移性，而不是记住了某个数据集的表面模式。

局限与在图谱里的位置

作者自己承认的

结论里点出的唯一局限是：GRAFT 每轮仍然串行执行草稿 → 建树 → 目标验证三段，由此产生的流水线气泡没有处理，留给并发投机解码的后续工作。消融里还提到一处：AIME 上的泛化证据「仍然有限」，因为 AIME 与训练数据同属数学推理类别——这也正是他们补做只训 GSM8K 那个实验的动机。

几处论文没说、但读的时候该记住的

  • 全部实验都是 batch size 1、单卡 A100。投机解码的收益随 batch 增大迅速衰减（算力开始成为瓶颈，多余的树节点不再「免费」）。SABA 的代价模型里没有 batch 项，服务化场景下需要重新拟合甚至重新建模。
  • $G_t$、$C_t$ 的参数在留出集上拟合后冻结。换硬件、换序列长度分布、换 batch 配置都可能让这组参数失配，而失配时 SABA 会静默地选错预算。
  • $E$、$m$、总参数量、$\gamma$、$w_1$、$w$ 都没给。想复现的话这几个数得自己试。
  • 没有理论保证。包括「加了 TDES 残差后是否仍保持目标分布无偏」这类问题，论文在贪心记号下讨论，未涉及采样下的分布保真度。

相邻工作

草稿模型这条轴上，无模型的一类靠 n-gram / 后缀结构（Lookahead、REST、SuffixDecoding），有模型的一类里 Medusa 给目标模型挂轻量解码头、EAGLE-3 从目标模型特征起草，DLM 草稿是最新的分支，DFlash 是其中的 SOTA。建树这条轴上，自回归 drafter 下已有一大批按置信度与成本调形状的方法（SpecInfer、OPT-Tree、TALON 按置信度在深与宽之间分预算、CAST 把 GPU 型号和 batch size 这类推理成本因素建进树结构）；而在 DLM 草稿这边此前只有 DDTree 一个。GRAFT 声称的新意就是两点：让 DLM 建树的选边变成父节点条件的，让预算变成每轮自适应的。

论文全文没有引用或讨论 Sequoia。

总结

GRAFT 解决的是一个由新硬件条件催生的具体问题：当草稿模型从「一次给一个 token」变成「一次给所有位置的边缘分布」，建树的自由度和约束都变了，而第一代方案（DDTree）只是把旧的贪心搬了过来。GRAFT 补的两块都不复杂，但都补在了要害上。

  • TDES：边缘分布天生缺少父子关系的信息，那就从目标模型的轨迹里蒸馏一个极廉价的双塔打分器补回来，以兄弟中心化的残差形式叠在对数概率上。同样大小的树，MAT 从 7.53 到 8.00。
  • SABA：固定预算既浪费又不够，那就把每轮的预算变成一个「收益/代价」比值的网格搜索。树砍掉一半以上，吞吐反涨 12.8%，并保住 oracle 的 94.1%。
  • 两者合起来相对 DDTree 吞吐 +19.4%，相对自回归 2.13×–6.36×，代价是每轮 < 0.5 ms（约验证时延的 1.4%）。
如果只带走一句话：这篇论文最有教育意义的地方不是两个方法本身，而是它两次把「看起来该优化的量」和「真正要优化的量」分开——MAT 不是目标（SABA 敢牺牲 MAT 换吞吐），错配率也不是目标（$\beta = 0.4$ 错配降最多却最慢）。中间指标做到极致往往正是性能变差的原因。
