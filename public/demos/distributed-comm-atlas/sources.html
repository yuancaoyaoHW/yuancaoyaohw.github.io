需要校准的口径

  1. 不同流不自动保证重叠。 计算和通信在同一时间区间并行，才是重叠的时间轴证据。即使并发，NCCL 与计算也可能争用 SM、HBM 或互联。max(T计算, T通信) 是理想化下界，真实过程还包括依赖、启动及末桶。
  2. Ring all-reduce 的每 rank 单向总字节是 2 × (N−1) × S/N。 RS 和 AG 各有 N−1 轮，每轮传 S/N。接收量与发送量相同；若统计收发合计，还需再乘 2。原文 2S/N 的表述没有计入所有轮次。
  3. SHARP 的 1/(N−1) 是单侧、分阶段的比值。 原文比较的是 RS 接收与 AG 发送；不能将其当成整个 all-reduce 的总流量或端到端加速比。以 N=4, S=256 MiB 为例，Ring 的每 rank 总发送和总接收各为 384 MiB。
  4. 集合通信语义不等于阻塞 CPU 或全局 barrier。 各 rank 的 collective 必须匹配，但 NCCL 操作可提交到 CUDA stream，并与其他合法操作重叠。
  5. 书中的分层概念不等于可直接填写的算法名。 CollTree 不在当前官方 NCCL_ALGO 取值表中；PAT 的可用 collective 与版本需另行核对。图中沿用原文的概念解释，同时明确这一边界。
  6. Socket 并发参数不负责打开 RDMA 多轨。 NCCL_SOCKET_NTHREADS 与 NCCL_NSOCKS_PERTHREAD 作用于 socket transport；它们的乘积不超过 64。RDMA 侧另查 NCCL_IB_HCA、rail 与实际端口计数等。
  7. monitored_barrier 只支持 Gloo。 NCCL 训练任务使用这一诊断接口时，需按一致顺序创建额外的 Gloo 进程组；不能直接在 NCCL 组上调用。
  8. PyTorch 的异步错误处理变量有自己的命名空间。 当前文档使用 TORCH_NCCL_ASYNC_ERROR_HANDLING；各取值及默认行为依版本检查，不直接照搬原文的旧简写。
  9. FSDP 分片的是参数、梯度和优化器状态。 激活内存还需重算、张量/序列等其他并行方式或专门策略处理。
  10. DDP 输入与累积需要调用方正确组织。 数据分片由 sampler / 数据流水线负责；前 k−1 个累积小批可用 no_sync() 覆盖前向与反向，第 k 个同步，并正确归一化梯度。分桶改变粒度，不直接减少总梯度字节。

上述校准属于概念澄清和工程补充，未修改已有的教学 HTML 文件。

公式示例与原文报告

  • KV 示例为每请求、分片前的估算：2 × 80 层 × 8 KV 头 × 128 头维度 × 32768 token × 2 B = 10 GiB。这里使用 KV 头数，不使用查询头数；未计入对齐、元数据与其他运行时开销。
  • 假定有效带宽 50 GB/s，只计搬运的时间约为 10 GiB / 50 GB/s = 214.7 ms。这是推导示例，不是本机或某个产品的基准结果。
  • 原文表 4-2 的 100 → 70 ms 同时涉及拓扑感知和计算通信重叠。
  • 原文的 SHARP 2–5×、KV 卸载对比重算最高 14×、Dynamo 系统最高 30× 都有具体配置和比较基线，不能外推成单项技术的固定收益。

图的阅读方式

通信原语采用“输入 → ReduceScatter → AllGather”三阶段矩阵。同色表示同一个 A / B / C / D 数据分片；中间态只高亮当前 rank 持有的结果块，右侧展示各 rank 收齐的完整结果。标量 AllReduce 与张量分片示例分开呈现。

全图统一使用深色标题、细边框与克制的配色。阅读器居中显示图形，默认宽度上限为 1180 像素，可用 ＋ / − 缩放并滚动阅读。4.6 的六张详解图继续保留逐轮数据、成本口径和支持条件。
