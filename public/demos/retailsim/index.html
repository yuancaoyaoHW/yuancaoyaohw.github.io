设计草案 v0.3（2026-10-31）· 尚未实现

模拟 A 股散户的声音、态度与决策

一个研究用沙盒：由 LLM 驱动的合成散户在点时的信息流里读新闻、逛论坛、聊群、下单，产出帖子、结构化态度和交易决策，导出给下游项目使用 §0。

声音：帖子与群聊态度：信念与情绪决策与账户不做因子

01这是什么、不做什么

先讲清三件事：模拟谁、产出什么、怎样判断模拟得像不像。读完这一节，后面每个模块在整体里的位置就清楚了。

RetailSim（仓库名 ashare-crowdsim）是一个可复现的多智能体模拟平台 §1。平台里的每个"智能体"是一个合成散户，有自己的年龄、性别、学历、职业、性格、人生与入市经历，由 LLM 扮演。它们在"点时"（point-in-time，PIT）的信息流里活动：任何数据、新闻、帖子只有到了它当年实际可见的时刻才会出现在智能体眼前，仿真时钟之前的东西一律看不到 §3.1。智能体读新闻、逛论坛、在熟人群里聊天、在模拟账户里下单。

产出分三类，各存一张主表 §1§10.3。声音是帖子、评论、群聊的自由文本，按人设与渠道标注。态度是结构化的信念、情绪、理由与政策信任，可以按人群切片，也可以聚合成恐惧 / 贪婪、政策信任、杠杆意愿、入场意愿、分歧度这类描述性的群体态度指标。决策是买、卖、持有、观望，加上仓位和理由，并且同时记下"想做什么"（意向）、"实际成交了什么"和"为什么没做成"。此外每个智能体有一个跨日连续的模拟账户，逐日记录交易流水、出入金和投资战绩，战绩会回灌到记忆里，影响之后的发言与决策 §1§8.4。几张表用 persona_id、event_id、run_id 关联，账户类表再加 sim_date。

为什么模拟散户：按 Jones et al.（2025）对上交所 2016-01 至 2019-06 共 5,340 万个散户账户的研究，散户贡献约 81% 的成交额，只持有约 22% 的市值 §2.1。散户怎么说、怎么想、怎么做，是理解 A 股的一个重要切面。为什么不直接让一个 LLM 扮演"散户"：现有研究显示，人设标签只能解释标注差异的不到 10%，LLM 只抓住个人特异方差的 3.05%，而人类自己重测为 53.6% §2.3。LLM 演出来的人群偏窄、偏理性、容易刻板化。所以本项目把差异主要从 LLM 之外注入：每人看到的信息不同，社交网络、经历、内核参数各异 §13.2。底座模型不在单次运行内混用：同一底座内全体智能体用同一个开源权重模型，跨底座比较时全体一起换，模型差异计入 V5 §6.6§14.1。

使用方式分两步 §1。先做按需的情景推演：回放某个历史事件，或者给一个假设情景，看各类散户如何反应。再在同一套人设与内核上扩展成每日持续运行，每天生成当天的帖子、态度与决策。

怎样算"像"：V1–V5

平台内置验证框架，五项判据各自独立出结论 §1§12.3。其中 V2"声音可信"是总闸门：帖子是最直接能拿真实数据对照的产出，也最容易露馅。V2 不过，帖子不对外交付，其余各项照常报告。下表的及格线是设计文档的经验设定，在 Phase 0 预注册，可依 B5（两批真实帖互相区分的噪声底线）调整一次 §12.3。

判据问的是及格线 §12.3
V1 人群可信合成人口的结构像不像真实散户主要边际 TVD ≤ 0.05
V2 声音可信帖子读起来像不像同期真实股吧 / 雪球帖人工盲评识别率 ≤ 65%，且显著低于 B1（混合效应逻辑回归 §12.1）；冻结版判别器 AUC 只要求逐版下降
V3 态度可信结构化态度的分布与方向对不对得上关键调查题 TVD ≤ 0.2，重大事件方向一致
V4 决策可信换手、处置效应等微观行为像不像硬目标矩相对误差 ≤ 50%（总量比方向与变化幅度）；软目标只要求方向与排序一致；无目标矩不设线
V5 稳定可解释结论是否不取决于种子、模型、模板校准前跨模型合并人群态度相关 ≥ 0.5，且可比率 ≥ 0.7、方向一致；同底座跨种子相关 < 0.5 时不判

TVD（总变差距离）衡量两个分布差多少，0 表示完全一致。B1 是"单个 LLM、不给人设"的基线，生成帖要比它更难被认出来才算数 §11。

不做什么 §1不生成因子，不预测价格，不对下游用途的预测力负责；不做实盘交易系统；MVP 不模拟机构，也不做闭环价格形成；模拟帖子不进入对外渠道 §16.2。完整的非目标与风险见第 06 节。

读图的顺序可以跟着一条新闻走。数据层负责"世界上发生了什么"：collect 从今天起逐日存档只能前向积累的数据（真实帖子、快讯），data 把行情、复权、成分与存档帖子整理成按时点可查的数据湖，events 把新闻、政策、公告抽成结构化的事件卡 EventCard §3.3。

模拟层负责"散户怎么反应"。population 生成人设卡；agents 跑每个智能体的认知循环，产出信念更新、帖子和决策意向；social 管发布者、论坛、群聊和推荐流，决定谁看到哪条帖子；market 按 A 股规则判定订单能否成交并算好费用，输出 Fill；accounts 只把成交与出入金记账、结算、生成快照和战绩 §3.3。产出层的 outputs 把这些整理成交付表，validation 拿交付表去和真实数据对照，给出 V1–V5 的结论。

基础层被所有模块使用。schemas 定义模块之间传递的类型，prompts 存全部提示词模板，llm 是统一的调用网关，orchestrator 管仿真时钟、谁在何时被激活、快照与分叉。

依赖方向有三条硬规定 §3.3。第一，业务模块只经 schemas 共享类型，彼此不导入对方的类型，由 orchestrator 串起来。智能体不直接访问数据，只通过感知步骤拿到信息；所有读取都经 pit.query(table, asof=clock)，由数据层强制 available_at ≤ clock §5.5。第二，market 读账户只读视图、判定成交、算费用，从不写账户；accounts 只记账，不判定成交、不算费用。这样拆是因为 market、agents（prompt 里的账户摘要）、outputs（账户类表）都要读账户，记账逻辑只能有一处。第三，LLM 响应缓存跨运行共享，放在单次运行目录之外，分叉与重放都复用它。基线 B2–B4 与消融是同一套模拟换配置运行，写在 configs/ 里，不另写代码。

事实与观点分开改写events 只产出 EventCard 与 L0（官媒转述）、L1（快讯）两类不带立场的版本，与 summary 做事实一致性校验，按量级每类 1–3 个版本 §5.3。L2–L4 都是观点，由 social 的发布者以 Post 产出；夸张度、确定性是发布者参数，与立场、动机、准确率并列 §5.6。L3 可歪曲，但必须标注所依据的 event_id；L4 传闻另立 origin="rumor" 的事件卡，带"传闻"标签，只在沙盒运行 §16.2。
注：§3.3 模块表的 events 一行仍写"按渠道改写（官媒 / 财经快讯 / 传闻）"，本站按 §5.3 画。

03五条设计原则

设计文档 §3.1 定了五条原则，后面每个模块的取舍都能追到其中一条。每条下面写它防的是什么错、具体怎么做、由哪个模块负责。

1. LLM 给意向，内核管约束

LLM 擅长读非结构化的东西：一条新闻、几条帖子、一段异动。它不擅长守规则，也不稳定地表现出可校准的行为偏差。所以每次激活最多两次 LLM 调用，帖子在成交判定之后写 §6.1。先感知注意力预算内的 K 条信息；第 1 次调用做解读与意向，只出结构化字段、不带风格示例帖：盘前与盘中输出 BeliefUpdate、DecisionIntent[]（买、卖、持有、观望，加仓位档与理由）和 FundingIntent，收盘后与晚间只输出 BeliefUpdate 加"明日打算"，不出订单 §3.4。然后内核做约束与成交判定，改动写回记忆。第 2 次调用只在 want_to_post 为真时发生，输入含当日意向与实际成交（含未执行原因），风格示例帖只放这次，正文是自由文本。反思低频，每周一次或大盈亏后触发。两次调用共用静态前缀，以命中前缀缓存。内核负责硬约束（T+1、涨跌停、资金、权限）和可校准的行为偏差修正（损失厌恶、从众等）§3.1§6.3。内核改动了意向，实际结果与没做成的原因写回记忆，之后的发言与之自洽；帖子里说的和实际成交之差记为"言行不一"，收盘后的明日打算与次日盘前实际意向之差记为"隔夜变卦"，都是可测量的产出 §6.1。LLM 也不直接给连续数字，因为数值输出校准差、易扎堆在整数；它只输出分档，分档到数值的映射由内核按人设完成，例如过度自信者映射得更极端 §6.2。意向来源做成可替换接口，可以是 LLM、规则先验或 Jev（一个只输出各选项概率的校准型分类模型）§6.6。负责模块：agents 跑循环和内核，market 判定成交。

2. 一切点时（PIT）

回放 2024 年的某一天，智能体只能看到那一天之前已经公开的东西。做法是所有数据、事件、帖子都带 available_at 字段，仿真时钟之前不可见 §3.1；事后补录的数据按保守延迟入库并打 backfilled 标记 §2.5。所有读取经 pit.query(table, asof=clock)，由数据层强制 available_at ≤ clock；泄漏测试注入未来时间戳的"金丝雀"记录并断言不可见，扫描所有 prompt 查找晚于仿真时钟的日期，并按同一运行清单重放核对结果完全一致 §5.5。LLM 参数里自带的"未来知识"另行处理：挑验收事件时优先用所有底座训练截止日之后的事件，并用记忆探针和帖子补全探针测出模型实际记得多少 §13.1。本项目不预测收益，所以这类泄漏在这里是逼真度污染：帖子带上事后视角，或者模型背过当年的帖子让 V2 虚高。负责模块：data 强制 available_at，orchestrator 推进仿真时钟，validation 跑探针。

3. 分层保真

智能体分两层 §14.1。Tier-A 50 人，完整记忆与反思，每个激活点都激活，用作大 V、典型人群代表、深度样本与审计。Tier-B 500 人，精简记忆、低频反思，事件触发加低频例行激活，填满 100 格 × 5 人的保底，是人群切片的主要来源。按事件触发激活，成本随信息量增长，不随人数增长 §3.1。第 1 次调用（全员）约 3.0k 输入、200 输出 token，第 2 次调用（仅发帖者）约 3.6k 输入、300 输出；550 人 × 2 个激活点的交易日上限约每日 7.26M 输入、0.55M 输出，全年 242 个交易日约 17.6 亿 / 1.33 亿；非交易日 20:00 激活点另计，约每日 3.63M / 0.28M §14.2。这是每人每个激活点都激活、都发帖的上限口径，按需激活后实际量低得多；N 个种子 × M 个底座要乘 N·M（Phase 1 为 6 倍）§14.2。规则或蒸馏的批量群体（Tier-C）不产出帖子，不进 MVP。负责模块：population 定名额，orchestrator 定谁何时激活。

同一底座内 Tier-A 与 Tier-B 用同一模型，分层只体现在记忆深度、反思频率与激活频率，避免把人设差异和模型大小混在一起；"2 个底座"即两个模型，跨底座比较时全体一起换。小模型延到 Phase 2 扩规模时再用，切换前在开发事件上用同一批 Tier-B 人设对比大小模型，V2 文风指标与 V5 一致性不退化才切 §14.1。

4. 声音与态度并重

帖子是一等产出，要进入测量与评估（V2）；结构化态度字段（信念、情绪、政策信任、意向）同时保留，用来按人群切片统计 §3.1。两者分开存表，用 persona_id、event_id、run_id 关联 §10。这样下游既可以读文本，也可以直接拿数字，而一张表出问题（比如 V2 不过，帖子不交付）不会连带另一张。负责模块：agents 产出，outputs 落表，validation 分别验收。

5. 可复现、可分叉

同一配置跑两次要得到同一结果，才能谈消融和基线对比。做法是事件溯源（日志只追加）、LLM 响应缓存、固定种子、锁定模型版本：任一交易日可以重放，也可以从快照分叉做反事实情景 §3.1。缓存跨运行共享，放在运行目录之外 §3.3；缓存键是模型 ID 与带日期的版本号、推理引擎版本、结构化输出后端、schema、采样参数、种子与完整消息的哈希；重放只读缓存，未命中直接报错，不静默重新调用；解析失败的尝试也写入缓存，重放时复现同一重试序列。API 模型做不到确定性输出，只能靠缓存存档，厂商的模型别名会指向新版本，所以运行清单里写带日期的版本号 §14.4。负责模块：orchestrator 管快照、分叉与运行清单，llm 管缓存。

人员与算力

人员 §15.3：研究员 1 名，负责数据、预注册、校准目标与 V1–V5 评估；人工盲评由用户及其团队完成，每个验收事件约 200 对 §11.4；平台工程师 1–2 名，负责调度、LLM 网关与数据层；可选行为金融或调查方法顾问 1 名。

算力按 token 量规划。每次激活最多两次调用：第 1 次全员，约 3.0k 输入、200 输出；第 2 次仅发帖者，约 3.6k 输入、300 输出。550 人 × 2 个激活点，交易日上限每日约 7.26M 输入、0.55M 输出，按 242 个交易日全年约 17.6 亿 / 1.33 亿；这是每人每个激活点都激活且都发帖的单次运行上限。非交易日的 20:00 激活点上限每日约 3.63M / 0.28M，全年约 4.5 亿 / 0.34 亿。N 个种子 × M 个底座再乘 N·M（Phase 1 的 3 × 2 即 6 倍），假设情景的三档价格路径再乘 3；盘中检查点、群聊接话、发布者层 L2–L4 帖子、V3 硅基调查和 Jev 单独计量，量级都小于主循环 §14.2。单价以各厂商定价页为准，设计文档不做费用估算 §15.3。

MVP 全部走国内厂商 API，不自部署；两个底座都从有开源权重的模型中选（如 Qwen、DeepSeek 系列），以后转自部署时可用同一权重做确定性重放和 LoRA 风格微调，闭源模型只作对比 §14.4。网关自写薄层，用官方 openai SDK 换 base_url，不用 LiteLLM；嵌入模型本地运行开源中文模型（如 BGE 系列），不用厂商嵌入 API §14.4。Phase 2 扩规模时 Tier-B 可换小模型或自部署，换前须通过大小模型对比 §15.3§14.1。

06非目标与风险

非目标划清项目边界；风险表说明这个设计最可能在哪里失败、靠什么发现、发现后怎么办。

不做什么

本项目只模拟散户的声音、态度和决策，不生成因子，不预测价格，也不对下游拿这些数据做出的预测力负责 §1。下游若用本项目数据做交易，合规由下游自己负责 §16.3。项目不接任何实盘交易系统，模拟账户只在仿真里记账。

MVP 不建模机构，也不做闭环价格形成：价格来自真实行情回放（模式 A）或脚本化价格路径，散户的下单不会反过来推动价格。闭环撮合（模式 B）只作远期选项，冲击模型（模式 C）放到 Phase 3 §3.5。模拟生成的帖子只在团队内部和内部下游项目之间流转，不进入任何对外渠道 §16.2。
