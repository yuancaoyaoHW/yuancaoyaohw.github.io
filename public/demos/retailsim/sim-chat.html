01群聊在系统里的位置

熟人群聊是三类渠道之一，人少、信任高、传闻走得快。

设计文档把社交层分成论坛（股吧、雪球风格）、熟人群聊、Tier-A 大V 与推荐流§3.2。熟人群聊对应微信群、QQ 群，5–50 人一群，同质性强，信任高，传闻扩散快，成员以中老年和亲友、同事圈为主§7.1。它在 Phase 1 MVP 范围内§15.1。

群的生成方式：按职业、地域、年龄做随机块模型分配，每人 0–5 个群；家庭群、同事群、"老股民群"、付费荐股群的初始信任度不同§7.2。边权就是信任度，按"跟着他赚了/亏了"更新；每 20 个交易日按信任重连，只在持续运行和长于重连周期的情景中启用，短情景网络固定§7.2，见第 05 节。群内只有智能体，不模拟不炒股的家人同事§7.1。文档没有给出四类群的初始信任数值，下图只画相对高低。

点击一个群，高亮它的成员；同一个人可以在多个群里（王阿姨同在家庭群和老股民群，小林同在同事群和付费群）。示例数据。

为什么单列一个渠道

设计文档把熟人群聊列为单独渠道：5–50 人小群，同质性强、信任高、传闻扩散快，主要人群是中老年与亲友/同事圈§7.1。这类消息不在公开论坛里留痕，不建模这一层，"转发一篇文章就跟着买"的路径就缺了（本页解读）。

它防住什么

信任按真实盈亏更新§7.2，避免"群里谁说都信"的固定权重；帖子带"传闻/喊单"分类标签 rumor_shill_tag，帖子表保留这类内容，下游可按标签过滤§16.2。

证据有多强

群聊没有可对照的真实文本，V2 只能人工盲评，记为弱证据§7.1§12.1。

03按人看：一个人在所有群里说了什么

选一个人，把这个人在四个群里的发言按时间排开，并统计帖子类型与立场变化。

同一个智能体在不同群里说话的口吻可以不同，但立场与行为应当前后一致。下面的立场曲线把每个时段的发言立场和实际动作并排画出：老马在群里说"满仓干"，实际只买了半仓；老周、小美前一晚打算买，次日盘前改为观望（隔夜变卦）。

已定（v0.3 §6.1，来自架构讨论 A6）说话与决策分两次 LLM 调用：第 1 次只出结构化的信念与意向，内核做约束与成交判定之后，第 2 次（发言）才写帖子，并且读得到自己的意向与实际成交；帖子与实际所为之差记为"言行不一"§6.1。前一晚的明日打算与次日盘前实际意向之差记为"隔夜变卦"，也是言行不一的一种§3.4。
立场 stance 随时段变化（−2 强烈看空 … +2 强烈看多）§6.2

"实际动作"一栏来自示例决策表（意向与成交），与发言并排是为了看言行是否一致。示例数据。

04群聊怎么生成：阶段内最多 M 轮

一般帖子下一阶段才可见；群聊是唯一的例外，只限该群、只走发言调用。

按 §9.1，同一阶段被激活的智能体并发运行，本阶段的帖子到下一阶段才可见§9.1。这样做的好处是结果与运行顺序无关，但群聊会变成"每人各说一句、没人接话"。所以 §9.1 留了唯一的例外：同群在阶段内顺序接话，只走发言调用，不影响当阶段交易§9.1§7.1。

已定（v0.3 §7.1、§9.1，来自架构讨论 A9）某群当阶段有 ≥ 2 个被激活成员且有人发言时，在阶段内顺序进行最多 M 轮（如 4 轮）短对话，每轮由一个已激活成员接话，顺序由种子决定。接话只走第 2 次调用（发言），不重做第 1 次调用；当阶段交易决定不受群聊影响，影响留到下一次激活，保证结果与并发顺序无关。群内只有智能体，不模拟不炒股的家人同事；群主可以是 L3 发布者；付费荐股群由 L4 喊单号当群主，按其准确率喊单，跟单亏钱写入"被荐股群坑"记忆，并按 §7.2 扣信任。群聊 token 计入 social 成本，上限由 M 与每晚活跃群数控制§7.1§14.2。

05一条传闻的来回：喊单、转发、辟谣、扣信任

付费群里的"内部消息"被转进两个群，次日晚间官方澄清，转发人的信任被扣。

传闻有两个来源：发布者层 L4 与低可信度事件卡；注入群聊或论坛后，智能体按轻信度决定是否相信、转发；之后可由官方渠道（L0）证实或辟谣（关联事件卡），用来研究"传闻—辟谣"周期§7.4。模拟传闻只存在于沙盒内，每条带"传闻"标签§16.2。

信任边权（示意数值）

点击左侧时间线的一步，看信任怎样变化。初始值与步长都是本页假设：文档只规定四类群初始信任不同§7.2，步长为人设参数、无真实数据可校准，报告中标为假设§7.2。

已定（v0.3 §7.2，来自架构讨论 A9）归因：DecisionIntent.source_post_ids 最多记 2 条影响决定的帖子§6.3，LLM 自报的归因照用不校正。更新时点：该笔持仓平仓时，或买入满 20 个交易日时按市值，用该笔收益的符号更新对所引作者的信任；群聊转来的消息同样更新对群与转发人的信任；被辟谣的传闻对转发人扣信任，不看盈亏。付费荐股群跟单亏钱写入"被荐股群坑"记忆并扣信任§7.1。重连：每 20 个交易日按信任重连，取关信任低于阈值的大 V，关注近期信息流里晒单赚钱的作者，只在持续运行和长于重连周期的情景中启用，短情景网络固定。大 V 粉丝数随战绩的变化作为描述性产出，持续运行中每 20 个交易日存一次信任网络快照§7.2§10.3。

def run_group_phase(group, activated, seed, M):
    members = [a for a in activated if a.persona_id in group.members]
    openers = [a for a in members if a.belief.want_to_post]
    if len(members) < 2 or not openers:
        return [a.speak(group) for a in openers]   # 无接话，照常下一阶段可见
    posts = [a.speak(group, turn=0) for a in openers]
    order = seeded_order(members, seed)               # 顺序由种子决定
    for turn in range(1, M + 1):
        who = order[(turn - 1) % len(order)]
        posts.append(who.speak(group, turn=turn, thread=posts))  # 只走第 2 次调用
    return posts                                       # 本阶段交易不受影响

09开放问题与待定

群聊这一块里还没定、或者没有数据可校准的地方。

验收只有弱证据熟人群聊拿不到真实聊天记录做对照，V2 只做人工盲评，记为弱证据§7.1§12.1。本页的对话是否"像"真实群聊，目前没有可量化的检验。
M 取多少设计文档只给了"如 4 轮"§7.1。M 同时决定对话深度和 token 开销；成本估算把群聊接话列为主循环之外单独计量的项§14.2，M 的取值需要按每晚活跃群数算一遍再定。
信任初值、步长与取关阈值设计文档只说四类群的初始信任度不同§7.2，具体数值没有给出；盈亏更新步长是人设参数，无真实数据可校准，标为假设；重连时的取关阈值也没有数值§7.2。本页的信任条数字是示例数据。
分群参数随机块模型按职业、地域、年龄分块，每人 0–5 个群§7.2；块内外连边概率、各类群的规模分布尚未给出。
接话顺序的细节§7.1 只规定"每轮由一个已激活成员接话，顺序由种子决定"§7.1。本页模拟器另加了"同一人不连续两轮"，这是本页的假设，是否采纳待定。
trigger=群聊 的含义§10.3 的 trigger 枚举含"群聊"§10.3，但没说明群聊接话是另记一行激活，还是附在当次激活上。本页把接话另记一行（trigger＝群聊，只走第 2 次调用），activation_id 带群与轮次；收盘后"当日交易者"必激活§3.4，在 trigger 枚举里没有对应值，本页标"（待定）"。
群帖的立场与情绪接话只走第 2 次调用，帖子表里的 stance、emotion 是取当次结构化输出，还是对接话文本另行标注，尚未说明。本页取前者。
