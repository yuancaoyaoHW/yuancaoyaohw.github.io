模块页 · data

点时数据层：只给模拟日当天已经知道的数据

data 保存行情、交易日历、复权因子、成分快照和去标识化的帖子，所有读取都经过 pit.query，只放行 available_at 不晚于模拟时钟的记录。

产物 Parquet 表 强制 available_at ≤ clock 不复权日线 + 复权因子（§5.5） 日线从 2005 年起，分钟线只补两类（§5.5）

01职责一览

一句话：data 是全系统唯一的历史数据入口，按"模拟时钟当时能知道什么"把数据交给其他模块。

模块说明写的是：data 是点时（PIT，point-in-time）数据层，管行情、交易日历、复权、指数 / 行业 / 题材成分的历史快照，以及去标识化后的真实帖子。点时的意思是：任何一次读取都带着一个时刻，只返回那个时刻之前已经公开的数据。每条记录带一个字段 available_at（这条数据最早什么时候能被看到），读取时由数据层强制 available_at ≤ clock，clock 是模拟时钟§5.5。

数据分两种来路。能一次性拉全的历史数据（行情、日历、复权、指数与行业成分）由 data 自己的导入器载入；只能逐日积累的前向存档（帖子、新闻、题材成分）由 collect 写入，data 只读§3.3。产物是 Parquet 表§3.3。和其他业务模块一样，data 只通过 schemas 的共享类型与外界交换数据，由 orchestrator 把它接到上下游§3.3。

输入

  • 历史导入器：日线、交易日历、复权因子、指数与申万行业成分快照，以及按需补的分钟线§5.5；数据源待定§5.5
  • collect：从平台上线当天起逐日存的帖子、新闻、题材成分§2.5§3.3
  • collect 已去标识化的帖子：user_id 哈希，昵称、头像、IP 属地入库即删除（属 collect 的采集规则§16.1）
→

data

  • 每条记录写 available_at，与报告期分开存§5.5
  • 存不复权日线 + 复权因子表§5.5
  • pit.query(table, asof=clock) 强制过滤§5.5
  • 按 asof 现算前复权，收益与战绩用后复权§5.5

输出

  • market：前收、涨跌停基准、除权参考价§8.4
  • accounts / population：除权时调整持仓与成本§8.4；投资史预跑用起点前的真实价格§4.4
  • events / outputs：事件卡的 assets 映射到点时的指数 / 行业 / 题材 / 个股代码§5.2，题材维度等授权题材来源落实§5.2§5.5；交付表每行标注可得时点§10.3

02为什么需要它

模拟回放的是过去，数据却是今天下载的。不加管控，智能体会读到它当时不可能知道的东西。

RetailSim 要回答的是"某个历史时点，不同散户会说什么、怎么想、怎么做"。今天拉下来的历史数据里混着大量"未来信息"：修订后的宏观数字、后来才公布的财报、事后才划入的指数成分、按今天视角重算过的复权价格。只要有一条漏进提示词，智能体的反应就带上了后见之明，整个模拟的可信度随之失效。设计文档把"一切都是点时的"列为架构原则之一§3.1。

所以设计文档要求每张表都有 available_at，并且和报告期、统计期分开存：宏观数据存首次发布值而不是修订值，财报按公告日，指数和申万行业成分用历史快照，股票池包含已退市股票以避免幸存者偏差§5.5。这些规则要在一个地方统一执行，否则每个模块各写一套过滤，迟早有一处漏掉。data 就是这个统一执行的地方。

复权是最容易出错的一类。两个反例：

反例一：存一份前复权序列

前复权是以"最新一天"为基准把历史价格往下折算。如果直接存今天算好的前复权表，回放到除权之前的某一天，智能体看到的旧价格已经被后来的分红送转折算过，等于提前知道了未来会除权。设计文档因此规定存不复权日线，前复权按 asof 当天现算§5.5。

反例二：用不复权价格算收益

除权日股价按除权参考价下调，不复权价格会出现一个跳空。用它算盈亏，一次分红送转就变成一笔大额"亏损"，智能体的战绩和情绪都会被带偏。设计文档规定收益与战绩统一用后复权计算§5.5。第 4 节的示例会把两种算法的差别算出来。

另一个原因是数据源本身不对称。有些数据可以随时回补，有些只能从某天起自己存，错过就没有了§2.5。data 需要把这两类记录区分开，并让结果可以分开比较。

03机制详解

四件事：每条记录怎样标可见时间、读取时怎样过滤、价格怎样复权、历史回溯到哪一年。最后列出还没谈定的部分。

3.1available_at：每条记录最早何时可见

available_at 记录的是"这条数据在现实中最早什么时候能被看到"，和它描述的时期是两回事。一份三季报描述的是 9 月 30 日之前，但要到公告日才可见；一个宏观数字后来可能被修订，模拟里只能用首次发布的那个值。设计文档对各类数据的口径如下§5.5：

数据available_at 口径出处
财报按公告日，不按报告期§5.5
宏观数据存首次发布值，不存修订值§5.5
指数、申万行业成分用历史快照§5.5
题材成分用授权来源（如 Tushare 同花顺概念成分或数据商）；拿不到历史快照就从某日起逐日存档，存档开始前不用题材维度§5.5§16.1
新闻平台上线当天起轮询存档，记录源时间戳与入库时间§5.5
证监会、国务院、人民银行文件用发布日，不用成文日§2.5
新闻联播文字稿19:00 播出，归入下一交易日§2.5
复权因子以除权除息日为 available_at§5.5
股票池包含已退市股票，避免幸存者偏差§5.5

表里的规则可以归成三类。第一类是"按公开时刻记"：财报、政策文件、新闻联播都有一个描述的时期（报告期、成文日、播出当天）和一个公开时刻（公告日、发布日、下一交易日），available_at 取后者，描述的时期另存一列§5.5。第二类是"只记第一次的值"：宏观数据后来会修订，修订值在当时并不存在，所以只存首发值§5.5。第三类是"会随时间变化的集合"：指数成分、申万行业成分、题材成分、股票池。对这类表，问"某天的沪深 300 有哪些股票"必须查那一天的快照，用今天的成分名单回看过去，等于提前知道哪些股票后来被调入；股票池保留已退市股票也是同一个道理，只用今天还在交易的股票，回放出来的历史行情会系统性偏好"活下来的"公司，这就是幸存者偏差§5.5。题材成分改用授权来源；若授权来源也拿不到历史快照，就只能从开始存档那天起使用，之前的区间不用题材维度§5.5。

自存档和回补数据要区别对待§2.5。自存档同时记录源时间戳和入库时间，两者取较晚的一个作为可见时间。举个例子（时刻为示例）：源上写着 9:30 发布，但系统 9:42 才抓到，那么模拟里按 9:42 算。回补的历史数据只有源时间戳，没有真实的入库时间，于是统一加一个保守延迟（文档举例"如 15 分钟"），并打上 backfilled 标记，方便比较两类数据上的结果有没有差别§2.5。

3.2pit.query：所有读取走同一个闸门

任何模块读数据都调用 pit.query(table, asof=clock)，由数据层强制 available_at ≤ clock。智能体不直接访问数据，只通过感知层拿到经过过滤的信息§5.5。下图是一次读取的路径，红色虚线是被禁止的绕行。

写成伪代码就是先扫表、再按时间过滤。真正的实现还要处理分区和缓存，文档没有规定，这里只表达规则：

# 示意，未实现
def query(table, asof, **filters):
    df = lake.scan(table, **filters)
    return df.filter(col("available_at") <= asof)

粒度方面，行情以日线为主：盘前激活看到 T−1 收盘和隔夜信息，收盘后激活看到 T 日收盘§5.5，与 MVP 的固定激活点"盘前 + 收盘后"一致§3.4。分钟线只补两类股票日§5.5：

  • 盘中事件日：量级 ≥ 3 且 available_at 落在交易时段的事件卡，会在其后最近的盘中检查点（10:00 / 11:30 / 14:00）激活接触到它的智能体。这一天只补指数与被激活者持仓的分钟线，智能体只看到检查点之前的分钟数据§3.4。拿不到分钟线的事件日，该次激活只出态度与帖子，交易意向转为"明日打算"，运行清单标"盘中无行情"§3.4。
  • 收盘封板但盘中开过板的股票日：收盘封住涨停、但盘中最低价低于涨停价（跌停对称），每日约几十只。market 用分钟线算下单后非封板时长占比，决定排队买单的成交概率；拿不到分钟线时用固定概率跑三档敏感性分析§5.5§8.2。

分钟线同样带 available_at、经 pit.query 读取；在检查点读取时，asof 就是检查点时刻。这一句是本页按 §5.5 的通用规则推出的，分钟线表的字段和可见时刻文档没有单独写。

3.3复权：存原始价，看前复权，算后复权

先解释三个词。上市公司分红、送股、转增股本时，股价在除权除息日按规则下调，这一天之前和之后的价格不能直接比较。"复权"就是把这种跳空修掉。前复权以最近一天为基准，把更早的价格按比例折算，最近的价格保持原样，设计文档认为按 asof 现算的前复权与当年券商软件的显示一致§5.5；后复权以最早一天为基准，把之后的价格往上折算，最早的价格保持原样，适合算长期收益。复权因子是每天一个累计乘数，除权日跳变一次，两种复权都由它算出。

已定（v0.3 §5.5，来自架构讨论 A1）存不复权日线（开高低收、量、额、涨跌停价、停牌标记）和复权因子表（以除权除息日为 available_at）。智能体看到的价格按 asof 当天现算前复权，与当年券商软件显示一致；收益与战绩计算统一用后复权。

这个决定的关键在"现算"。前复权的基准是"最近一天"，而模拟里的"最近一天"就是 asof。只用 available_at ≤ asof 的因子，以 asof 当天的因子为分母，算出来的就是那天的投资者在软件里看到的价格。除权日还没到，因子表里就没有这次除权，旧价格不会被提前折算。后复权的基准固定在序列第一天，不随 asof 变化，所以同一段收益无论哪天去算都相同，适合记战绩和事后统计。

# 示意，未实现。f[t] 为累计复权因子，除权除息日跳变
# 除权参考价与因子跳变：交易所通行算法，设计文档未写出这两条公式〔需复核〕
ref = (pre_close - cash) / (1 + ratio)     # cash 每股派现，ratio 每股送转
f[ex] = f[ex - 1] * pre_close / ref        # 除权日因子跳变

# 前复权：只用 available_at ≤ asof 的因子，基准是 f[asof]
qfq[t] = raw[t] * f[t] / f[asof]           # 仅对 t ≤ asof 有定义

# 后复权：基准是序列第一天的因子 f[0]
hfq[t] = raw[t] * f[t] / f[0]
ret(t1, t2) = hfq[t2] / hfq[t1] - 1

除权还牵动其他模块。设计文档规定除权除息在权益登记日的次一交易日处理（沪 4.3.1），持仓数量与成本价同步调整，涨跌幅以除权参考价为基准；停牌期间订单无效§8.4。涨跌停价 = 前收 ×（1 ± 比例），主板 10%，创业板与科创板 20%，北交所 30%，最小价位 0.01 元§8.1。这些交易规则本身归 market 管，按"生效日 → 参数集"点时存放§8.1；data 提供的是不复权价格、停牌标记和复权因子。提示词里给智能体的持仓成本采用券商式摊薄成本〔需复核〕§8.4。

3.4回溯：日线从 2005 年起

已定（v0.3 §5.5、§4.4，来自架构讨论 A1）日线从 2005 年起，覆盖股改与 2007 年牛市。2005 年以前的经历只写进人生骨架作文字背景，不在行情上预跑。

设计文档列出的关键市场时期从 2007 年牛市与 2008 年崩盘开始§6.5，2005 年起的日线可以覆盖它们。2005 年这个起点影响两处：一是人群生成时的投资史预跑，二是模拟起点前的热身期。预热期是正式测量前的 20–60 个交易日§9.2。按此推算（本页推论，文档没有写），只要正式测量起点不早于 2005 年初再加上预热长度，预热期的日线就够用。投资史预跑从每个人的 entry_year 跑到模拟起点，入市早于 2005 年的人只从 2005 年起在行情上预跑，之前的部分只作文字背景§4.4。预跑只记仓位权重、收益率和出入金占资产比例，期末再整体缩放到抽样档位§4.4。

3.5泄漏测试

闸门写好了，还要能证明没有漏。设计文档规定三项测试§5.5；技术栈一节的"可复现的工程约定"第 6 条也把点时泄漏金丝雀测试和同一运行清单的重放一致性测试列为必做测试§14.4：

  • 金丝雀记录：往表里插一条 available_at 在未来的记录，查询结果里必须看不到它。
  • 提示词日期扫描：扫描所有提示词，不允许出现晚于模拟时钟的日期。
  • 回放一致性：同一份运行清单（RunManifest，记录数据快照§9.4）重放，结果必须完全一致。这一条依赖 LLM 响应缓存；回放只读缓存，未命中就报错§14.4。

三项测试各管一条泄漏路径。金丝雀管的是闸门本身：过滤条件写错、某张表漏了 available_at、某个模块绕开 pit.query，查询结果里都会多出那条记录。日期扫描管的是闸门之外的路径：例如背景故事、预置记忆或事件改写里写进了起点之后的日期，这些文本不一定经过数据层，只能在提示词这一端查（§4.4 第 5 条也要求扫描背景故事里起点之后的日期）§4.4。重放一致性管的是"同样的输入是否得到同样的结果"：如果某处读数据时用了系统当前时间而不是模拟时钟，或数据快照被悄悄更新，重放结果就会不同§5.5§9.4。这一段对三项测试分工的解释是本页的归纳，文档只列出了测试本身。

这些测试只管数据里的未来信息。大模型参数里本身记着的"未来知识"是另一类污染，用截止表、记忆探针等办法另行处理§13.1，不在 data 的职责内。

3.6还没定的部分

设计文档写明：数据源、各表 available_at 的取值规则与存储格式待定，随数据源一起定；历史新闻源与授权题材来源同此§5.5。所以本页凡涉及表名、字段名、时刻精度（例如因子的 available_at 是除权日零点还是开盘前）的地方，都只是示意。技术栈写的是"Parquet + DuckDB + Polars；事件日志只追加；点时查询"§14.4，表怎么分、字段怎么写还没定。题材成分的方向已经定了：东财题材成分接口 robots 禁止，不采，改用授权来源§16.1；具体用哪家，与数据源一起定§5.5。

07与其他模块的关系


data 处在依赖链的底部：它不调用业务模块，别的模块读它。下面按"谁写给 data""谁从 data 读"分开列。


写给 data 的只有 collect 和历史导入器；读 data 的模块都经过 pit.query，时钟由 orchestrator 推进。共享类型放在 schemas 里§3.3。




collect
逐日存帖子、新闻、题材成分，写入 data 的前向存档；data 只读§2.5。


orchestrator
推进模拟时钟，决定每次读取的 asof；把 data 接到其他模块§3.3。


schemas
放共享类型，data 与其他模块只通过它交换数据§3.3。


agents
经感知层 perceive 拿到前复权价格和可见信息，不直接读表§5.5§6.1。


market
用前收、除权参考价算涨跌停；交易规则的点时参数集归 market§8.1§8.4。


accounts
除权日同步调整持仓数量和成本，战绩用后复权§5.5§8.4。


population
投资史预跑读起点前的真实价格§4.4；行情只回溯到 2005 年，更早的经历只写进人生骨架作文字背景，预跑按比例记账、期末缩放§4.4§5.5。


events
资产映射读指数、行业成分快照；题材维度等授权题材来源落实后再用§5.2§5.5。


outputs · validation
交付表每行标注可得时点，t 日产出只用 t 日收盘后可得的信息§10.3。金丝雀与重放一致性测试列在 §14.4 的工程约定里，文档没写归哪个模块。




想看 data 在一天里什么时候被读、读到什么，参见一个交易日；数据快照怎样写进运行清单，参见运行生命周期；智能体最终看到的价格怎样进入人设与决策，参见散户决策演示。





08开放问题


以下各项在设计文档 v0.3 里仍标为待定或需复核，本页没有替它们做决定。


数据源未定数据源、各表 available_at 的取值规则与存储格式待定，随数据源一起定；历史新闻源与授权题材来源同此§5.5。


各表 available_at 的取值规则与存储格式设计文档列为待定§5.5。例如复权因子的 available_at 落在除权日的哪个时刻、日线是收盘即可见还是另有延迟，文档都没有规定。


Tushare 新闻时间戳的含义Tushare news 有 6 年以上历史、可回补、精确到秒，但需要单独的新闻权限；时间戳是发布时间还是抓取时间、修改和删除怎样处理，尚未确认§2.5。


其他候选源的限制AKShare 新闻类接口除"财经早餐"外只给最近 20–200 条、不能回补，接口也会失效§2.5；新闻联播文字稿的社区存档有缺天，版权未核实§2.5；GDELT 2.0 自 2015-02 起、15 分钟更新，对 A 股新闻覆盖偏少〔需复核〕§2.5；Wind、Choice、CSMAR、CNRDS 等付费库需确认时间戳口径和再分发条款§2.5。


分钟线的来源与可见时间补哪两类分钟线已经定了§5.5，但分钟线从哪个源取、每根 K 线的 available_at 怎样取值，随数据源一起待定§5.5。取不到分钟线时，盘中激活只出态度与发帖、意向记为明日打算并在清单标"盘中无行情"§3.4；开板回封日按固定档位兜底§8.2。


需复核的规则日期与口径创业板涨跌幅 2020-08-24 由 10% 改为 20%〔需复核〕、印花税 2023-08-28 由 0.1% 降至 0.05%〔需复核〕§8.1；提示词中的券商式摊薄成本〔需复核〕§8.4。这些规则与口径归 market 和 accounts，回放时要按生效日取用§8.1，所以和 data 的日期口径一起列在这里。


金丝雀断言的位置文档要求未来时间戳的金丝雀记录"必须不可见"§5.5，但没写断言是检查 pit.query 的返回结果，还是检查最终提示词，或两者都查。
