模块 · validation · 验收、基线与校准

模拟出来的散户像不像真的

validation 用公开统计、调查和同期真实帖子检查合成散户的人口结构、帖子、态度与交易，五项各自下结论，帖子这一项（V2）不过，帖子就不交付。

V1–V5 验收 · V2 总闸门 基线 B1–B6 探针 · 判别器 · 校准 仅设计，未实现

01职责一览

validation 拿模拟产出和真实数据逐项对照，给出 V1–V5 五个结论和一份验收报告§3.3，并负责把行为参数校准到真实矩上§12.2。

它不参与模拟本身。编排器（orchestrator）跑完一次模拟，把帖子表、态度表、决策表、账户类表（含持仓快照与战绩表）和 RunManifest（运行清单，记录模型版本、种子、模板哈希等）落盘§9.4 §10.3；validation 读这些表，再读真实对照数据，算指标、比过线、写报告。代码里分五个子包：acceptance（验收指标与过线判断）、baselines（B1）、probes（探针）、discriminator（判别器）、calibration（校准）§3.3。判别器要深度学习框架，校准要优化库，所以各自作为可选依赖组单独安装§3.3。

02为什么需要它

LLM 写出的散户帖子读起来很顺，正因为顺，才需要一套事先定好的对照和过线，否则“看着像”会被当成“就是像”。

RetailSim 交付的是散户的声音、态度和决策§12.1。这三样东西都很容易做得“似是而非”：单个帖子语气逼真，整体却千人一脑，全是同一个立场；态度方向对了，强度和分化却比真实窄很多；交易次数看着合理，盈亏结构和资金流向却对不上。只有拿真实数据逐项比，才知道哪一层出了问题，该改哪一层。

第二个原因是大模型自带的污染。模型可能在训练时见过某次历史事件的真实帖子和后续行情，于是写出“后来证明”式的事后视角，或者直接复述背过的帖子，让 V2 的分数虚高§13.1。研究已经表明，提示“只用某日之前的信息”或者遮掉实体名都挡不住这种泄漏（Lopez-Lira、Tang & Zhu 2025）§13.1。所以 validation 要先用探针挑出干净的验收事件，再谈打分。

第三个原因是要回答“这套复杂的系统比一个 LLM 强在哪”。如果给同一个模型同样的事件卡、不给人设和社交层，它写出的帖子盲评也分不出来，那人设、内核、社交层就都白做了。基线 B1 就是这个对照，V2 要求盲评识别率显著低于 B1§11.1 §12.3。

反例：没有验收会怎样只看几条挑出来的帖子，会觉得效果很好；但如果一群智能体对同一条降准新闻给出几乎一样的看多理由，群体分歧（下文的 DR）远低于 1，这个平台其实退化成了“B1 加一点噪声”§13.2。没有诊断，这件事在交付前不会被发现。

03机制详解

先用探针挑出模型“没见过”的验收事件，再让 V1–V5 各自对照真实数据打分，基线负责回答“比一个 LLM 强在哪”，过线和止损动作都在 Phase 0 预注册，事后不改§11.4 §15.2。

几个术语。TVD（总变差距离）衡量两个分类分布差多少，取值 0 到 1，0 表示完全一样。AUC 是判别器把模拟帖和真实帖排开的能力，0.5 表示完全分不开。PGR/PLR 是处置效应的两个比率：已实现盈利占全部盈利机会的比例，与已实现亏损占全部亏损机会的比例，散户通常前者高于后者。下面的公式只是定义说明（示意，未实现）：

# 示意，未实现
TVD(p, q) = ½ · Σ_k |p_k − q_k|
PGR = 已实现盈利数 / (已实现盈利数 + 账面盈利数)
PLR = 已实现亏损数 / (已实现亏损数 + 账面亏损数)
盲评识别率 = 二选一中判对“哪条是模拟”的配对数 / 总配对数
可比率 = 跨模型相关 / 同底座跨种子相关

V2 人工盲评协议写在 §12.1，在 apps/annotate 里执行§12.1：

  • 每对是一条真实帖加一条生成帖，同吧、同事件窗口内同一时段（如 2 小时块）、同长度档（按字数分 4 档）。长度差异不靠盲评，另在文风分布指标里比。
  • 真实帖从全部可见帖里随机抽，先按规则去掉广告与推广帖并记录去除比例，同一规则也作用于生成帖。生成帖在对应格内随机抽，不人工挑；抽自哪个种子、哪个底座随机决定并记录。标注员只看去标识化的真实帖。
  • B1 帖按同样规则与真实帖配对，和主模型的配对混排、随机呈现。“显著低于 B1”在同一批标注员、同一场次内比较。
  • 标注是二选一“哪条是模拟”，加三档把握度。一个验收事件标完之前不公布对错；记录标注员 ID 与呈现顺序，约 10% 的配对重复出现，用来测前后一致性。
  • 统计用混合效应逻辑回归，标注员为随机效应，主模型 / B1 为固定效应；另报每个标注员的识别率，并检查识别率是否随呈现顺序上升。
  • 团队成员调过 prompt，熟悉生成帖的破绽，识别率会偏高。这个偏差的方向是保守的，报告里注明。

判别器分两条线，AUC 不设绝对线。冻结版每个 Phase 开始时训练一次，只用开发事件的真实帖和当时生成器的帖子，锁定权重与版本号；本 Phase 内各版生成器都用它在验收事件上打分，“逐版下降”按冻结版判定。调 prompt 时不得看冻结版对单条帖子的打分，只看汇总 AUC。重训版每版生成器各训一个，训练集与冻结版同口径，报告验收事件上的 AUC，衡量还剩多少破绽，只作诊断、不设及格线；它输出最能区分真假的特征（高权重词、句长等）供调 prompt 参考，冻结版不提供。两条线差值大，说明生成器在迎合冻结版，报告要标出。两条线都在同一份 B5 数据上算误报水平，即两批真实帖跨时段、跨吧被判为不同的比例，作为下限参照§12.1。不给 AUC 设绝对线的理由是，微调过的判别器往往能抓到人看不出的细节§12.3。V2 里有绝对线的只有人工盲评识别率。

V2 证据分强弱。论坛帖最强；熟人群聊只做盲评，算弱证据§7.1；同日写盘的前向对比最干净§13.1。发布者（信息流里只发帖、不交易的账户，见 发布者演示）的帖子进帖子表、不进入任何人群统计§10.1，也不能替代真实帖子做 V2 对照，因为它的帖子同样是模型产物（讨论第 10 条）§5.6。验收运行强制关闭真实帖子注入，开关写进 manifest，否则 V2 作废§5.7。热身期 20–60 个交易日的输出打标签，不计入 V2–V4§9.2。漏跑日按 PIT 补跑的产出标 backfilled=true，不算 V2 前向证据（补跑时当日真实帖已经存在），只作开发与校准样本，补跑日占比写进 V2 报告§9.3。

V4 的战绩部分对照 CHFS 2013 亏损账户占比 70.4%，并检验“小户跑输大户、主要输在选股”§2.1–§2.2 §12.1；2015 年复盘的大小户差距拆成择时与选股两部分，财富再分配本身只有闭环模式才能检验§12.1。

V3 硅基调查走旁路调用。从调查时点的日终快照出发，智能体带当时的人设与记忆答题；答案不写回记忆、不影响后续运行，单独缓存，写入调查表§10.3 §12.1。调用形式同第 1 次调用，不放风格示例帖，每个调查时点调一次§6.1 §12.1。题干、选项、量表照抄真实问卷原文，选项顺序随机；关键题备两种措辞，措辞差异计入 V5。真实调查样本有偏（如线上问卷偏年轻、偏活跃），公布了样本构成的就按它重新加权智能体，否则用 w_head 并注明；只问符合问卷条件的人（如“过去一年有交易”）。同一时点的调查答案还要和态度表的全体持有者口径做一致性检查，不一致比例计入 V5§12.1。

V4 目标矩分三档，预注册时为每个矩登记来源、时期、样本与档位§11.4 §12.1：

  • 硬目标：同期同市场的官方统计，包括两融余额变化、新开户数、证券交易结算资金、银证转账〔需复核〕，CHFS 亏损账户占比只对应它的调查期。总量只比方向与变化幅度的相关性，不比水平。“相对误差 ≤ 50%”只适用于这一档。
  • 软目标：其他时期或市场的文献结果，如 PGR > PLR、小户跑输、注意力驱动买入、彩票偏好、涨跌停附近行为。只要求方向与排序一致，给出模拟值与文献值区间，不算相对误差。
  • 无目标：言行不一率、涨停买不进率§8.2、隔夜变卦率等。只报告并做合理性检查，不设及格线，标“无对照”。

校准用过的矩在开发事件上拟合，V4 只在验收事件上检验，同一个矩不在同一段数据上既拟合又检验。V4 结论按硬目标是否通过来下，软目标作补充证据§12.1 §12.2。

V5 的计算单位与噪声上限。跨模型相关在合并人群上算，单位是“气质组（4）× 年龄段（5）× 事件 × 态度字段”（恐惧、政策信任、stance 等），态度取全体持有者口径；100 格的结果只作描述，不进及格线。先算同底座跨种子相关，作为可达上限，跨模型相关除以这个上限得到可比率。同底座跨种子相关本身 < 0.5 时说明噪声过大，先加种子或合并单位，不判 V5。结果分两层报告：校准前的结果作及格判定，校准后的结果只作说明。人设一致性用回归检验：换手、仓位、杠杆、发帖率等行为指标对风险厌恶、外向性、神经质等人设连续参数回归，预注册预期符号，看两个底座的符号是否都对，符号错的参数在报告里列出。跨模板（V3 的两种措辞、prompt 模板改写版）用同样的方法和可比率判定§12.1。

基线 B1–B6：每个零件的贡献怎么证明讨论第 8 条 · §11.1

基线是“去掉某个部分再跑一遍”的对照。如果去掉人设后 V2–V4 分数不变，说明人设没起作用。六个基线分三类：B1 是“只有一个 LLM”的最低对照；B2–B4 各拆掉一层，看这一层的贡献；B5 和 B6 检验评估方法本身靠不靠得住。原设计里的“真实舆情”基线已经改为 V2 的对照目标，旧的 B0 已删除（讨论第 8 条）§11.1。

基线怎么做检验什么谁来跑
B1 单 LLM 无人设同一模型、同样的事件卡，不给人设和社交层，直接写帖、答问卷、给决策V2–V4 是否胜过“一个 LLM”；V2 盲评识别率要显著低于 B1validation.baselines，只经 llm、events、prompts
B2 同质群体所有智能体用同一个人设人设异质性是否让分布更真实configs/ 换配置，编排器重跑
B3 打乱人设人设属性随机置换切片差异来自人设结构，而非噪声
B4 无社交层关掉发帖、群聊和信息流社交传播的贡献
B5 真对真上限判别器和盲评去区分两批同期真实帖子噪声下限：V2 最好能做到哪validation.discriminator
B6 事件错配事件 A 的模拟帖对照事件 B 的真实帖评估对事件敏感吗；分数应明显变差validation.acceptance

消融与基线同理，只是拆的是实现选择：换底座模型、换意向来源§6.6、把内核换成 LLM 直接出 OrderIntent、去掉少样本帖子、关掉发布者层。每个消融都比较 V2–V4 和同质化诊断§11.2。

样本量怎么定。盲评与判别器按二项检验估功效：80% 功效、双侧 α = 0.05，要检出“识别率 60% 对 50%”，每个验收事件约需 200 对，用 statsmodels 计算，盲评由用户团队完成§11.4 §15.3。二项检验只用于事先估样本量，正式分析用混合效应逻辑回归§11.4 §12.1。每个单元格约 5 人，格内几乎没有功效，所以分人群结论只在合并切片（气质组、年龄段、账户规模）上下§11.4。

同质化诊断：防止“千人一脑”§13.2

同质化是指很多智能体说着几乎一样的话、站一样的立场，平台于是退化成“B1 加噪声”§13.2。文献里的证据包括方差被压窄（Bisbee 2024）、RLHF 降低多样性（Kirk 2024）、过度准确（Aher 2023）、漫画化（CoMPosT，Cheng、Piccardi & Yang 2023；Wang、Morgenstern & Dickerson 2025）等§13.2。对策的思路是异质性主要从 LLM 之外注入：信息不同（各人看到的帖子不同）§5.4 §7、参数不同（si、γi、λi）§6.3、经历不同§6.4 §6.5。模型这一来源按 MVP 的做法处理：用两个开源权重底座，同一底座内全体智能体用同一模型，跨底座比较时全体一起换；模型差异体现为跨底座的结果差，计入 V5，不在单次运行内混用。温度只调到输出不重复为止，高温带来的是噪声，没有结构§13.2 §6.6 §14.1。仍然太窄时，才调内核映射斜率和显式噪声项，并记录调整§13.2。

已定（v0.3 §6.6 §13.2，来自架构讨论 A4）同一底座内 Tier-A 与 Tier-B 用同一模型，分层只体现在记忆深度、反思频率与激活频率，避免人设差异与模型大小混淆；“2 个底座”即两个模型§6.6 §14.1。对 validation 的影响是：单次运行内部没有模型异质，跨模型稳定性只能靠 V5 的跨底座对比来测。

样本切分、校准与防泄漏§11.3 §12.2

事件分三类，用途互不交叉§11.3。这是校准不作弊的前提：校准用的数据，验收时不能再拿来比。

开发事件

在某个底座模型截止日之前，或被探针判为泄漏。只用于跑通流程、调文风和校准。

验收事件

最好在全部截止日之后，并通过记忆和补全两种探针。它们的真实帖子不进校准目标，也不进少样本池。

前向持续运行

每天跑、当天写盘、只追加。是最终证据；之后用新模型版本重跑不算数，厂商更新记进 manifest 分段分析§13.1。

校准什么。目标是 §6.3 行为参数的群体超参数（均值、方差、对人设属性的回归系数），以及激活和社交参数§12.2。校准的对象是群体层面的参数分布，也就是“这一类人的参数大致怎么分布”，单个智能体不逐个调。参数按底座分开校准：每个底座各有一套 β、ρ、η 等的群体尺度，人设间相对关系不变；各底座的校准修正量记入运行清单，作为底座自带偏差的度量与选型参考§6.3 §9.4。V5 的跨模型相关用校准前的结果作及格判定，校准后的结果只作说明§12.1。本页的理解是：校准会把两个底座往同一组真实矩上拉，校准后的一致性说明不了底座本身稳定。

怎么算。用 MSM（模拟矩方法）：选一组真实矩（如换手率、处置效应、亏损账户占比），让模拟矩与真实矩的加权距离最小。每算一次距离都要跑一遍模拟，代价高，所以用高斯过程或树模型做代理模型，再用贝叶斯优化挑下一组参数（Lamperti、Roventini & Sani 2018）；需要参数后验分布时改用 ABC（近似贝叶斯计算）§12.2。

          • outputs：帖子表、态度表、决策表和账户类表（含持仓快照与战绩表）§10.3
          • orchestrator：RunManifest；也负责按 configs/ 重跑 B2–B4 与消融

          • events：事件卡与 event_id；抽取模型计入截止日表§5.2
          • llm 与 prompts：B1 只经这两者和 events 跑；Jev 走网关
          下游：结论落到谁
          • agents：V3 / V4 不过时改内核映射或内核§15.2；校准结果（§6.3 参数的群体超参数）由 population 产出的行为参数承接§3.3 §12.2，具体写回路径文档未定义

          08开放问题

          下面这些点设计文档没有给出数值或做法，或者依赖外部条件，实现前需要先定。

          V4 的资金流对照口径 〔需复核〕V4 硬目标里的“证券交易结算资金、银证转账”在设计文档中标了〔需复核〕§12.1：数据是否公开、按什么频率、能否拆出散户部分，都还没确认。
          V3 的月度对照来源 〔需复核〕V3 对照里的“投资者信心类月度指数”标了〔需复核：仍在发布的有哪些、口径〕§12.1。来源定下来之前，V3 的月度对照只能依赖交易所年度调查和股吧情绪。
          探针的“显著”怎么判记忆探针要“显著好于朴素基准”，补全探针要“显著高于打乱对照”§13.1，但检验方法、显著性水平和截止日“缓冲”的长度文档都没写。这些应该和过线一起写进 Phase 0 预注册。
