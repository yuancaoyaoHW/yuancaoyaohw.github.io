所有发给大模型的提示词都由这个包里的模板拼出来：静态内容在前、动态内容在后，模板按内容算哈希写进运行清单，每个用途并列 2–3 个等价模板，用来检验结论是否依赖措辞。

02为什么需要它

提示词的措辞会改变结论，也决定花多少钱、能不能复现、会不会泄露未来信息，所以要单独管。

措辞会改结果。已有研究发现，只改提示词里的格式和措辞，模型输出就会明显变化（Sclar et al. 2024）。设计文档的对策是给模板做版本、把哈希记进运行清单，并且每个用途准备 2–3 个说法不同、意思相同的等价模板，和随机种子、基座模型一起作为稳健性检验的维度。验证项 V5 要求"结论不取决于种子、模型、模板"。§13.4 §12.1

要能复现。每一行帖子、信念、成交都要能追到一份运行清单，清单里记着模板哈希。§9.4 回放时只读缓存，未命中直接报错，不会偷偷重新调用模型。§14.4 如果模板散落在各模块的代码里，改了一个字也不会在清单里留下痕迹。

要省钱。MVP 是 550 个散户、交易日 2 个激活点；每次激活最多两次调用，第 1 次全员约 3.0k 输入 token，第 2 次只有发帖者调用，约 3.6k 输入，其中 3.0k 是和第 1 次共用的前缀。按 242 个交易日算，一年交易日输入的上限约 17.6 亿 token（第 1 次约 8.0 亿，第 2 次按全员发帖上限约 9.6 亿）。§14.2 把每次都一样的内容放在最前面，同一激活的两次调用才能共用前缀，推理引擎和 API 的前缀缓存才有机会复用。§6.1 §14.3 顺序由谁定必须统一，否则一个模块把日期写在开头，整段前缀就每次都不同。

要防泄露。在提示词里写"只用某日期之前的信息"挡不住模型用训练时见过的未来知识。§13.1 能做的是控制喂进去的东西：风格示例帖只取模拟起点之前的，验收事件的真实帖子不进示例池，并且扫描每段提示词里有没有晚于模拟时钟的日期。§4.4 §5.5 模板集中在一处，这些检查才有一个统一的地方做。

反例（假想情形，用来说明问题）agents 的同事为了让帖子更口语化，直接在代码里把"请以散户身份发言"改成"你是一个老股民，随便聊聊"。跑出来的情绪分布变了，但运行清单里的模板哈希没变，没人知道两次结果为什么不同；同时他把当天日期挪到了提示词第一行，之后每次调用的前缀都不一样，前缀缓存全部失效。

03机制详解

按"越稳定越靠前"的顺序把六层内容叠起来，两次调用共用这段前缀；哪些东西不准进提示词、示例帖放在哪次调用、改模板后缓存怎么变，都在这一层规定。

3.1 六层顺序：静态在前、动态在后

设计文档规定的顺序是：规则说明 → 人设卡 → 长期信念 → 检索到的记忆 → 当日信息 → 输出 schema。§6.1 这样排的目的是让前缀缓存多命中：模型服务端会把"和上次调用开头一模一样的那一段"直接复用，开头越稳定，能复用的越长。§14.3 常见的 system / persona / memory / feed / task 五段叫法可以对上这六层，但设计文档本身没用 system、task 这两个词，下图括号里的对应只是帮助理解。

每次激活最多两次调用，帖子在成交判定之后写。§6.1 第 1 次调用（全员）做解读和意向，只出结构化字段，约 3.0k 输入 token：规则 200、人设与背景故事 600、记忆 800、信息流 1,400；输出约 200 token。第 2 次调用（只在 want_to_post = True 时）写帖子，约 3.6k 输入：与第 1 次共用的 3.0k 前缀，加当日意向与成交 100、风格示例帖 500；输出约 300 token，是自由文本。§14.2 §6.1 输出 schema 这一层的长度文档没有单列。点图中任意一层看它装什么、从哪来。

3.2 哪些东西不进提示词

人设卡里有很多字段是给内核或验证用的，大模型看不到。本页把下表概括为一条原则（概括是本页的，各条依据见出处）：模型只看到能写成文字的自我描述，涉及计算的事交给确定性代码（下称"内核"）。

3.3 风格示例帖（few-shot）的规则

few-shot 指在提示词里放几条示例，让模型照着写。本项目用它控制发帖文风：先把脱敏后的公开股吧、雪球帖子按句长、口语词、表情和黑话、情绪强度、话题偏好聚成若干文风簇，每个散户按人设绑定一个簇（字段 voice_style），提示词里放这个簇的少量示例帖（字段 voice_examples）。§4.4 示例帖只放在第 2 次调用（发帖）里，第 1 次调用只出结构化字段，不带示例帖；这样意向和信念不受文风示例牵引，帖子又能照着示例写。§6.1（后半句的理由是本页的理解，文档只写了做法。）股吧和雪球机制相同，但示例池分开。§7.1

  1. 时间：只取模拟起点之前的帖子，否则示例本身就带进了未来信息。§4.4 §13.1
  2. 脱敏：去掉用户名和可识别信息，不照抄某个具体用户。§4.4 发往境外 API 前必须先脱敏，并核对厂商的数据条款。§16.4
  3. 隔离验收：验收事件的真实帖子既不进校准目标，也不进示例池。否则 V2（文风与真实帖子对比）就成了拿考题当范文。§11.3 §12.2
  4. 只管文风：内核只矫正结构化字段，不改帖子正文；文风靠示例帖和模型选择去接近真实。§13.3
  5. 可消融：消融实验里有一项就是去掉少样本示例帖，看结果差多少。§11.2

示例帖放几条，文档只写了"少量 / 若干"，本页不给具体数字。示例帖能否算版权上的合理使用，还在等法务意见。§16.1 雪球不自行采集，雪球文风示例池只能靠授权数据。§16.1

3.4 按用途分目录，每个用途 2–3 个等价模板

prompts 模块的文档字符串列出的用途有：事件卡抽取、分渠道改写、认知循环各步、反思、预置记忆。§3.3 分渠道改写在 events 里只产出 L0、L1 两类不带立场的版本，L2–L4 的文本是观点，由 social 的发布者以 Post 产出，相应模板归发布者使用。§5.3 §5.6 认知循环里用到大模型的有三类：

  • 第 1 次调用（解读 + 意向）：全员，只出结构化字段，不带风格示例帖。盘前和盘中输出 BeliefUpdate + DecisionIntent[] + FundingIntent；收盘后和晚间输出 BeliefUpdate + 明日打算（买 / 卖 / 持有 / 观望 + 标的），写入记忆、不出订单。意向来源换成规则先验或 Jev 时，这次调用只剩解读。§6.1 §6.6
  • 第 2 次调用（发帖）：只在 want_to_post = True 时调用，输入加上当日意向与实际成交（含未执行原因），风格示例帖只放在这次，正文是自由文本、不进 JSON。群聊接话只走这一次调用，不重做第 1 次。§6.1 §7.1
  • 反思：低频，每周一次（Tier-A 放在周末激活点）或大盈亏后触发，产出记忆。§6.1

感知（perceive）和约束与成交（constrain + fill）由内核代码完成，不用模板。§6.1 帖子与实际所为之差就是"言行不一"；收盘后的明日打算与次日盘前实际意向之差叫"隔夜变卦"。两者都要能测，所以第 2 次调用必须看到真实成交，晚间的第 1 次调用必须把明日打算写进记忆。§6.1 §3.4

模板里还有随时段变化的任务说明：长假前最后一个交易日的盘前 prompt 写明"明天起休市 N 天"；非交易日只有 20:00 晚间激活点，调用同收盘后激活，不出订单。§3.4 V3 硅基调查是旁路调用：从调查时点的日终快照出发，形式同第 1 次调用，不放风格示例帖，每个调查时点一次，单独缓存，答案不写回记忆。§12.1

"等价模板"是同一用途下说法不同、要求相同的 2–3 份模板。一次实验固定用其中一份，换一份重跑，看结论变不变；它和种子、基座模型并列，是 V5 稳健性检验的三个维度之一。§13.4 §12.1 目录名、文件格式文档都没有规定。

3.5 模板版本和缓存键是什么关系

两件事要分开看。模板哈希由加载器按模板内容算出，写进运行清单，用来回答"这次实验用的是哪一版模板"。§9.4 缓存键由 llm 网关算，决定一次调用能不能直接拿缓存里的旧回答：

cache_key = hash(模型 ID 与带日期的版本号, 推理引擎版本, 结构化输出后端,
                 schema, 采样参数, 种子, 完整 messages)   // §14.4 第 1 条

模板本身不单独进缓存键。改了模板，拼出来的完整 messages 就变了，缓存键随之变化，旧回答自然不再命中。所以改一个字有两个后果：清单里的模板哈希变了（可追溯），缓存全部未命中（要重新花钱调用）。反过来，回放旧实验时只读缓存，未命中就报错，不会悄悄用新模板重跑。§14.4 解析失败的那几次尝试也写入缓存，重试用的新种子在缓存键里，所以回放能复现同样的重试序列。§6.2 §14.4 同一次激活的两次调用共用静态前缀，第 2 次调用的前缀部分可以命中第 1 次调用留下的前缀缓存。§14.3

同理，模型要用带日期的版本号，结构化输出后端也要锁版本，因为换后端本身就会改变输出。§14.4 schema 尽量扁平：一份厂商实测（8B 模型）里嵌套 schema 的额外开销在 vLLM 上是 +42%、SGLang 上 +6%，扁平的只有 +6% / +2%。§14.4

3.6 规则说明层写什么

规则说明如实告诉模型：这是研究用的模拟，输出不会发布，请按人设表达真实情绪；不用越狱提示词，遵守各厂商的使用政策。§13.3 §16 内容尺度放开，但不许威胁、人肉或捏造对具名真人的指控。§16.2 拒答率、无效输出率、免责声明率和说教率按模型、按事件类别监控。§13.3

3.7 生成环节的防泄露：模板管住"让模型写什么"

前视泄露在本项目里主要表现为逼真度污染：历史推演的帖子带上当时散户不可能知道的结局，或者模型背过当年的帖子，让 V2 虚高。§13.1 除了散户每天的提示词，生成人设和记忆的那几类模板也会把未来信息带进来，设计文档对它们分别做了规定：

  1. 预置记忆：事实填模板，模型只润色。预置记忆的事实部分（哪段行情里多大仓位、加没加杠杆、亏了多少）由经历向量填进模板，大模型只改语气，生成后扫描有没有起点之后的日期与事件。这样模型没有机会"顺手"补上它从训练数据里知道的后续走势。§13.1 §6.5 §6.4
  2. 背景故事：只改写、不新增事实。背景故事是 200–300 字的第一人称叙述，由大模型把人生骨架里的事实改写而成，不得新增事实、日期和数字；生成后与人设卡逐项比对（年龄、职业、入市年份、盈亏方向），并扫描起点之后的日期与事件，不一致就重写。§4.4
  3. 反思：不得出现模拟时钟之后的日期。反思模板读的是模拟自己的经历，产出语义记忆；反思 prompt 里出现晚于模拟时钟的日期即违规。§6.4
  4. 事件卡抽取：抽取模型也算进截止日表。抽取模型给量级时可能受"已知结局"影响，所以它和散户用的底座一样要查训练截止日。§13.1 §5.2 抽取 prompt 还要遮去专有的时期叫法（如"9·24"），只按文本写明的政策力度、发布机构级别、是否超预期打分；历史验收事件的量级由团队人工标定，LLM 打分只作参考。§5.2
  5. 统一扫描。数据层的泄漏测试里有一条是扫描所有 prompt，查找晚于仿真时钟的日期；模板集中在本模块，扫描才能覆盖全部用途。§5.5

这些规则都放在"喂进去什么"上，因为在提示词里写"只用某日之前的信息"已被证明挡不住泄露（见 3.2 表）。§13.1
