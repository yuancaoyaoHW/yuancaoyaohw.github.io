流程 · 信息到成交

一条新闻的旅程

跟着一条示例快讯，看它怎样变成事件卡、被发布者转述、进入某位模拟散户的信息流，最后变成一条帖子、一次下单和几行数据表记录。

示例数据，化名eventssocialagents · market · accounts

01总览：十一站

一条快讯从进入系统到落进数据表，要经过十一站，分属 collect、events、social、agents、market、accounts、outputs 七个业务模块。点击图中任一站，下方显示这一站做什么。

整条路可以分成四段。第一段是信息段：原始快讯被聚类成事件，抽成一张结构化的事件卡（EventCard），再改写出不带立场的官媒转述（L0）和快讯（L1）版本，这一段归 events 模块 §5.2 §5.3。第二段是传播段：发布者层的大 V、博主、喊单号（L2–L4）读事件卡与 L0/L1 版本后以 Post 发帖，这些帖子、L0/L1 版本和其他模拟散户的帖子一起进入推荐流，按每个人的注意力预算挑出少数几条，这一段归 social 模块 §5.3 §5.6 §7.3。第三段是决策段：每次激活最多两次 LLM 调用。第 1 次调用读完信息流，一次给出信念更新和买卖意向；规则内核把意向换算成订单，market 判定能否成交，accounts 记账；成交判定之后，想发帖的人才走第 2 次调用写帖子 §6.1 §8。第四段是落表：帖子、态度、决策、成交分别写进不同的表，以 persona_id、event_id、run_id 关联 §10.3。

贯穿全程的约束有两条。一是时点正确（PIT，point-in-time）：每条数据带"最早何时公开可得"的时间戳 available_at，任何读取都只能拿到 available_at ≤ 当前模拟时钟 的记录 §3.1 §5.5。二是分工固定：LLM 只给意向，硬约束和行为偏差修正由内核负责，内核改了什么都写回智能体记忆 §3.1。

02分步演示：一条示例快讯

用一条化名快讯和一位化名散户"老周"，逐站看对象怎样生成、怎样变化。每一步都列出输入、处理、输出和对应的设计文档条目。

示例设定如下，全部为示例数据，公司、人物、价格均为虚构：T−1 日晚间，一条快讯说"某部委印发储能产业支持措施"，点名的上市公司用化名"星河储能"（主板，T−1 收盘价 20.00 元）。老周是一位 Tier-B 智能体，55 岁，关注储能板块但没有持仓。Tier-B 是 500 人的普通散户样本；Tier-A 共 50 人，拆为大 V 20 人与深度样本 30 人，两层用同一模型，只差记忆深度、反思频率与激活频率 §4.3 §14.1。T 日盘前他被激活，读到了这条消息。

到第 9 步"成交"时，可以切换两种行情分支：A 是盘中触及涨停后回落、能成交；B 是全天一字涨停、买不到。两种分支下老周的意向相同，成交不同；帖子在成交判定之后才写，所以帖子内容和落表也跟着不同。意向与实际成交之差就是设计文档要测量的"言行不一" §3.1 §6.1 §6.3。

行情分支：

01 快讯进入系统

T−1 日 20:10（示例时间），一条快讯被采集入库。

输入

东财 7x24 快讯条目（示例数据，化名）【某部委印发储能产业支持措施】措施提出加快新型储能项目建设，完善储能参与电力市场的价格机制。相关公司：星河储能。
  • 条目含发布时间、标题、正文、关联股票（示意，字段名以接口为准）。

处理

  • collect 模块按游标翻页抓取 §16.1；自建存档同时保存源时间戳与入库时间，以二者较晚者为可见时间 §2.5 §5.5。
  • events 把同一件事的多条原始报道按嵌入相似度加时间窗聚类去重，后面只对整簇做一次抽取 §5.2。
  • 记下最早公开可得时间 available_at。夜间发布的条目进入下一个激活点（T 日盘前）的候选池 §5.2 §3.4。

输出

  • 一簇原始条目，available_at = T−1 20:10（示例）。
  • 老周这晚没被激活：晚间只激活被事件触发的时政敏感者和群聊活跃者，老周两者都不是（示例设定），所以最早在 T 日盘前看到 §3.4。

对应文档条目

  • §5.1 信息来源；§5.2 聚类与去重；§5.5 时点约束
  • §16.1 自采范围：东财 7x24 快讯接口可采（2026-10-30 实测）

02 抽取事件卡 EventCard

一簇条目调用一次 LLM，抽成结构化的事件卡。

输入

  • 上一步的条目簇。
  • 抽取 prompt：遮去专有时间叫法（如"9·24"），只依据文本写明的政策力度、发布机构级别、是否超预期打分 §5.2。

处理

  • 每簇 1 次 LLM 调用，成本随事件数增长，不随智能体数增长 §5.2。
  • 量级按 §5.2 量级表打分：部委级行业支持措施落在 3 档"板块级"（示例判断）。
  • 量级只看事前文本，不按事后涨跌回填，否则未来收益会漏进激活模式 §5.2。
  • 抽取模型与 prompt 版本锁定，结果缓存，人工定期抽检量级与资产映射 §5.2。

输出（示意，未实现；示例数据）

{
  "event_id": "ev_demo_001",
  "origin": "real",
  "available_at": "T-1 20:10",
  "source_tier": "mainstream",
  "category": "industry_policy",
  "scope": "sector",
  "assets": ["储能板块", "星河储能"],
  "magnitude": 3,
  "direction_hint": 1,  // 不给智能体看
  "credibility": 1.0,
  "summary": "某部委印发储能产业支持措施，涉及项目建设与电价机制。"
}

对应文档条目

  • §5.2 EventCard 字段与量级表
  • §5.2 量级防记忆污染：V2 历史验收事件由团队人工标定，LLM 打分只作参考

03 改写出 L0 / L1 版本

events 把事件卡改写成"官媒转述"和"快讯"两类不带立场的文本。

输入

  • 事件卡及其 summary（200 字以内的中性摘要，是所有改写的底稿 §5.2）。

处理

  • 每个"事件 × 渠道"改写 1–3 个版本，量级越高版本越多 §5.3。
  • 可以省略细节，不得编造事实，也不带立场；与 summary 做事实一致性校验，不一致的丢弃重写 §5.3。
  • L0 延迟 0，L1 延迟 0–10 分钟 §5.3。

输出（示例数据）

L0 官媒转述某部委日前印发储能产业支持措施，提出加快新型储能项目建设、完善价格机制。
L1 快讯【部委发文支持储能】新型储能项目建设提速，储能参与电力市场价格机制将完善。

对应文档条目

  • §5.3 分渠道改写表（L0、L1 两行，产出方 events）
  • §5.3 改写按事实与观点分开：events 只出 EventCard 与 L0/L1

04 发布者 L2–L4 发帖

发布者只发帖、不交易。各级按自己的立场、动机、夸张度出帖。详细机制见 发布者演示页。

输入

  • 事件卡与 L0/L1 版本 §5.6。
  • 每个发布者的参数：立场、动机、准确率、夸张度、确定性。夸张度与确定性是发布者参数，不是改写参数 §5.3 §5.6。

处理

  • social 的发布者以 Post 产出 L2–L4 文本，这些都是观点 §5.3。
  • L2 大 V 延迟"随传播"，标注依据的 event_id；L3 中小博主延迟数小时，可以歪曲、不做事实校验，但须标注 event_id §5.3。
  • L4 喊单号延迟不定，传闻另立一张 origin="rumor" 的事件卡，帖子带"传闻"标签，只在沙盒运行 §5.3 §16.2。
  • L2–L4 的成本归入 social 估算 §5.3 §14.2。

输出：3 条 Post（示例数据，化名）

L2 大V"老K看盘" · event_id=ev_demo_001储能这份文件力度不小，但项目落地要时间，短线别追，等回踩。
L3 博主"短线小飞侠" · event_id=ev_demo_001储能要起飞了！部委亲自下场，龙头明天怕是买不到！
L4（仅沙盒）· 传闻听说星河储能还有大单没公告，懂的都懂。

对应文档条目

  • §5.3 分渠道改写表（L2–L4 三行，产出方 social）
  • §5.6 发布者层：读事件卡与 L0/L1 后发帖，不交易；§7.4 帖子类型与传闻

05 推荐流挑出老周看到的几条

T 日盘前，老周被激活；推荐流排序，再按他的注意力预算抽出少数几条。

输入

  • 候选池：L0/L1 版本、发布者帖、其他模拟散户在上一阶段发的帖、行情，只用 available_at ≤ 09:15 的信息 §3.4 §5.4 §9.1。
  • 老周的媒体习惯、关注板块、持仓 §5.4。
  • 真实帖子注入开关默认关闭，验收运行强制关闭 §5.7。

处理

  • 激活：老周的媒介接触到量级 3 的事件，触发方式记为"事件" §9.1。盘前是当日唯一产生例行订单的激活点 §3.4。
  • 推荐流打分：时近性 × 热度 × 兴趣相似度 × 关注关系，热榜放大头部 §7.3。
  • 个人注意力打分：渠道权重 × 量级 × 资产相关度 × 时间衰减 × 显著性 §5.4。
  • 持仓异动必进，其余按 softmax 不放回抽取，K 在 3–15 条之间，约 1,500 token §5.4。

输出：老周的信息流（示例数据，K=4）

  • L1 快讯：部委发文支持储能
  • L3"短线小飞侠"：储能要起飞了
  • 模拟散户帖："昨天已上车储能，拿着"
  • 行情：星河储能 T−1 收 20.00 元

没被抽中的 L2 解读，之后仍可能经群聊或转发再次进入 §5.4。

对应文档条目

  • §5.4 注意力预算；§7.3 推荐流；§5.7 注入开关
  • §9.1 激活：媒介接触到量级 ≥ 3 的事件可触发激活；§3.4 盘前激活点

06 老周更新信念 BeliefUpdate（第 1 次调用）

第 1 次 LLM 调用读信息流、持仓和记忆，同时给出信念更新和决策意向。本步先看信念部分。

输入

  • prompt 按"规则 → 人设卡 → 长期信念 → 记忆 → 当日信息 → schema"从静态到动态排列，便于前缀缓存 §6.1。
  • 记忆约 800 token，其中账户摘要约 100 token §6.4。

处理

  • 第 1 次调用 interpret + intend，只出结构化字段，不带风格示例帖；盘前出 BeliefUpdate + DecisionIntent[] + FundingIntent §6.1。
  • LLM 只给档位，不给连续数值；档位到数值的映射由内核按人设做 §6.2。
  • Pydantic 校验不过则换种子重试，最多 2 次；仍失败则记为未激活、原因"解析失败"，不填默认值，写进激活表 §6.2 §9.1。

输出（示意，未实现；示例数据）

{
  "views": [{
    "asset": "星河储能", "horizon": "1w",
    "stance": 1, "ret_bucket": "2~5%",
    "confidence": 3,
    "reasons": ["policy", "kol", "herd"]
  }],
  "emotion": {"fear": 0, "greed": 2, "regret": 0, "fomo": 2},
  "policy_trust": 1,
  "want_to_post": true,
  "monologue": "部委发文，板块要动，怕又踏空。"
}

对应文档条目

  • §6.1 第 1 次调用 interpret + intend
  • §6.2 AssetView、BeliefUpdate 字段；ReasonTag 取值；解析失败与拒答

07 给出决策意向 DecisionIntent（同一次调用）

同一次调用里的意向部分只给"想怎么做"：动作、仓位档、执行方式、理由。不含价格和股数。不同类型散户在同一条消息下的差别见 人设决策演示页。

输入

  • 同一 prompt；记忆里的账户摘要（总资产、可用资金、仓位、各持仓浮盈亏） §6.4。

处理

  • 执行方式三选一：open 开盘就买卖、dip 挂单等回调、chase 盘中追；盘中激活只能选 chase §6.3。
  • 意向来源是可替换接口：LLM（MVP 默认）、规则先验、Jev；换成后两者时第 1 次调用只剩解读 §6.1 §6.6。
  • 出入金意向 FundingIntent 在同一次调用里给出，本例为 none §6.1 §6.3。

输出（示意，未实现；示例数据）

{
  "asset": "星河储能",
  "action": "buy",
  "size": "small",
  "execution": "open",
  "reasons": ["policy", "herd"],
  "source_post_ids": ["post_demo_l3"],
  "rationale": "部委文件力度够，开盘小仓位试试。"
}

对应文档条目

  • §6.3 DecisionIntent 字段（含 execution、source_post_ids）、FundingIntent
  • §6.6 意向来源

08 内核把意向换成订单 OrderIntent

规则内核做可校准的偏差修正和硬约束检查，再按执行方式定价。改动写回记忆。

输入

  • DecisionIntent、人设参数（风险厌恶、损失厌恶、从众系数等）、情绪档 §6.3；账户只读视图（字段文档未逐项定义） §3.3。
  • 老周看到的可见买卖行为：信息流里有 1 条"已上车"，所以净买入占比为正（示例） §6.3 §7.5。

处理

  • 仓位档 small → 意向权重；加上从众、外推、彩票偏好修正，再按风险厌恶缩放、截断 §6.3 第 1–2 步。
  • 情绪分支：只有贪婪或 FOMO 处于最高档（3）时才临时放大从众与彩票系数；本例 greed=2、fomo=2（示例），不放大 §6.2 §6.3 第 5 步。
  • 硬约束：现金、T+1、整手、涨跌停可成交性、交易权限、费用 §6.3 第 6 步。§8.1 的权限表只对创业板、科创板、北交所与两融设门槛，本例是主板股票 §8.1。
  • 定价：LLM 只选执行方式，不报价格。open 的买入限价取涨停价，即按开盘价成交；订单当日有效，未成交的收盘撤单 §6.3 第 6 步。

输出（示意，未实现；示例数据；字段名为假设）

{
  "asset": "星河储能", "side": "buy",
  "qty": 300,
  "execution": "open", "limit": 22.00,
  "decision_ref": "dec_demo_001"
}

v0.3 没有定义 OrderIntent 的字段 §6.3 第 6 步；上面的字段名借用交易流水表的 side、qty、decision_ref 和决策表的 execution §10.3，是示意。主板涨跌幅 10% §8.1，T−1 收 20.00 元，涨停价 22.00 元，所以 open 买单的限价是 22.00 元；集合竞价无价格笼子 §6.3 第 6 步。订单在 09:15–09:25 集合竞价时段提交 §3.4。

对应文档条目

  • §6.3 内核第 1–7 步与执行方式定价；§8.1 规则
  • §3.1 原则 1：LLM 给意向、内核管约束

09 market 判定成交，accounts 记账

模式 A 回放真实行情，智能体是价格接受者，不影响价格。用上方按钮切换行情分支。

输入

  • OrderIntent；账户只读视图 §3.3。
  • T 日行情（分支 A，示例数据）：开 21.60、高 22.00、低 21.20、收 21.80，盘中触及涨停后回落。
  • T 日行情（分支 B，示例数据）：开高低收都是 22.00，一字涨停。

处理

  • 检查顺序：交易时段 → 权限 → T+1 可卖数量 → 整手与单笔上限 → 涨跌幅与价格笼子 → 风险警示股买入上限 → 资金与两融额度。不合规直接拒绝并计数，不自动修正 §8.1。
  • 第 1 步：集合竞价单按真实开盘价成交，买入限价不低于开盘价才成交；execution = open 走这一步 §8.2。
  • 第 3 步：一字涨停（最高价 = 最低价 = 涨停价）时买单不成交 §8.2。
  • 第 4 步：个人成交不按 w_cap 放大后的量缩减；只有自身订单超过该股当日真实成交额的设定比例（如 1%）时，超出部分不成交 §8.2。
  • 费用逐笔扣除：佣金上限 0.3%，常见万一至万三、单笔最低 5 元；经手费 0.00341%、证管费 0.002%、过户费 0.001%，均双向；印花税 0.05% 只向卖方收 §8.1〔需复核〕 §8.4。

输出（示例数据）

Fill · 分支 A限价 22.00 ≥ 开盘价 21.60，买入 300 股 @ 21.60，成交额 6,480 元。佣金 max(6,480 × 佣金率, 5)，万三以下都按最低 5.00 元；经手费、证管费、过户费合计约 0.42 元；印花税 0（买入）。费率〔需复核〕，计算为示例。
  • accounts 记账：持仓总数 +300，可卖数量当日不变，次日开盘前转为可卖 §8.4。
未成交 · 分支 B一字涨停，买单按第 3 步不成交，收盘撤单。
  • 没有 Fill，账户不变；"涨停买不进"写回老周的记忆 §6.3 第 7 步。

开盘价 22.00 等于限价，第 1 步的条件本身满足；本页按第 3 步处理一字板，v0.3 没有写明两步的先后。

对应文档条目

  • §8.1 检查顺序与费用；§8.2 模式 A 第 1–4 步；§8.4 T+1 与可用资金
  • §3.3 market 不写账户，accounts 不判成交

10 老周发一条帖子（第 2 次调用）

want_to_post 为真，成交判定之后才发第 2 次调用，写自由文本，并附结构化元数据。用上方按钮切换行情分支。

输入

  • 当日意向与实际成交（含未执行原因） §6.1。
  • 人设绑定的说话风格与少量风格示例帖，示例帖只放这次调用；静态前缀与第 1 次相同，可命中前缀缓存 §6.1 §7.4 §14.3。
  • 渠道：公开论坛（股吧风格） §7.1。

处理

  • 第 2 次调用 post 只对 want_to_post = True 的智能体发送；正文为自由文本，不进 JSON §6.1。
  • 帖子带标的、立场、情绪、类型、传闻/喊单标签和"模拟生成"标记 §7.4 §16.2。

03每站详细说明：信息段与传播段

前五站决定"谁在什么时候看到什么"。这里逐站讲为什么这样设计、怎样计算、由哪个模块负责。

第 1–2 站：从快讯到事件卡

原始新闻量很大，同一件事常被几十家媒体重复报道。如果让每个智能体直接读原文，成本会随智能体数增长，而且不同人读到的措辞差异会混进实验。events 模块先按嵌入相似度加时间窗把条目聚类去重，每簇只调用一次 LLM 抽成事件卡，所以成本随事件数增长 §5.2。新闻是自建存档：东财 7x24 快讯接口可采，按游标翻页；历史新闻源待定，随数据源一起定 §5.5 §16.1。

事件卡里有两个字段最容易被误用。第一个是 available_at，它记的是最早公开可得的时间，不是事件发生时间；夜间和周末的事件放进下一个激活点的候选池 §5.2。第二个是 direction_hint（方向提示，−1/0/1），只用于路由和监控，绝不给智能体看。原因是一旦智能体看到"利好"标签，所有人都会朝同一方向反应，群体会接近基线 B1（单个 LLM、无人设）的表现 §5.2 §11.1。

量级 magnitude（1–5）影响谁会被激活：媒介接触到量级 ≥ 3 的事件是激活触发条件之一 §9.1。量级只依据事前文本判断，不按事后涨跌回填，否则"涨得多的事件量级高、量级高的事件激活人多"会把未来收益漏进激活模式 §5.2。

已定（v0.3 §5.2，来自架构讨论 A3）量级防记忆污染：抽取 prompt 遮去专有时间叫法（如"9·24"），只依据文本写明的政策力度、发布机构级别、是否超预期打分。V2 历史验收事件的量级由团队按 §5.2 量级表人工标定，LLM 打分只作参考；在模型截止日之后的事件上比较 LLM 与人工打分的一致性，记入运行清单。开发事件与持续运行只做遮蔽与一致性检查。

第 3–4 站：事实版本与观点帖

同一件事在不同渠道的说法差别很大：官媒只转述，快讯简短带数字，博主会夸张，喊单号会编"内部消息"。模拟要重现这种差别，又不能让改写过程凭空造出事实。v0.3 按事实与观点分开：events 以 summary 为底稿生成 L0、L1 两类版本，可以省略细节，不得编造事实，也不带立场，并与 summary 做一致性校验；L2–L4 的文本都是观点，由 social 的发布者产出 §5.3。

events：EventCard 与 L0/L1

L0 官方媒体延迟 0，L1 财经快讯与券商观点摘要延迟 0–10 分钟。每个"事件 × 渠道"改写 1–3 个版本，量级越高版本越多，避免所有人读到同一段文字。不一致的版本丢弃重写 §5.3。

social：L2–L4 发布者 Post

发布者读事件卡与 L0/L1 后以 Post 发帖。L2 大 V 延迟"随传播"，L3 中小博主延迟数小时、可以歪曲，两者都须标注依据的 event_id；L4 传闻另立 origin="rumor" 的事件卡，只在沙盒运行。夸张度、确定性是发布者参数，成本归入 social 估算 §5.3 §5.6 §14.2。

已定（v0.3 §5.3，来自架构讨论 A3）改写按事实与观点分开：events 只出 EventCard 与 L0、L1 两类不带立场的版本；观点和歪曲全部归 social 的发布者。v0.3 §3.3 的模块表仍写 events "按渠道改写（官媒 / 财经快讯 / 传闻）"，与 §5.3 不一致，见第 08 节。

发布者的级别、延迟、参数和"插入一条传闻"的干预效果，在 发布者演示页 有完整演示，本页不重复。这里只记一点：发布者只发帖、不交易，帖子进帖子表但不进入任何人群统计 §5.6 §10.1；会交易的大 V 是 Tier-A 散户，照常进统计、照常测言行不一 §5.6。

第 5 站：推荐流与注意力预算

真实散户每天能读的东西有限，读到什么很大程度由平台推荐和个人习惯决定。这一站分两层计算。第一层是平台侧的推荐流（参照 OASIS 的做法）：按时近性、热度（赞、转、评）、兴趣相似度、关注关系打分，热榜放大头部内容，这些参数本身是实验变量 §7.3。第二层是个人侧的注意力预算，对每条候选算一个分数 §5.4：

score = w_i(渠道) · m(量级) · rel_i(资产) · exp(−Δt / τ_d) · sal

其中 w_i 是此人的媒体习惯，比如中老年偏官媒与群聊、年轻人偏论坛与自媒体、专业背景偏快讯与雪球；rel_i 是与持仓、自选、关注板块的重合度；Δt 是发布后经过的时间，τ_d 是衰减常数；sal 是显著性，例如涨跌停、上热榜、大 V 转发 §5.4。持仓股的异动（单日涨跌超过个人阈值、涨跌停）必进；其余按 softmax(score / T_i) 不放回抽取，每人 K 条，K 在 3–15 之间，信息流预算约 1,500 token §5.4。

没被抽中的消息并没有消失，之后可能经群聊或大 V 转发再次进入，这就产生了扩散延迟和反应不足或过度。设计文档引 Hirshleifer, Lim & Teoh 2009 说明注意力竞争：同一时段候选越多，每条被看到的概率越低；并补充节后首个交易日积压的信息尤其如此 §5.4。抽取用 softmax 而不是直接取分数最高的 K 条，所以同样人设的两个人也可能读到不同的信息流。设计文档没有给出 τ_d、T_i、w_i 和推荐流各项权重的取值，本页不写数字。

推荐流里还有两条边界。真实股吧帖子默认不进智能体的信息流，只留接口和开关，验收运行强制关闭并记入运行清单，否则 V2 对照会失效 §5.7。所有读取都经过 pit.query(table, asof=clock)，强制 available_at ≤ clock §5.5。

04每站详细说明：决策段

第 6–10 站把"读到了什么"变成"想做什么、实际做成了什么、说了什么"。LLM 负责想和说，内核和 market 负责做成了什么。

第 6–7 站：信念与意向（第 1 次调用）

每次激活最多两次 LLM 调用，帖子在成交判定之后写，都由 agents 模块驱动 §6.1：

perceive(feed, portfolio, prices)        # K 条（§5.4）
  → 第 1 次调用：interpret + intend      # 只出结构化字段，不带风格示例帖
      盘前 / 盘中：BeliefUpdate + DecisionIntent[] + FundingIntent
      收盘后 / 晚间：BeliefUpdate + 明日打算，不出订单（§3.4）
  → constrain + fill (kernel) → 实际成交  # 硬约束 + 偏差修正 + 成交判定；改动写回记忆
  → 第 2 次调用：post，仅 want_to_post = True → Post
                                         # 输入含当日意向与实际成交；风格示例帖只放这次
  → reflect (LLM, 低频) → Memory          # 每周一次（Tier-A 放在周末激活点）或大盈亏后

LLM 只输出档位，不输出连续数值。信念和意向都用离散档：收益预期分六档，仓位分 tiny/small/half/large/all_in 五档，情绪四项各 0–3 档 §6.2 §6.3。档位到具体数值（比如仓位档到意向权重）的映射由内核按人设完成 §6.2 §6.3。行为参数挂在大五人格的连续分数上，不进 prompt，LLM 不知道自己的损失厌恶系数是多少 §4.1 §4.2。意向里还有执行方式 open / dip / chase，LLM 只选方式，不报数字价格 §6.3。

帖子放在成交之后写，是为了让发言与实际经历自洽：第 2 次调用的输入里有当日意向和实际成交（含未执行原因），老周没买到就不会说自己已经持有 §6.1。声音和决策仍是两种并列的产出，存在不同的表里 §3.1。帖子与实际所为之差记为"言行不一"；收盘后的明日打算与次日盘前实际意向之差记为"隔夜变卦" §6.1 §3.4。

同一条消息在不同人设下会走出很不一样的路径：风险厌恶、损失厌恶、从众系数、神经质高低都会改变内核的修正量。这部分在 人设决策演示页 用多种类型散户并排演示，本页只跟老周一个人走。

已定（v0.3 §6.2，来自架构讨论 A4）解析失败与拒答分开处理。解析失败：Pydantic 校验不过则换种子重试（种子进缓存键），最多 2 次；仍失败则该智能体当日记为"未激活"、原因"解析失败"，不填默认值，也不沿用上期信念。拒答单独记类、不重试，当日同样记缺席。失败的尝试也写入缓存，重放时复现同一重试序列；失败率与拒答率写入运行清单 §6.2。缺席写进激活表 §9.1 §10.3。

第 8 站：内核

内核是一段确定性的规则代码，把意向换成可执行订单，共七步 §6.3。第 1–2 步做偏差修正：仓位档先换成意向权重，再加上从众、近期涨跌外推、彩票偏好三项修正，按随恐惧上升的风险厌恶缩放，最后截断到仓位上限；其中从众项用的是此人看到的可见买卖净占比 H_j。第 3 步处理卖出时的损失厌恶，损失厌恶系数 λ 先验中位数 2.25（Tversky & Kahneman 1992）；改善不够时不卖，理由记"舍不得割"。第 4 步决定今天是否查看并调仓。第 5 步是情绪分支：恐惧到最高档且回撤超过阈值时，高神经质或曾在杠杆崩盘中受伤的人以一定概率恐慌卖出，其他人"躺平"；贪婪/FOMO 到最高档时从众与彩票系数临时放大。第 6 步查硬约束：资金、T+1、整手、涨跌停可成交性、权限、两融、费用，再按执行方式定价：open 买入限价取涨停价（卖出取跌停价），dip 买入限价为前收 × (1 − k_i)、卖出为前收 × (1 + k_i)，chase 按均价加滑点；订单当日有效，未成交的收盘撤单。第 7 步把所有改动写回记忆 §6.3。

设计文档给出的公式如下 §6.3，参数的取值方向见 §6.3 参数表，数值本页不写：

步骤 1  w^int_ij = 仓位档按人设映射（斜率 s_i 随过度自信 κ_i 增大）
步骤 2  w*_ij = clip( w^int_ij + Δ_ij, 0, w_i^max )
        Δ_ij  = (β_i^herd · H_j + β_i^ext · R_j^(5d) + β_i^lot · L_j) / (γ_i(t) · σ_j²)
        γ_i(t) = γ_i · (1 + η_i · fear_i(t))
步骤 3  卖出时 U_real = ρ_i · g          （g > 0，落袋为安）
                 U_real = −λ_i · ρ_i · |g|  （g < 0，割肉之痛；λ 先验中位数 2.25）
        组合改善 + U_real 超过 τ_i 才卖，否则改为持有，原因"舍不得割"
步骤 4  当日查看组合 ~ Bernoulli(1 − exp(−ν_i · a_i(t)))；只在 |w* − w| > τ_i 时调仓
步骤 5  fear = 3 且回撤超阈值 → 以 p_panic 恐慌卖出，或"躺平"
        greed 或 fomo = 3 → β^herd、β^lot 临时放大

式中 H_j ∈ [−1, 1] 是此人看到的"别人在买 vs 在卖"净比例，R_j^(5d) 是近 5 日收益，L_j 是彩票特征（近期涨停、高 MAX、低价），σ_j 是标的近期波动 §6.3。分母里的 γ_i(t) 随恐惧上升，所以同样的从众信号在恐惧高时换来的加仓更少。LLM 的意向本身已带有一部分从众与外推，修正项只校准残差，这是 β 先验以小值为中心的原因 §6.3。组合层另有约束：总仓位 ≤ 1 + 杠杆上限（仅两融合格者）、持股数上限、现金缓冲 §6.3。

H_j 只统计帖子里明确的买卖行为（晒单、"已上车"、"割了"），帖子观点经 LLM 影响信念，两条路分开，避免同一条帖子被计两次 §7.5。各项 β 系数的先验集中在小值，由 V4 校准 §6.3；恐慌卖出概率、阈值的具体数值设计文档未给。

第 9 站：成交与记账

MVP 没有撮合引擎。market 模块只做三件事：检查合规、判定能否成交、计算费用，结果交给 accounts；market 不写账户，accounts 不判成交、不算费用 §3.3 §8。检查按固定顺序进行，不合规的订单直接拒绝并计数，不自动修正 §8.1。

模式 A 默认用日线判定成交，按 §8.2 第 1–4 步 §8.2。第 1 步：集合竞价单按真实开盘或收盘价成交，open 走这一步。第 2 步：dip 限价买单在限价 ≥ 当日最低价时成交，成交价 min(限价, 最高价)，卖单对称取 max(限价, 最低价)；chase 按当日成交均价加滑点。第 3 步：一字涨停买单不成交；收盘封板但盘中有低于涨停价成交的，买单按概率 p 抽签，全成或不成，跌停卖出同规则。第 4 步：个人成交不按 w_cap 放大后的量缩减，只有自身订单超过当日真实成交额的设定比例（如 1%）时超出部分不成交；放大后的群体资金流只作诊断 §8.2。只为收盘封板但盘中开过板的股票日和盘中事件日补分钟线 §8.2。T+1 的实现是买入只增加总数量，次日开盘前才转为可卖 §8.4。

05时间与可见性

同一条消息在不同激活点能不能被看到，由两条规则决定：available_at ≤ 当前时钟，以及"本阶段发的帖子下一阶段才可见"。选一个激活点，看老周那一刻能看到什么。

一个交易日分晚间/隔夜、盘前、集合竞价、盘中检查点、收盘后几个阶段 §3.4。MVP 的固定激活点是"盘前 + 收盘后"，非交易日改为 20:00 晚间激活点；盘中检查点只由量级 ≥ 3 的盘中事件触发，执行方式限 chase §3.4。盘前是当日唯一产生例行订单的激活点，只用 available_at ≤ 09:15 的信息；收盘后与晚间激活的第 1 次调用只出 BeliefUpdate 和"明日打算"，不出订单。打算为买或卖的人次一交易日盘前强制激活 §3.4。用日线时，盘前激活看到的是 T−1 收盘价加隔夜新闻，收盘后激活看到的是 T 日收盘价 §5.5。

同一阶段内被激活的智能体并发调用 LLM；阶段之间严格按时钟推进，本阶段发的帖子下一阶段才可见。这样做避免了同一时刻的循环依赖，也让并发结果与执行顺序无关 §9.1。唯一例外是群聊：同群在阶段内顺序接话最多 M 轮，只走发言调用，不影响当阶段交易 §7.1 §9.1。代价是不同群、不同渠道的人在同一阶段内彼此看不到对方刚发的帖子，传播速度以"阶段"为最小单位。

防泄漏有三项检查：放入金丝雀（故意设置的未来信息，看会不会被读到）、扫描 prompt 中的日期、重放一致性 §5.5。

    06每站详细说明：落表与回写

    第 11 站把一次激活拆进激活表和多张产出表。同时，内核做过的每一处改动都会回到智能体的记忆里，影响它下一次怎么说。

    拆表与关联

    声音、态度、决策是三种并列的产出，分表存放，以 persona_id、event_id、run_id 关联 §3.1 §10.3。激活表是各表的行级元数据来源：每个智能体每个激活点一行，记 phase（盘前 / 盘中 / 收盘后 / 晚间）、trigger（ν 抽中 / 事件 / 强制 / 群聊）、status 与 absent_reason（解析失败 / 拒答 / 超时），被抽中但缺席的也记；其余各表带 activation_id，时点、版本线、补跑、预热等字段从激活表取 §10.3。帖子表存正文、渠道、时间、回复关系和结构化元数据；态度表存 BeliefUpdate 里的结构化字段；决策表用 intent_kind 区分订单与明日打算，把意向（intent_action、intent_size、execution）和实际执行（exec_qty、exec_price、not_executed_reason）放在同一行，plan_ref 链回前晚打算 §10.3。账户类表另有交易流水、出入金、账户快照、持仓快照与战绩，全部可以由事件日志重算 §10.3。

    帖子表每行带 simulated 字段，正文另带隐式标识 §10.3 §16.2；每行只用 available_at ≤ info_cutoff 的信息，info_cutoff 记在激活表上 §10.3。帖子表只在团队内部和内部下游项目之间流转，对外展示的样例加显式"模拟生成"标识 §16.2。这些表是模拟产物，下游使用时要自行检验 §10.4。

    聚合口径

    态度类指标默认按人头权重 w_head 聚合，资金流类按资金权重 w_cap 聚合；对某标的的态度只在注意到该标的的智能体上聚合，同时输出覆盖人数 n_attend，覆盖太少时置空 §10.1。老周在 T 日盘前读到了星河储能的消息并给出态度，所以计入这只股票的 n_attend。没被激活、解析失败或拒答的人不进入当期态度均值，缺席是否集中在某些人群或行情日要单独检查，缺席记录在激活表 §6.2 §10.1 §10.3。

    回写记忆与言行不一

    内核第 7 步把改动写回记忆：缩量、取消、挂单没成交、涨停买不进、T+1 卖不出、权限不足、"舍不得割" §6.3。回写的目的是让后续发言与实际经历自洽。v0.3 把帖子放在成交判定之后写，所以分支 B 里老周当次发的帖就已经知道没买到；下一次被激活时，他的记忆里也有"涨停买不进"，发帖时可能抱怨踏空，而不会说自己已经持有 §6.1 §6.3。

    意向和成交分开记录，两者之差就是"言行不一"，作为一种可测量的特征 §3.1 §6.3。本例分支 A 意向与成交一致；分支 B 意向是买、成交为零，原因是涨停买不进。决策表里能直接数出这类行，按人群切片统计 §10.2。言行不一还包括"隔夜变卦"（明日打算与次日盘前实际意向之差）和口头战绩与账户战绩之差 §3.4 §10.2。言行不一率与隔夜变卦率没有真实对照，只报告并做合理性检查，标"无对照" §12.1。

    07涉及的模块

    一条新闻穿过七个业务模块，再加上负责串联的 orchestrator。业务模块之间只通过 schemas 共享类型。

    模块之间不直接互相调用内部实现，只交换 schemas 里定义的对象，比如 EventCard、Post、BeliefUpdate、OrderIntent、Fill §3.3。orchestrator 推进时钟、按阶段调度激活，并管理 /runs/<run_id>/ 下只追加的事件日志 §3.3。重放靠事件日志、LLM 响应缓存、随机种子和锁定的模型版本 §3.1。

    08开放问题

    沿着这条路走一遍后，下面这些点在设计文档 v0.3 里还没有定论，或者前后写法不一致。

    待定
    • §3.3 与 §5.3 的改写分工写法不一致。§3.3 的模块表仍写 events "按渠道改写（官媒 / 财经快讯 / 传闻）"；§5.3 已改为 events 只产出 EventCard 与 L0/L1，L2–L4 由 social 发布者以 Post 产出。本页按 §5.3 画，§3.3 的措辞待统一 §3.3 §5.3。
    • OrderIntent 字段未定义。第 8 站的示例字段借用 §10.3 交易流水表与决策表的列名，属于假设；内核与 market 之间的订单结构需在 schemas 里定下来 §3.3 §6.3 §10.3。
    • 盘前帖子能写哪些成交。§6.1 写第 2 次调用的输入含当日实际成交；持续运行中成交在收盘后判定 §3.4。本页演示按"盘前下单后即判定成交"画，持续运行时盘前帖子能写什么成交结果需要说明 §3.4 §6.1。
    • 一字涨停下 open 买单走哪一步。open 买单限价取涨停价，一字板时开盘价等于限价，第 1 步条件满足；第 3 步又写一字涨停买单不成交。本页按第 3 步处理，两步的先后需写明 §6.3 第 6 步 §8.2。
    • 注意力与推荐流参数。衰减常数 τ_d、温度 T_i、渠道权重 w_i、推荐流各项权重没有给出取值；推荐流参数被列为实验变量 §5.4 §7.3。
    • 发布者帖子的延迟。§5.3 中 L2 的延迟是"随传播"，L3 是"数小时"，L4 "不定"，具体怎样换成模拟时间戳未定 §5.3。
    • 内核参数取值。β 系数先验集中在小值、由 V4 校准；dip_k 只给了先验 1%–3%；恐慌卖出概率 p_panic、回撤阈值、调仓阈值 τ_i 的数值未定 §4.1 §6.3。
    • 开板涨停的成交概率是假设。收盘封板但盘中开过板的买单按概率 p 成交：有分钟线时 p = 非封板时长占比 × 排队折扣，排队折扣是假设参数；没有分钟线时跑 0.1 / 0.3 / 0.5 三档做敏感性分析。"涨停买不进率"没有真实数据，不进校准目标 §8.2。
    • 费用与权限数字。印花税、佣金、经手费、证管费、过户费，以及创业板与科创板/北交所权限门槛都标了〔需复核〕 §8.1。
