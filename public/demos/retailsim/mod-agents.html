模块 · agents

agents：一个散户怎么想、怎么说、怎么做

每个智能体每次被激活，就走一遍认知循环：读有限的几条信息，第 1 次调用 LLM 形成态度并给出买卖意向，由规则内核按 A 股规则和行为偏差改写成订单并判定成交，改动和原因写回记忆；想发帖的人再做第 2 次调用，看着实际成交结果写帖子。

LLM 给意向，内核管约束 四层记忆 言行不一可测量 意向来源可替换

01职责一览

一句话：把一张人设卡变成一个会看信息、会说话、会下单、会记仇的模拟散户。

agents 模块管每个智能体的"脑子"：认知循环、注意力预算、三层记忆加预置记忆、情绪状态，以及可替换的意向来源接口§3.3。它自己不撮合、不记账、不生成新闻，也不决定谁和谁是好友。这些分别是 market、accounts、events、social 的事。agents 只读它们给的数据，只交出结构化的态度、帖子和意向。模块之间不互相 import，类型全部来自 schemas，由 orchestrator 按日内时段把它们接起来§3.3。

输入

  • PersonaCard ← population：人口属性、大五描述、内核参数 KernelParams、渠道偏好、经历向量、文风§4.1
  • FeedItem[] ← social：模拟散户帖、发布者 L0–L4 帖、新闻快讯§5.4。events 只给 L0/L1 两类不带立场的版本，L2–L4 由 social 的发布者以帖子写出§5.3§5.6
  • 账户只读视图 ← accounts：总资产、可用资金、持仓与成本、两融负债§3.3§6.4
  • 行情与市场状态 ← market / data
  • Fill ← market：上一阶段订单的成交结果，用于写回

agents（本模块）

  • 激活判断与注意力预算：每次只看 K 条
  • 每次激活最多两次 LLM 调用：第 1 次出结构化态度与意向，第 2 次（只在想发帖时）在成交判定之后写帖子§6.1
  • 规则内核：7 步修正，把意向改成订单，按执行方式定价
  • 写回与反思：改动原因进情景记忆，低频反思形成教训

输出

  • BeliefUpdate → outputs 态度表§10.3
  • Post → social 推荐流，同时进帖子表
  • DecisionIntent（盘前与盘中）→ outputs 决策表（意向那一栏）
  • NextDayPlan 明日打算（收盘后与晚间）→ 记忆与决策表，不产生订单§3.4§6.3
  • FundingIntent → accounts 出入金§8.4
  • OrderIntent[] → market 成交判定

主要产物与职责以 agents/__init__.py 文档串和 §3.3 模块表为准；模块尚未实现。

02为什么需要它

只让大模型扮演散户，说得像，但做得不对；只用规则，做得对，但说不出话。

项目要产出三样东西：散户的声音（帖子）、态度（结构化信念与情绪）和决策（买卖与仓位）§1。声音只能靠 LLM 写，因为它要有口语、黑话和情绪。决策却不能全交给 LLM：T+1、涨跌停、资金和交易权限是必须逐条执行的硬规则，交给 LLM 无法保证；损失厌恶、从众这类偏差需要按文献校准强度，而对齐训练过的模型本身就偏理性、割肉追涨太少§13.3。所以设计采用混合方案 C：LLM 给出意向，规则内核负责硬约束和可校准的行为偏差修正§3.1 原则 1。

混合方案带来一个新问题：内核把"我要卖一半"改成"持有"，智能体第二天发帖时如果还以为自己卖了，就前后矛盾。agents 模块因此把内核改动的结果和原因写回该智能体的记忆，让后续发言与之自洽。说的和做的之间的差距不当作 bug 消掉，而是单独记录，作为一个可测量的特征，叫"言行不一"§6.3 第 7 步。

第三个理由是成本与异质性。550 个智能体每天激活两次，第 1 次调用人人都做，输入约 3.0k token；第 2 次调用只有发帖者做，输入约 3.6k token，其中 3.0k 是与第 1 次共用的前缀§14.2。信息必须先按注意力预算裁到每人几条。同一运行内全体用同一底座§6.6，异质性主要从 LLM 之外注入：每人看到的信息不同，内核参数和人生经历也不同，这样才能避免 550 个人说同一句话§13.2。

反例：让 LLM 直接下单TwinMarket、StockAgent 等做法让 LLM 直接输出订单。这样无法区分"模型觉得该卖"和"规则不允许卖"。本项目只把"内核换成 LLM 直接输出 OrderIntent"放进消融实验，作为对照§11.2。

03机制详解

一次激活 = 一遍认知循环。紫色步骤调用 LLM，蓝色步骤是确定性的规则内核，青色是不调模型的规则筛选。

3.1 认知循环：每个阶段做什么

先决定醒不醒。MVP 的固定激活点是盘前与收盘后，非交易日为 20:00 晚间激活点；盘中检查点只由量级 ≥ 3 的事件触发§3.4。一个智能体在某个时段被激活有三种来由：按自身活跃度 ν 抽中；被触发，即持仓日涨跌超过个人阈值、关注的媒体里出现量级 ≥ 3 的事件、持仓在群里被讨论、持仓涨跌停；强制，即昨晚的明日打算是买或卖，次日盘前一定激活§9.1§3.4。没被激活的人保持持仓、不发帖。被抽中但缺席的（解析失败、拒答、超时）照样记入激活表；盘前调用到 09:15 仍未完成的，当日记为未激活、原因"超时"§9.1。同一时段内的智能体并发运行，本时段发的帖子下一时段才可见，唯一例外是熟人群聊的阶段内多轮对话§9.1§7.1。

只有盘前出订单。盘前（08:00–09:15）是唯一产生例行订单的激活点，按 T 日行情判定成交；盘中检查点也可下单，但执行方式只能是 chase，拿不到分钟线时交易意向转为明日打算，运行清单标"盘中无行情"。收盘后与晚间激活的第 1 次调用只出 BeliefUpdate 与明日打算，不出订单§3.4。

感知（perceive，规则）。候选信息很多，每人每次只看 K_i 条，K_i 由人设给出，在 3–15 条之间，约占 1,500 token 的信息流预算§5.4。每条候选打分：

score = w_i(渠道) · m(量级) · rel_i(资产) · exp(−Δt / τ_d) · sal

w_i(渠道) 是这个人对各渠道的偏好（人设字段 media_diet），m 是事件量级，rel_i 是信息涉及的资产与他的相关度，即与他的持仓、自选、关注行业的重合度（文档未给三者的权重），Δt 是信息发出到现在的时间，τ_d 是衰减时间常数，sal 是显著性。持仓异动（日涨跌超个人阈值或涨跌停）必入；其余按 softmax(score / T_i) 不放回抽取，随机性是有意保留的。没看到的信息不会消失，之后可能经群聊或大V转述再到达§5.4。信息顺序按种子对每个智能体打乱，以免模型偏爱排在前面的条目§13.4。

第 1 次调用：解读（interpret，LLM）→ BeliefUpdate。每次激活最多两次 LLM 调用，帖子在成交判定之后写§6.1。第 1 次调用把解读和意向合在一起，只出结构化字段，不放文风示例帖。prompt 按"静态在前、动态在后"排列：规则说明 → 人设卡 → 长期信念 → 检索到的记忆 → 当日信息 → 输出 schema，两次调用共用这段静态前缀，前缀缓存命中率最高§6.1§14。人设卡里大五人格以描述语给出，不给分数，也不写 MBTI 类型名；内核参数完全不进 prompt，模型不知道自己的 λ 是多少§4.1。浮亏比例等数字由内核先算好再以文字给出，例如"浮亏 12.3%"§13.4。模型输出的是分档：对每只注意到的资产给立场（−2 到 2）、收益分档、信心（1–5）和至多 3 个理由标签，再给恐惧、贪婪、后悔、怕踏空四种情绪（各 0–3）、政策信任（−1/0/1）、想不想发帖，以及一段不超过 120 字的内心独白，独白只用于审计，不对外交付§6.2。用分档而不用连续数字，是因为模型报出的数字校准差、扎堆在整数上；分档到数值的映射由内核按人设做，过度自信的人映射得更极端§6.2。

解析失败与拒答。输出先过 Pydantic 校验，推理框架支持时再加 JSON schema 约束解码。校验不过就换种子重试，种子进缓存键，最多 2 次；仍失败则该智能体当日记为"未激活"、原因"解析失败"，不填默认值，也不沿用上期信念。拒答单独记类、不重试，当日同样记缺席，拒答率按话题与人群切片，作为底座选型扣分。失败的尝试也写入缓存，重放时复现同一重试序列§6.2。

第 1 次调用：意向（intend）→ DecisionIntent 或明日打算。盘前与盘中激活时，对每个资产给出买 / 卖 / 持有 / 观望、仓位档（tiny / small / half / large / all_in）、执行方式、至多 3 个理由、至多 2 条影响这个决定的帖子 id 和一句不超过 120 字的理由说明；每次激活最多再给一个出入金意向 FundingIntent§6.3。执行方式三选一：open 开盘就买卖，dip 挂单等回调或反弹，chase 盘中追；盘中激活只能选 chase。LLM 只选执行方式，不报数字价格，价格由内核第 6 步定§6.3。source_post_ids 供 social 更新信任，按自报归因使用，不作修正§7.2。收盘后与晚间激活改为输出明日打算 NextDayPlan（买 / 卖 / 持有 / 观望 + 标的 + 不超过 60 字的理由），写入记忆，不产生订单§3.4§6.3。意向来源是可替换接口：MVP 默认用 LLM，也可以换成不调模型的规则先验或 Jev；换成后两者时，第 1 次调用只做解读（见 3.7）§6.1§6.6。

约束与成交（constrain，内核；撮合，market）→ OrderIntent[] → Fill。确定性的 7 步修正，见 3.2。订单交给 market 按 §8.2 判定成交。凡是内核改了意向或订单没成交，实际结果和原因都写回记忆§6.1§6.3。

第 2 次调用：发帖（post，LLM）→ Post。只在 want_to_post 为真时调用。输入在共用前缀之后追加当日意向、实际成交与未执行原因，以及文风示例帖；文风示例帖只放在这一次调用里§6.1。所以帖子说的是成交之后的事，例如"挂了个低价没成交"§6.3。帖子表有 reply_to、group_id、turn 字段，可以是回复或群聊里的一轮§10.3。正文是自由文本，不在 JSON 里；文风随人设与渠道变化，每个智能体绑定一种说话风格，股吧与雪球换不同的示例池§4.4§7.4。群聊接话只走第 2 次调用，不重做第 1 次调用§6.1§7.1。帖子是一等产出，进入帖子表并参与 V2 声音验收。帖子与实际所为之差是言行不一；收盘后的明日打算与次日盘前实际意向之差叫"隔夜变卦"，也是言行不一的一种§6.1§3.4。社交影响分两条路：观点路径是别人的帖子在解读时被读到；行为路径只统计看到的买卖行为（晒单、"已上车"、"割了"），进入内核的 H_j。两条路分开，避免同一条帖子被计两次§7.5。

反思（reflect，LLM，低频）。每周一次，或大盈亏之后触发；Tier-A 的每周反思放在周末激活点§6.1§3.4。模型读一段时间的情景记忆，写出带信心度的教训存入语义记忆。反思 prompt 里不得出现仿真时钟之后的日期§6.4。

记忆。记忆是循环的起点也是终点：下一次激活时，按"近因 + 重要度 + 相关度"检索出约 800 token 放进 prompt，相关度以结构化匹配为主、本地嵌入为辅§6.4，细节见 3.4。

3.2 内核 7 步：意向怎么变成订单

内核的输入有六类：意向、观点分档与情绪、人设参数、持仓状态（成本 c、现价 p、浮盈 g = p/c − 1、持有天数）、行情状态、社交信号§6.3。7 步按顺序执行，每一步都是可复现的计算，没有 LLM 参与。下标 i 指智能体，j 指资产。

第 1 步：仓位档 → 目标权重 wint

把 tiny / small / half / large / all_in 映射成目标权重 wintij（这只资产占总资产的比例）。映射斜率 s_i 随过度自信 κ_i 上升：同样说"半仓"，过度自信的人实际给得更多§6.3。文档没有给出各档的具体数值和 s_i 的函数形式，本页 s4 示例里的映射是演示用的假设。

第 2 步：行为偏差修正 Δ 与随恐惧变化的风险厌恶 γ(t)

w*ij = clip( wintij + Δij, 0, wimax )
Δij = ( βiherd·Hj + βiext·Rj(5d) + βilot·Lj ) / ( γi(t)·σj2 )，　γi(t) = γi·(1 + ηi·feari(t))

分子是三种"想多买一点"的冲动：H_j ∈ [−1, 1] 是他在信息流和群里看到的"别人在买"减"别人在卖"的净比例（只算行为，不算观点），R_j(5d) 是近 5 日收益（追涨杀跌），L_j 是彩票特征（近期涨停、高 MAX、低价）。分母是风险：σ_j 是近期波动率，γ_i(t) 是当下的风险厌恶，恐惧越高、情绪越敏感（η 越大），分母越大，修正越小。这是均值-方差框架下"冲动 ÷ 风险厌恶 × 方差"的写法§6.3。

β 的先验中心取小值，因为 LLM 的意向里已经含有一部分从众与外推，内核只校准剩下的残差；β 的最终取值由 V4 行为矩决定§6.3§12.2。修正后还要满足组合约束：总仓位 ≤ 1 + 杠杆上限（只有两融权限的人才有杠杆）、持股数 ≤ N_imax、保留现金缓冲§6.3。wimax、N_imax 与缓冲比例文档未给数值。

第 3 步：实现效用，决定卖不卖

Ureal = ρi·g（g > 0）；　Ureal = −λi·ρi·|g|（g < 0）

这一步来自 Barberis & Xiong (2012) 的实现效用：卖出那一刻，盈亏才"落袋"，人会为这一刻本身感到高兴或痛苦。ρ_i 是这种感受的强度（处置效应强度），λ_i 是损失厌恶，亏损时的痛苦是同等盈利快乐的 λ 倍，先验中位数 2.25§6.3。只有"组合改善 + U_real"超过惯性阈值 τ_i 才真的卖。盈利时 U_real 为正，容易过线，于是"卖赢家"；亏损时 U_real 为负，很难过线，于是"扛输家"；浮亏回到 0 附近时阻力消失，于是"回本就卖"§6.3。想卖但没过线的意向改成持有，原因记为"舍不得割"。"组合改善"一项文档没有给出公式。下面的小计算器可以拖动参数看判定怎么变。

第 4 步：今天看不看盘

P(看盘) = 1 − exp( −νi · ai(t) )

每天是否打开账户按伯努利分布抽取。ν_i 是活跃度，a_i(t) 随注意力事件、持仓波动和情绪上升；文档没有给 a_i(t) 的具体形式。即使看了盘，也只在 |w* − w| > τ_i 时才调仓，τ_i 是"差一点就懒得动"的不调仓区间§6.3。ν 与 τ 都按换手与交易频率分布校准（见 3.3 参数表）。

第 5 步：情绪分支

情绪在 BeliefUpdate 里是 0–3 的分档，3 为最高档§6.2。内核只在最高档时走分支§6.3：

  • 恐惧到顶且回撤超过阈值：神经质高的人、在以往杠杆踩踏里受过伤的人，以概率 p_panic 清掉高波动持仓（恐慌割肉）；神经质低的人、长期被套的人"躺平"，接下来若干天不激活。
  • 贪婪或怕踏空到顶：βherd 与 βlot 临时放大，第 2 步的修正随之变大。

p_panic、回撤阈值、躺平天数和放大倍数，文档都没有给数值。哪些人算"受过伤"来自经历向量：2015 年被强平过的人杠杆上限低、恐慌阈值低§6.5。

第 6 步：硬约束

依次检查现金、T+1、整手、涨跌停可成交性、交易权限（创业板、科创板、北交所、两融）、两融额度与维持担保比例，并计入佣金、印花税、过户费，输出 OrderIntent§6.3。LLM 只选执行方式，不报数字价格，内核按执行方式定价§6.3：

  • open：买入限价取涨停价，卖出取跌停价，也就是按开盘价成交，走 §8.2 第 1 步；集合竞价没有价格笼子。
  • dip：买入限价 = 前收 × (1 − k_i)，卖出限价 = 前收 × (1 + k_i)。k_i 是人设参数 dip_k，先验 1%–3%§4.1，走 §8.2 第 2 步：买单在限价 ≥ 当日最低价时成交。
  • chase：按当日均价加滑点成交，盘中激活取检查点至收盘的分钟均价；遇封板走 §8.2 第 3 步。

订单当日有效，没成交的收盘撤单，"挂单没成交"写回记忆§6.3。T+1 的实现方式是：当日买入只增加总数量，次日开盘前才转为可卖§8.4。成交与否不归 agents 判断：订单交给 market，按日线规则判定，例如一字涨停时买单不成交；收盘封板但盘中开过板的，按成交概率 p 全成或全不成；个人订单超过该股当日真实成交额的设定比例（如 1%）时，超出部分不成交，原因写回记忆§8.2。market 对不合规订单直接拒绝并计数，不自动修正，因为自动修正会掩盖内核的错误§8.1。

第 7 步：写回

内核改动意向的情况包括：缩量、取消、挂单没成交、涨停买不进、T+1 卖不出、权限不足、舍不得割。每种改动都把实际结果和未执行原因写进情景记忆，下一次激活时模型会读到"我昨天想割没割成"，后续发言与之自洽§6.3。意向与实际成交分两栏进入决策表（intent_action、intent_size、execution 对 exec_qty、exec_price、not_executed_reason）§10.3，两者之差就是言行不一，按人群统计并给出原因分布§10.2。言行不一有三种测法：帖子与成交之差；明日打算与次日盘前实际意向之差，即隔夜变卦，决策表的 plan_ref 把两者链起来§3.4§10.3；帖子里自报的战绩与账户实际战绩之差§6.4。

3.4 记忆与反思

记忆分四层§6.4：

层存什么怎么用
工作记忆当日信息流、账户摘要（总资产、可用资金、仓位、各持仓浮盈亏）、盯盘快照只在本次激活内有效，不持久化
情景记忆带日期的经历，包括内核写回的"没卖成""没买进"重要度 = 规则分（盈亏大小、事件量级）+ LLM 评分；检索分 = 近因 + 重要度 + 相关度，做法同 Generative Agents；相关度以结构化匹配为主、嵌入相似度为辅
语义记忆反思得出的教训，每条带信心度和来源情景 id可以被后来的经历削弱或推翻
预置记忆仿真起点之前的人生经历，3–8 段显著片段§4.4标记 seeded，与仿真中产生的记忆区分

每次进 prompt 的记忆约 800 token，其中账户摘要约 100 token；旧情景定期压缩§6.4。预置记忆和初始持仓来自预跑：population 用规则内核在真实历史行情上把这个人的经历跑一遍，得到起点时的持仓与成本，再由 LLM 改写成背景故事，不得新增事实§4.4。

相关度怎么算。记忆写入时标注标的、事件类别、理由标签、盈亏方向，检索时与当日信息流逐项匹配，这是主路。嵌入相似度为辅，补结构化字段覆盖不到的联想。嵌入模型本地运行开源中文模型（如 BGE 系列，CPU 可跑），锁定权重版本，结果按文本哈希缓存；记忆检索、背景故事多样性检查与同质化诊断共用这一模型，版本号写入运行清单与缓存键；不用厂商嵌入 API§6.4§4.4§13.2。

战绩怎么回到记忆。每月把一段战绩摘要写成一条情景（Tier-A 每周一次）：区间与累计收益、相对沪深 300 的超额、最大回撤、最好与最差的一笔、出入金。显著单笔当日写入：单笔或单日账户波动超个人阈值、被强平、清仓、回本§6.4。战绩影响行为有两条路：一是 LLM 读到记忆，二是内核慢变量更新。慢变量更新有两类：自我归因学习（Gervais & Odean 2001），赚钱抬高 κ，亏钱压低 κ 但幅度更小；赌场钱与回本效应（Thaler & Johnson 1990），盈利后 γ 下降，深套时"等回本"的倾向增强。步长取小值，由 V4 定；两条路要一起校准，不能重复计入§6.4。

3.5 经验效应：人生经历怎样进入信念

μexpi,t = Σk wi(k)·Rt−k，　wi(k) ∝ (Li − k)θ

这是 Malmendier & Nagel 的经验加权：亲身经历过的市场收益决定先验乐观程度，越近的年份权重越大。L_i 是看盘年限（从入市年份算起），θ 控制近期经历的权重，工作论文版在风险容忍度回归中估计为 1.43（标准误 0.28），参与回归中为 1.33（0.21），论文后文取 1.5；正式发表版的表格尚未核对§6.5。原文的窗口按年龄算，本项目改为按入市年限算，这是平台自己的假设，两种设定都实现，用硅基调查比较§6.5§12.1。经历向量编码了 2007/2008、2015 杠杆牛与股灾及 2016 年初熔断、2018、2019–2021、2021–2024 与 2024-09-24、2025-04 关税冲击与汇金托底等关键行情，影响三件事：先验乐观 μexp、对政策底的信任、杠杆厌恶§6.5。

已定（v0.3 §4.4、§5.5，来自架构讨论 A1）日线从 2005 年起，覆盖股改与 2007 年牛市；2005 年以前的经历只写进人生骨架作文字背景，不在行情上预跑§4.4。智能体看到的价格按 asof 当天现算前复权，收益与战绩统一用后复权§5.5。

3.6 Tier-A 与 Tier-B 的差别

MVP 约 550 人分两层§14.1。Tier-A 50 人用作大V、典型人群代表、深度样本与审计，记忆与反思完整，每个激活点都激活；Tier-B 500 人填满 100 格 × 5 人的人群保底，记忆精简、低频反思，事件触发加低频例行激活。两层共用同一套认知循环、同一个内核和同一个模型，区别只在记忆深度、反思频率、激活频率§14.1。战绩摘要写入记忆的频率也不同：Tier-A 每周，其余每月§6.4。人设卡的 tier 字段取 A_bigv、A_deep、B 三值§4.1。

Tier-A · 50 人

大V 20 人 + 深度样本 30 人§14.1。完整记忆与反思，每个激活点都激活；战绩每周回灌。

Tier-B · 500 人

精简记忆，低频反思，事件触发加低频例行；战绩每月回灌。人群切片的主要来源§14.1。

已定（v0.3 §6.6、§14.1，来自架构讨论 A4）MVP 同一底座内 Tier-A 与 Tier-B 用同一模型，分层只体现在记忆深度、反思频率与激活频率，避免把人设差异和模型大小混在一起。"2 个底座"即两个模型，跨底座比较时全体一起换。小模型延到 Phase 2 扩规模时再用，切换前在开发事件上用同一批 Tier-B 人设对比大小模型，V2 文风指标与 V5 一致性不退化才切。
已定（v0.3 §4.3、§14.1，来自架构讨论 A5）Tier-A 50 人拆为大V 20 人与深度样本 30 人。深度样本按账户档每档 6 人、分散在不同年龄段，落在已有 Tier-B 的格内，每个账户档至少 1 个杠杆户；同格 Tier-A 与 Tier-B 只差记忆深度与反思频率，对比结果作为 V5 的分层效应检验。人群切片默认只用 Tier-B，Tier-A 单列；大V 的言行不一照常测量。

3.7 意向来源可替换

第 1 次调用里的"意向"部分是一个接口，有三种实现§6.6：

LLM MVP 默认

解读之后由同一底座输出 DecisionIntent 与理由，理由与帖子同出一源。

规则先验 对照

不调 LLM，按观点分档、情绪与人设参数直接给意向。用作对照，也是降本备选；此时第 1 次调用只做解读§6.1。

Jev 候选

TypeSafe 的校准型决策模型，输入状态与预定义选项，输出各选项概率，不写文本。需通过 Phase 0 对比试验。

Phase 0 在开发事件上分别跑三种来源，比较 V4 行为矩误差与同质化诊断§13.2。Jev 胜出，则 Phase 1 由它给出意向分布并抽样，LLM 只写帖子与理由，言行一致靠写回记忆维持；否则 Jev 只保留评估分类器用途。使用 Jev 前要验证中文与股吧黑话能力、数值与长信息流下的误差、校准相对的是其训练分布而非 A 股散户，历史推演同样要过记忆探针；它是境外 API，输入按 §16.4 去标识化§6.6。另外，底座模型由运行配置统一指定，一次运行内不混用；温度在人设生成时绑定、运行期不变§4.1，只调到输出不重复为止，不靠高温制造差异§13.2。同一批人设在不同底座下的行为差异放在 V5 检验§6.6。

        07与其他模块的关系

        agents 读人设、信息和行情，写帖子、态度和意向；真正改账户的是 market 和 accounts。

        按一天的数据流顺序：orchestrator 决定谁在哪个时段被激活§9.1；agents 从 events、social 和行情里取候选信息，经 prompts 拼好提示词、经 llm 网关调用模型，第 1 次调用得到结构化的解读与意向；内核产出的 OrderIntent 交给 market 判定成交，成交回报经 accounts 记账后再回到 agents 写记忆；想发帖的智能体随后做第 2 次调用写帖子§6.1；帖子、态度、决策、激活等表交给 outputs§10.3，再由 validation 对照真实数据打分。
