PTStore: Distributed Prefix Caching and Replication for High Throughput Inference Serving

⭐⭐⭐⭐☆ (4/5)
作者: Meghana Maghyastha, Robert Underwood, Randal Burns, Bogdan Nicolae  |  机构: Johns Hopkins University; Argonne National Laboratory  |  分类: cs.AI  |  日期: 2026-07-28
arXiv · PDF
受 CDN 客户端缓存设计启发,PTStore 将构成可复用 KV cache 前缀的热门张量进行分布式存储与复制。这降低了 KV cache 访问延迟并缓解了因热门张量集中在少数服务器上导致的负载不均衡。通过去中心化,PTStore 将 LLM 推理可用 KV cache 容量扩展数个数量级。在长文问答数据集上,PTStore 比不聚合跨节点/GPU 内存、需重新生成 KV cache 的基线高效 5-6 倍。

核心贡献

  • 提出 PTStore——分布式、可复制的细粒度前缀张量存储,受 CDN 客户端缓存启发,实现跨多节点/GPU 的 KV cache 前缀复用可扩展存储(增量存储消除冗余、扁平化合并元数据支持一次性 LCP 查询、热前缀本地复制)
  • 给出一套设计原则:RDMA 感知的主存整合(零拷贝批量 RDMA、段缓存)、访问模式感知的 GDSF 淘汰策略(适配大小-频率权衡,区分 owned/replicated 缓存)、可配置多级缓存与驱逐策略
  • 实现研究原型,基于 Mochi/Thallium 的 C++ 客户端 + nanobind Python 接口,无缝替换 vLLM 的前缀共享路径

主要结论

  • 通过分布式增量张量存储与本地复制,PTStore 能跨大量 GPU/节点高效复用 KV cache 前缀,将 LLM 推理可用 KV cache 容量扩展数个量级
  • 在长文问答数据集上,PTStore 比不聚合跨节点/GPU 内存的基线高效 5-6 倍,TTFT 降低最多约一个量级
  • 本地复制是关键:缺乏复制(如 EvoStore)的远程前缀复用因 RDMA I/O 开销过大而接近于忽略远程前缀

实验结果

  • 测试平台:ALCF Polaris(560 节点,每节点 4×A100、512GB DDR4、Slingshot 10、Lustre),Mistral-7B + vLLM v0.6,每 GPU worker 跑 1500 条抽取式问答查询,按 α=6 幂律采样模拟重尾前缀热度
  • 弱可扩展(8-32 GPU,WikiQA ~8k tokens):PTStore 优于 vLLM-Vanilla、vLLM-Prefix 和 EvoStore;EvoStore 因无本地复制 RDMA 开销高、接近 vLLM-Prefix
  • 序列长度可扩展(SQUAD,1k-8k tokens):短前缀(1k)vLLM 基线更优,2k 起 PTStore 反超,8k 时比 vLLM 前缀缓存快约 2 倍
  • PTStore 相对 EvoStore:1k 时快 2 倍以上,8k 时快 20%,复制显著降低 RDMA I/O 开销
  • 局限:复制缓存比例固定 50% 未做敏感性扫描,与 LMCache/Mooncake 正面对比留待未来工作
为什么重要: 将 CDN 客户端缓存范式引入 LLM KV cache 管理,实现跨节点分布式前缀存储与复制,使 KV cache 容量可扩展数个量级,是大规模 LLM 推理服务的关键基础设施创新

FusionML: Prefill, Not Decode — Mechanism and Boundaries of CPU+GPU Co-Execution on Unified-Memory Apple Silicon

⭐⭐⭐⭐☆ (4/5)
作者: Om Mohite  |  机构: Independent Researcher, Mumbai, India  |  分类: cs.AR  |  日期: 2026-07-28
arXiv · PDF
Apple Silicon SoC 在统一内存系统上共享 CPU、GPU 和 Neural Engine,引发了 Transformer 推理能否通过跨单元拆分单算子加速的问题。此前尝试(包括作者自己的)都失败了。本文找到原因:MLX 的惰性图调度器在 CPU 操作消费未具体化的 GPU 结果时序列化跨流工作。FusionML 实现逐层、竞争感知的 CPU+GPU 行拆分用于 Transformer prefill,在五款芯片、三代 Apple Silicon 上将 Llama 形状 decoder-block prefill 加速 1.15-1.38 倍,在 Qwen2.5-7B 上通过原生 MLX-LM 达到 1.18-1.25 倍更快 TTFT,token 输出完全相同且 decode 吞吐不变。

核心贡献

  • 机制发现:识别 MLX 惰性图调度器为跨流 CPU+GPU 工作的隐藏序列化器——行拆分 matmul 在具体化输入下快 1.38 倍,在惰性图内反而慢至 0.66 倍;eager 物化边界(mx.eval)恢复并发(1.34 倍)。解释了此前协同执行尝试失败的历史
  • FusionML 设计:逐层、竞争感知的 CPU+GPU 行拆分用于 Transformer prefill,基于 eager 边界,在实际并发竞争下校准比例(非单单元速率),配有无回归运行时门控(试运行+周期性重探测+迟滞)
  • 跨五款芯片、三代 Apple Silicon 的公平社区复现评估,采用严格精度匹配、相邻测量协议
  • 同等严谨的边界刻画:decode 结构性不获益(共享带宽受限)、精度匹配训练在所有芯片上均失败、ANE 分派开销在层粒度排除、探测调度器在内存压力下自我破坏

主要结论

  • 在统一内存 Apple Silicon 上,算子内 CPU+GPU 协同执行既非神话也非免费午餐:它是 prefill 范围内的机制,受 eager 边界调度要求约束(惰性图框架默认违反)
  • 在其有效区间内,加速真实、可复现且免费(块级最高 1.38 倍,端到端 TTFT 1.25 倍,token 输出完全相同且 decode 中性)
  • 受共享带宽(decode)、分派开销(ANE)和工作集共驻(探测调度器)三重边界约束

实验结果

  • Llama-3-8B 几何 decoder-block prefill 在五款芯片(M1/M2/M3 Pro/M4/M4 Pro)上加速 1.15-1.38 倍,全 32 块深度无损
  • Qwen2.5-7B 通过原生 MLX-LM 端到端 TTFT 加速 1.18-1.25 倍,token 输出完全相同,decode 吞吐不变
  • 精度匹配训练在所有五款芯片上失败(0.86-0.97 倍);ANE 分派开销在层粒度排除
  • 无回归门控在内存压力下自我破坏:观察者效应约 1.4 倍偏差,约 1.7 倍重载成本
  • 公平协议:精度匹配相邻基线、环境戳记原始结果、撤回先前关于训练速度提升的声明
为什么重要: 揭示了 Apple Silicon 上 CPU+GPU 协同执行失败的根因(MLX 惰性图序列化),并给出了 prefill 范围内真实有效的解决方案,对 Apple Silicon 上的 LLM 推理优化有直接工程价值

xMIx: High-Performance Serving-Time Platform for Mechanistic Interpretability Apps

⭐⭐⭐⭐☆ (4/5)
作者: Michael Blum, Mark Silberstein, Yaniv David  |  机构: Technion (Israel Institute of Technology)  |  分类: cs.AI  |  日期: 2026-07-28
arXiv · PDF
机械可解释性(MI)已成为分析和干预推理计算的有力方法,但 MI 在生产级模型服务系统中部署目前不现实,因为现有 MI 框架引入了过高的运行时开销。根本问题是 MI 函数与服务模型不能干净组合:它们碎片化部署,常迫使排空请求并重建服务状态,并与连续批处理和 CUDA 图执行等关键性能优化冲突。本文提出 xMIx——一个服务原生框架,在 vLLM 中部署 MI 应用,实现 1.3% 平均 ITL 减速、1.2% P99 ITL、2.6% TTFT、1.6% TTT 减速,性能与原生 vLLM 执行相当。

核心贡献

  • 调研 14 个 MI 应用并归纳为三个原语(Read/Write/Conditional Write),提供统一抽象
  • 构建服务原生框架(基于 vLLM),保持高吞吐低延迟推理,支持动态运行时启用/禁用("don't-use-don't-pay")
  • CUDA 图安全内核设计,图级切换支持连续批处理;多个 MI 应用可部署在单个模型实例中

主要结论

  • xMIx 消除了将 MI 洞察带入生产级推理的障碍;MI 应用可坍缩为少量适合服务原生集成的原语
  • 开销比现有 MI 框架低至少一个数量级
  • 为 MI 从研究走向生产部署铺平道路

实验结果

  • 在 3 个模型(Llama-3.1-8B、Mixtral-8x7B、Qwen3-8B)× 7 个 MI 应用上评估
  • 性能开销:1.3% 平均 ITL、1.2% P99 ITL、2.6% TTFT、1.6% TTT 减速 vs vLLM 基线
  • vs TransformerLens/NNsight:xMIx 保留约 99% 基线吞吐,而 TransformerLens 全层配置吞吐下降 99.7%(17.18 vs 7596 tok/s),NNsight 下降 54-55%
  • vs EasySteer:在 Mixtral 上 xMIx +0.7% ITL vs EasySteer +178% ITL
  • 内存开销可忽略——框架状态几 KB,MI 应用总占用几 MB;输出正确性通过精确 token 比较验证
为什么重要: 首次将机械可解释性(MI)应用以近乎零开销部署在生产级 vLLM 服务系统中,使越狱检测、真实性评估、幻觉检测等 MI 应用可用于生产推理,是 MI 从研究走向生产的关键一步

HyMCache: A KV Cache Framework for Multi-Turn LLM Serving with CXL-Hybrid Memory

⭐⭐⭐⭐☆ (4/5)
作者: Hakbeom Jang, Inho Song, Sam H. Noh, Jongryool Kim  |  机构: SK hynix America; Virginia Tech  |  分类: cs.DC  |  日期: 2026-07-28
arXiv · PDF
长上下文、多轮和智能体 LLM 工作负载日益复用先前处理的上下文,使 KV cache 复用对减少冗余计算至关重要。然而,复用将瓶颈转移到存储和提供可复用 KV 状态的内存层。本文提出 HyMCache——一个集成 CXL 混合内存(CXL-HM)的 KV cache 框架。CXL-HM 将少量设备内 DRAM 与大容量 SSD 后端容量结合在 CXL 接口之后。通过利用多轮 KV cache 访问的读主导、可预测和仅追加特性,HyMCache 在设备 DRAM 中暂存延迟关键的读取,实现 DRAM 级 KV cache 效率与 SSD 级成本。在相同 DRAM 预算下,HyMCache 单节点服务比本地 LMCache 快 3.0 倍,PD 分离式服务快 1.45 倍。

核心贡献

  • 提出 HyMCache——首个将 CXL 混合内存(CXL-HM)作为远程 KV-cache 层集成到多轮 LLM 服务中的框架,暴露 SSD 支持的 TB 级容量作为 RDMA 可寻址的内存语义层
  • 表征多轮/智能体 LLM 访问模式(读主导、可预测的跨轮前缀重用、仅追加),表明通用商用 CXL-HM LRU 管理不足以应对此类工作负载,设计了针对 LLM 的 CXL-HM
  • 在 CXL-HM 内重新构思 DRAM 管理,通过请求级前缀预取和机会性写入缓冲两个机制,使延迟关键的读取保持在快速 DRAM 路径上
  • 在 vLLM/Dynamo 中实现 HyMCache 连接器,具有统一多设备 NUMA 地址空间、对象粒度放置及异构 KV 块大小支持

主要结论

  • 通用 CXL-HM 资源管理(如商用 LRU)无法满足智能体 LLM 服务;针对多轮 KV 重用的可预测性进行定制,使 CXL-HM 成为高效的远程 KV 后端
  • CXL-HM 是远程 LLM 服务的实用中间方案:以 SSD 级成本提供 DRAM 级 KV cache 效率,比 DRAM-only 层扩展性更好
  • 随着可复用 KV 足迹在轮次间增长,容量占据主导地位,HyMCache 与 DRAM-only 基线的性能差距随轮数增加而缩小

实验结果

  • 在相同 DRAM 预算下(64GB/worker,256GB 总量),HyMCache 单节点服务比本地 LMCache 快 3.0 倍,PD 分离式服务(4P-1D-1S 配置)快 1.45 倍
  • 与 1TB 分布式 DRAM Mooncake 相比,HyMCache 性能低约 30%,但使用 DRAM 少 16 倍;差距在后续轮次中缩小(SSD 容量保留更多可复用前缀块,命中率高约 10%)
  • FPGA CXL-HM 原型成本约 1.05-1.1 万美元,比 1TB Mooncake DRAM 层便宜约 2.8-3.8 倍
  • 在真实 CXL-HM 原型上评估,涵盖单聚合器和 PD 分离式服务配置
  • 与 LMCache、Mooncake(DRAM 和 NVMe-oF 变体)及 Redis 支持 LMCache 公平对比,附清晰成本效益分析
为什么重要: 首个将 CXL 混合内存用于多轮 LLM 服务的 KV cache 框架,以 SSD 级成本实现 DRAM 级 KV cache 效率,为 TB 级共享上下文容量提供了经济可行的远程 KV 层方案

Beyond Block Boundaries: Multi-Block Editing for Diffusion Large Language Models

⭐⭐⭐⭐☆ (4/5)
作者: Xingyu Mou, Zijin Huang, Tianze Zhang, Yuxin Ma, Lanning Wei  |  机构: Ant Group; Fudan University; Shanghai Innovation Institute  |  分类: cs.AI  |  日期: 2026-07-28
arXiv · PDF
块扩散已成为扩展离散扩散语言模型(dLLM)的主导范式,因为按固定大小块解码文本在保持每块内并行生成的同时控制了二次注意力成本。然而,这种效率带来了结构限制:块末尾的 token 生成时无法获取未来跨块上下文,一旦块确定,其不确定预测成为后续所有块的不可逆上下文。这造成块边界问题,不确定性沿块边界累积并向后传播。本文提出 Multi-Block Editing(MBE),通过基于跨块上下文编辑已解码 token 来缓解此问题。在 LLaDA2.1-Mini 的 13 个基准上,训练自由 MBE 超过所有现有解码基线,MBE SFT 再提升 2.7 分,AIME 2025 提升 13.3,ZebraLogic 提升 5.9。

核心贡献

  • 首次识别并定义块扩散语言模型(dLLM)中的"块边界问题"(block boundary problem):块末尾 token 生成时无法获取未来跨块上下文,不确定预测不可逆影响后续生成,导致错误沿块边界累积并向后传播
  • 提出 Multi-Block Editing(MBE)训练自由解码算法:将块视为调度单元而非硬修订边界,通过重新打开已解码块的滑动窗口进行联合全注意力前向传播,基于熵的历史困惑水印自适应识别最不确定的块进行编辑修正
  • 提出 Multi-Block Edit SFT 策略:使用双向注意力掩码和逐步扩展编辑跨度的课程学习,弥合块扩散训练与 MBE 推理之间的注意力机制差异,将编辑窗口从 K=2 扩展至 K=4
  • 基础设施级优化:扩展 SGLang 的多形状 CUDA Graph 池和细粒度 KV cache 控制,使变长编辑过程在实践中高效执行

主要结论

  • 块扩散模型存在结构性的块边界问题,token 在块边界处缺乏未来跨块上下文,不确定预测不可逆地影响后续生成
  • MBE 通过跨块编辑有效缓解该问题:将块作为调度单元,以滑动窗口重做联合全注意力前向传播,使早期 token 能在新跨块上下文中被直接修正
  • 基于熵的历史困惑水印可自适应定位最不确定块进行编辑;SFT 通过双向注意力掩码和课程学习进一步扩展有效编辑范围
  • 实验验证训练自由 MBE 优于所有现有解码基线且保持可比吞吐,MBE SFT 进一步提升性能,长程一致性任务改善尤为显著

实验结果

  • 训练自由 MBE 在 LLaDA2.1-Mini 的 13 个基准上平均分 61.14,超过全部 5 个基线(标准解码 60.44、ReMDM 60.66、RDD 55.81、Saber 60.46、DCD 58.93)
  • MBE SFT 进一步将平均分提升至 63.10(+2.7 over Standard Decoding)
  • 改善集中在需长程一致性的任务:AIME 2025 +13.3、ZebraLogic +5.9;知识密集型 GPQA 上略低于标准解码,说明事实性错误源于模型知识缺口
  • 质量-吞吐权衡:MBE 方法处于帕累托最优区域,在 BFCL v3 和 Spider 上 TPF 甚至超过标准解码
  • 跨规模泛化:在更大的 LLaDA2.1-Flash 上 5 类基准中 4 类提升(ZebraLogic +4.0、MBPP+ +2.38),证明跨块修正效益不随模型容量增大而消失
为什么重要: 识别并解决了块扩散语言模型的结构性"块边界问题",MBE 框架(训练自由解码 + SFT + 工程优化)在 13 个基准上超过所有基线,且扩展了 SGLang CUDA Graph 和 KV cache 控制,对 dLLM 推理质量与效率均有直接贡献

PRESTO: Prefix-Aligned Tree Drafting for Diffusion Speculative Decoding

⭐⭐⭐⭐☆ (4/5)
作者: Zheng Wang, Zhifan Ye, Qi Cheng, Yonggan Fu, Ziyan Wang 等 11 人  |  机构: University of Illinois Urbana-Champaign; Georgia Institute of Technology; NVIDIA  |  分类: cs.AI  |  日期: 2026-07-28
arXiv · PDF
扩散大语言模型(dLLM)作为自回归 LLM 的替代方案,可并行生成 token,使其成为投机解码的有效草稿模型。然而现有基于扩散的草稿方法依赖线性草稿,未充分利用 dLLM 的多候选结构,限制了接受长度和解码效率。本文提出 PRESTO,将树形草稿扩展到扩散草稿器,通过前缀对齐评分和基于优先级的树搜索,解决扩散草稿置信度与前缀 AR 验证之间的根本不匹配。在 dFlash 上平均 1.5 倍端到端吞吐加速,在自推测扩散 LLM 上平均 1.12 倍。

核心贡献

  • 首次形式化揭示了扩散草稿评分与基于前缀的自回归验证之间的根本不匹配:扩散边缘分布是前缀盲的(prefix-blind),无法为树形草稿提供可靠的路径排序
  • 提出 PRESTO 框架,通过最小化修正将前缀条件兼容性信号 ρ_d 融入扩散边缘 q_d,实现 prefix-aligned scoring,并以基于优先级的树搜索构建候选路径
  • 首个同时适用于专用扩散草稿器(dFlash)和自推测扩散 LLM(Nemotron-Labs-Diffusion)的树形草稿框架,并给出基于 prefix-mass 分解与 KL 正则化的理论支撑
  • 将树构建形式化为在统一路径分数下的优先级扩展,无需手工调参即可跨树预算/草稿器/目标模型泛化

主要结论

  • 扩散概率虽提供强全局合理性信号,但本质上前缀盲,不足以可靠排序树形草稿候选路径

HeraSys: Collaborative Serving of Multiple LLM Workflows via Fine-Grained End-to-End Optimization

LLM 的普及使服务系统从处理孤立请求转向编排高并发、多租户 agentic 工作流。现有方案优先工作流内优化,忽略了工作流间优化的巨大潜力。本文提出 HeraSys——一个设计用于优化并发工作流端到端性能的 LLM 服务系统。通过细粒度编排,HeraSys 通过结构化节点合并和复用消除跨工作流计算冗余。此外,HeraSys 引入负载感知联合调度策略,动态管理执行顺序。实验表明 HeraSys 在严格延迟保证下将 P99 延迟降低最高 2.17 倍,服务吞吐提升最高 1.85 倍。

核心贡献

  • 提出 HeraSys——针对多工作流 LLM 服务场景的细粒度端到端服务系统,通过双层优化(执行前图融合 + 运行时调度)打破请求级别隔离
  • 执行前图融合器:在并发查询中识别冗余子图(嵌入/检索/工具/共享前缀),通过签名匹配结构性地合并到单个执行实例,结合异步缓存重用
  • 负载感知联合调度器:基于 SRTF 的动态优先级,结合拓扑感知和抗饥饿提升、资源倾斜机制及自适应批处理/流水线分解
  • 提供形式化问题建模(资源/决策变量、NP 难度证明、具竞争性和活性的在线求解器),在 Ray 和 vLLM 上实现原型

主要结论

  • 通过细粒度编排和跨工作流节点合并/复用消除跨工作流计算冗余,可显著提升端到端多租户 LLM 服务性能
  • 双层设计是协同的:单靠调度不够——冗余移除至关重要,单靠 SRTF 损害尾部延迟,联合优化是必要的
  • 负载感知调度加资源倾斜缓解异构工作流中的阻塞和饥饿,在保持低平均延迟的同时减少尾部延迟(P99)

实验结果

  • 测试平台:Ray 原型,4× RTX 4090,vLLM 后端,Llama-3-8B,bge-large-en-v1.5 + bge-reranker-large;对比 LangGraph、LlamaIndex 及 Ayo
  • 延迟:平均延迟降低 35.2%(带重排 RAG)和 30.7%(不带重排 RAG),Web Search 工作流降低 41.8%
  • 吞吐:可达 Ayo 的 1.50 倍,约为传统模块化框架的 2 倍;P99 延迟最高降低 2.17 倍,服务吞吐最高提升 1.85 倍
  • 消融:禁用图融合将吞吐限制为完整版的 1/1.16;恢复 FCFS 使 P99 增加 12.5%;仅 SRTF 使 P50 降低约 13% 但 P99 增加 22.3%
  • 去重验证:对重复查询(Zipfian 热点文档,注入 5-15% 重复)系统比基线更高效应对不断增加的负载
