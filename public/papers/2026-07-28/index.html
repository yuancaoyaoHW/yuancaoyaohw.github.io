RTP-LLM: High-Performance Alibaba LLM Inference Engine

⭐⭐⭐⭐☆ (4/5)
作者: Boyu Tan, Jiarui Guo, Zongwei Lv  |  机构: Alibaba Group (†, 主要), Peking University (§), Zhejiang University (‡)  |  分类: cs.OS  |  日期: 2026-07-28
arXiv · PDF
大语言模型(LLM)深刻变革了人工智能应用,但其大规模部署仍面临巨大挑战。本文提出 RTP-LLM——一个面向工业级 LLM 部署的高性能推理引擎,已在阿里巴巴集团内部成功落地,服务于超 1 亿用户。RTP-LLM 通过整合式设计解决核心瓶颈:采用文件序驱动 I/O 与 I/O-通信并行重叠优化模型加载;Prefill-Decode 解耦架构将计算密集的 prefill 与访存受限的 decode 分离,结合分层多级 KV cache 管理实现高效缓存复用;此外集成支持多种算法的模块化投机解码、自适应 KV cache 量化解耦的多模态处理以及多级并行。在 8B-235B 参数的多种模型架构上进行了全面评估,涵盖受控基准与真实生产流量。结果表明 RTP-LLM 显著优于 vLLM 与 SGLang:模型加载加速 4.7-6.3 倍,生产流量调度下 TTFT P95 降低 35-37% 且缓存复用提升 215%,投机解码与多模态推理吞吐分别提升 1.12-2.48 倍和 1.86-2.52 倍,量化推理下批延迟降低 35-40%、TTFT 提升 1.9-3.0 倍。其生产验证的架构与开源可用性使其成为工业级 LLM 部署的综合解决方案。

核心贡献

  • 提出并开源 RTP-LLM——一个面向工业级规模部署的高性能 LLM 推理引擎,已支撑阿里巴巴集团超 1 亿用户生产流量,将内存管理、调度、硬件加速整合到统一的生产级平台。
  • Prefill-Decode 解耦(PD)架构:把计算密集的 prefill 与访存受限的 decode 分离调度,配合分层多级 KV cache 管理(本地+远程+前缀采样哈希匹配)实现高效 cache 复用
  • 针对 MoE 用 DeepEP/NCCL IBRC 做跨节点 KV 传输。
  • 工程级系统实践:层次化负载均衡、统一多模态请求编排、按实时流量动态调整 prefill/decode GPU 内存配额的自适应资源分配
  • 模块化投机采样框架、自适应 KV cache 量化、ViT-LLM 解耦处理。

主要结论

  • RTP-LLM 通过整合式设计(模型加载优化、PD 解耦、分层 KV cache、模块化投机解码、自适应量化、解耦多模态、多级并行)系统性地解决工业级 LLM 推理瓶颈,在公开基准与真实生产流量上均显著优于 vLLM、SGLang。
  • 该架构已成功支撑阿里巴巴多个关键业务单元的亿级用户生产部署,验证了生产可用性与 SLO 保障能力。
  • 作为开源软件发布,为 LLM 推理研究提供可扩展基础,已在社区获得活跃采用。未来计划探索 DSA(DeepSeek Sparse Attention)等加速技术。

Blink: CPU-Free LLM Inference by Delegating the Serving Stack to GPU and SmartNIC

⭐⭐⭐⭐⭐ (8/5)
作者: Mohammad Siavashi, Mariano Scazzariello, Gerald Q. Maguire  |  机构: KTH Royal Institute of Technology (Stockholm, Sweden); RISE (Stockholm, Sweden)  |  分类: cs.OS  |  日期: 2026-07-28
arXiv · PDF
大语言模型（LLM）推理正迅速成为数据中心的核心服务，但现有服务栈将主机 CPU 留在编排和逐 token 控制的关键路径上。这使 LLM 性能对 CPU 干扰极为敏感，破坏了应用共置，并迫使运维人员预留 CPU 余量，造成大量算力闲置。我们提出 Blink——一种端到端服务架构，通过将职责重新分配到 SmartNIC 和 GPU 之间，将主机 CPU 从稳态推理路径中移除。Blink 将请求处理卸载到 SmartNIC，由其通过 RDMA 将输入直接送入 GPU 显存；并用一个持久化 GPU 内核取代主机驱动的调度，在无 CPU 参与的情况下完成批处理、调度和 KV 缓存管理。与 TensorRT-LLM、vLLM 和 SGLang 相比，Blink 即使在隔离环境下也优于所有基线：饱和前 P99 TTFT 降低高达 8.47 倍，P99 TPOT 降低高达 3.40 倍，解码吞吐量提升高达 2.1 倍，每 token 能耗降低高达 48.6%。在 CPU 干扰下，Blink 保持稳定性能，而现有系统则退化高达两个数量级。

核心贡献

  • 识别控制路径依赖为 LLM 推理的关键瓶颈——证明现代服务系统依赖细粒度、主机驱动的控制，使其对 CPU 干扰敏感并限制高效资源共享；
  • 提出 CPU-free LLM 推理架构 Blink——将主机 CPU 从稳态关键路径移除，把控制和数据职责重新分配到 GPU 与 SmartNIC DPU 之间；
  • 基于持久内核的 GPU 驻留控制——用 GPU 驻留调度器替代主机驱动的解码循环，实现连续批处理、调度和 KV 缓存管理而无需逐 token 的 CPU 交互；
  • 强性能与隔离收益——在隔离环境下优于 SOTA（吞吐量最高 2.1×、P99 TTFT 降低最高 8.47×），在 CPU 干扰下基线退化一至两个数量级时保持稳定。系统实现约 16k 行 CUDA/C++（GPU 后端）+ 17k 行 C/C++（DPU 控制/数据面，DOCA 3.2 SDK）。

主要结论

  • Blink 是一种 CPU-free LLM 服务架构，通过协同设计 SmartNIC 驻留入口、零拷贝 RDMA 直达 GPU 显存、以及 GPU 驻留持久化调度器（用于连续批处理、KV 缓存管理和 token 生成），将主机 CPU 从稳态推理路径中移除。
  • 在覆盖 dense 与 MoE 架构的四个模型（Llama-3 8B、Phi-4 15B、Qwen-3 32B、Qwen-3 30B-A3B）上，Blink 相对 TensorRT-LLM、vLLM、SGLang 将饱和前 P99 TTFT 降高达 8.47×、P99 TPOT 降高达 3.40×、解码吞吐量提升高达 2.1×、每 token 能耗降高达 48.6%，且在多租户 CPU 争用下基线退化一至两个数量级时保持稳定。
  • 更广泛地，Blink 表明持久化的加速器驻留控制结合 SmartNIC 驻留 I/O 可替代主机中介的编排，将推理与共享主机资源解耦是数据中心扩展时性能隔离与服务器整合的关键。

实验结果

  • 硬件：NVIDIA H100（96GB HBM3）、2× Intel Xeon Gold 6336Y（96 核 @2.40GHz，DVFS 关）、256GB DDR5、ConnectX-6 200Gbps、BlueField-3 DPU（16 ARM Cortex-A78, 32GB）、Linux 5.15。
  • 模型：Llama-3 8B（dense 8B）、Phi-4 15B（dense 14.7B）、Qwen-3 32B（dense 32B）、Qwen-3 30B-A3B（MoE 30B/3B active），均用 paged attention + fp16。
  • 基线：TensorRT-LLM v1.1.0（与 Blink 共用相同 TRT 引擎以隔离 CPU 编排影响）、vLLM v0.13.0、SGLang v0.5.8，均启用 CUDA Graphs，关闭 chunked prefill/prefix caching/CPU offloading 做受控对比。
  • 负载：ShareGPT v3 经 guidellm 工具，13 档负载 1–32 req/s，每档测 60s。
  • 干扰：pbzip2（45 线程压 50GB 文件）+ Ninja 编译 LLVM（45 并行 job），为推理预留 6 核、其余 90 核给干扰。

ThunderAgent: A Simple, Fast and Program-Aware Agentic Inference System

⭐⭐⭐⭐⭐ (8/5)
作者: Hao Kang, Ziyang Li, Weili Xu  |  机构: Georgia Institute of Technology; Carnegie Mellon University; University of Illinois Urbana-Champaign; Together AI; Individual Researcher  |  分类: cs.OS  |  日期: 2026-07-28

大语言模型(LLM)现已被用于驱动复杂的多轮agentic工作流。现有系统通过松散拼装孤立组件来运行agentic推理:一个LLM推理引擎(如vLLM)加一个工具编排器(如Kubernetes)。尽管agentic工作流涉及多个LLM与工具请求,这些系统在单请求级别分别调度与分配资源,缺乏对工作流的端到端认知,导致KV cache与工具执行环境管理次优。为应对这些挑战,我们提出ThunderAgent——一个快速、简洁且程序感知的agentic推理系统。我们首先将agentic工作流抽象为LLM Program,实现KV cache、系统状态与磁盘内存/网络端口等外部工具资产等异构资源的统一视图。在此抽象之上,ThunderAgent引入程序感知调度器与工具资源管理器,旨在最大化KV cache命中率、缓解内存不均衡并启用异步环境准备。在编码、路由与科学发现agent上的评估表明,ThunderAgent相对SOTA推理系统在serving吞吐上提升1.5–3.6×、RL rollout提升1.8–3.9×、磁盘内存节省最高4.2×。为促进可复现与未来开发,我们在GitHub开源全部系统实现。

核心贡献

  • 提出ThunderAgent——一个程序感知(program-aware)的agentic推理系统,核心创新有三点:
  • 将agent workflow抽象为LLM Program,作为跨多次模型调用与工具执行的一等调度单元,持久化追踪工作流ID、执行阶段(reasoning/acting)、调度状态、总token数及工具资源,解耦调度与执行后端(vLLM/SGLang/TensorRT-LLM)
  • 将agentic推理调度建模为受GPU内存约束的优化问题,最小化重计算与缓存开销、最大化prefill/decode吞吐,含两个关键机制:状态感知暂停(在内存压力时选择性暂停acting态workflow,保护reasoning态program,消除任意次优的KV cache驱逐)与动态迁移(基于全局program-aware等待队列在DP节点间迁移agent program以缓解内存不均衡)
  • 程序感知的工具资源管理,包括hook-based垃圾回收防止资源泄漏与异步环境准备。系统已开源(GitHub)并被SkyRL(NVIDIA Dynamo)等开源框架采纳。

主要结论

  • ThunderAgent是基于程序级抽象的快速、简洁agentic系统,该抽象贯穿每个agentic workflow整个生命周期追踪元数据。
  • ThunderAgent利用程序抽象进行运行时调度与资源管理:动态在GPU节点间调度program执行以缓解KV cache thrashing与内存不均衡,同时管理工具资源防止泄漏。
  • 实验显示ThunderAgent在serving上达1.48–3.58×、在RL rollout上达1.79–3.92×优于既有系统。

  • RL rollout 1.79–3.92×(mini-SWEAgent 375.4→671.8 steps/min
  • OpenHands 69.1→270.8)

SAGA: Workflow-Atomic Scheduling for AI Agent Inference on GPU Clusters

AI agent每任务执行数十至上百次链式LLM调用,而GPU调度器将每次调用视为独立,在步骤间丢弃数GB中间状态,使端到端延迟膨胀3-8x。我们认为这种请求级抽象与compound AI workload根本不匹配,并提出向程序级调度转变:将整个agent workflow(而非单次推理调用)作为一等可调度单元。我们提出SAGA,一个通过三大机制实现该抽象的分布式调度器:(1)Agent Execution Graphs捕捉workflow结构以预测跨tool-call边界的KV cache复用,达到Bélády最优离线策略的1.31x以内;(2)session-affinity batching配合work stealing,在保持全局负载均衡的同时共置相关请求;(3)Agent Fair Share,一个具有可证明有界偏差保证的task-completion-time公平性度量。在服务SWE-bench编码agent与WebArena浏览器任务的64-GPU集群上,SAGA相对带prefix caching与affinity routing的vLLM v0.15.1将任务完成时间降低1.64x(几何均值,p<0.001),同时GPU内存利用率提升1.22x,多租户干扰下SLO达成率99.2%。这些延迟增益伴随量化代价:峰值吞吐相对throughput-optimal batch调度约低30%,这一权衡适合主导compound AI使用的延迟敏感交互式部署。我们的结果表明workflow-aware调度对高效compound AI serving至关重要。

核心贡献

  • 提出将agent整个workflow(而非单次LLM推理调用)作为GPU集群调度的一等单元(program-level scheduling)。三大机制:
  • Agent Execution Graphs(AEG)捕捉多步推理结构,驱动Workflow-Aware LRU(WA-LRU)驱逐策略,在production trace上达到Bélády最优离线策略的1.31x竞争力(首个针对workflow-aware KV cache驱逐的经验竞争力界)
  • session-affinity batching+randomized work stealing,在保持cache局部性的同时实现cluster-wide负载均衡
  • Agent Fair Share(AFS)——基于task completion time的公平性度量,通过Lyapunov drift分析给出有界偏差保证(Theorem 2)。还引入tool-call-aware TTL(对数正态拟合的工具延迟分布自适应保留KV cache)与speculative prefetching。理论分析刻画了request-level vs workflow-aware调度的cache效率gap。系统实现为vLLM v0.6.0扩展(8.5K Python+1.2K C++/CUDA)。定位为首篇将workflow-aware caching、distributed scheduling、tool-aware TTL、task-level fairness统一在经验竞争力界下的工作(Table 11与Parrot/Autellix/Pie/KVFlow逐维对比)。

主要结论

  • 论证并实证:当workflow结构显式暴露给调度器时,online KV cache管理可逼近offline-optimal Bélády策略(1.31x),这是compound AI workload下online调度器可达上界的首次经验量化。三大经典系统原理(HPC workflow调度、informed caching、application-level fairness)经非平凡领域特化扩展后可部署于真实GPU集群。在64-GPU集群上SWE-bench/WebArena分别取得1.73x/1.55x TCT加速(几何均值1.64x,p<
  • 0.001),内存利用率提升1.22x,多租户干扰下SLO达成率99.2%。代价为相对throughput-optimal batch调度约30%峰值吞吐下降,适合latency-sensitive交互式部署而非批处理。明确列出7项局限(workflow observability、tool-latency黑天鹅、novel agent任务时长估计、单数据中心、仅Llama-3-70B未覆盖MoE/Mistral/Qwen/DeepSeek、未验证>
