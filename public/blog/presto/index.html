PRESTO

Prefix-Aligned Tree Drafting for Diffusion Speculative Decoding

扩散语言模型天生适合做多路径候选起草器——但块内位置边际分布对"在树中选了哪条前缀"不敏感。PRESTO 通过在边际对数分数上叠加前缀校正项 + 优先级树搜索，缓解构树阶段的前缀盲性。

背景：扩散模型作为投机解码起草器

扩散语言模型（dLLM）能在一次前向传播中并行生成一整块 token，这使它天然适合作为投机解码（SD）的起草模型：起草阶段极高效，目标模型只需一次验证即可接收/拒绝整块候选。

关键优势： 扩散起草器一次前向就能产出一整块（如 16 个位置）的候选 token，形成丰富的组合空间——但现有方法只走了一条路。

问题：线性起草浪费了候选空间

现有扩散起草方法采用线性（单路径）起草：每个位置取 top-1，串成一条序列交给目标模型验证。但扩散模型在每个位置同时产出多个候选，形成巨大的组合空间——线性起草只探索了其中极小一部分。

实测证据（Qwen3-4B-DFlash，block size=16）： GSM8K 的接受长度从线性起草的约 6.5 到 top-10 oracle 上界的约 9.78；Math500 从约 7.9 到约 11.16。差距显著，说明候选空间远未被充分利用。（具体数值依模型与实验设置而变，下同。）

根本矛盾：构树阶段的前缀盲性

把树起草直接搬到扩散起草器上为什么不行？因为存在一个结构性矛盾：

  • AR 验证是前缀条件化的： 验证从左到右进行，第 $i$ 个 token 是否被接受取决于它前面的所有 token 是否都被接受。接受概率按链式法则分解。
  • 扩散块内边际不随树中前缀选择而变： 扩散起草器在固定提示、固定扩散状态下一次产出整块的位置级边际分布 $q_i(x_i)$。对于同一个位置 $i$，无论树中该节点之前选择了哪条候选前缀，$q_i(x_i)$ 的取值不变。因此仅用边际分数扩展候选树时，不同前缀无法影响后续节点的排序——这就是构树阶段的"prefix blindness"。
注意： prefix blindness 并不是说扩散模型对整个历史上下文完全不敏感。模型当然条件化于提示和已生成上下文；它针对的是"在同一个扩散状态上，用独立位置边际分数扩展候选树"这一具体限制。矛盾的根源是结构性的，而非训练不足。

三个关键观察

论文在 Qwen3-4B-DFlash（block size=16）上做了细致的经验分析，揭示三个关键事实：

观察 1：线性起草有巨大提升空间

对比线性起草与 oracle 上界（每个位置保留 top-10，做位置级 oracle 匹配），所有任务上都存在显著差距。GSM8K 从约 6.5 到约 9.78，Math500 从约 7.9 到约 11.16——线性起草远未充分利用候选空间。

观察 2：边际置信度与全局接受率正相关

扩散边际置信度 $c_i^{\text{diff}}$（幂次化的边际概率）与实际接受率呈单调正相关——高置信度 token 确实更可能被接受。但校准曲线始终低于理想 $y = x$ 线，说明边际置信度有信息但不完美。

观察 3：边际信号不充分，前缀条件化可补充

在相同 $c_i^{\text{diff}}$ 分箱内，按前缀兼容性 $c_i^{\text{prefix}}$ 分为低/中/高三组，接受率从低到高递增——说明前缀条件化提供了边际置信度之外的预测信号。校正项 $(c^{\text{prefix}} - c^{\text{diff}})$ 与真实残差正相关（但相关系数远低于 1），是有方向性但含噪的校正信号。

洞察： 有效打分应保留边际的全局信号，同时在边际对数分数上叠加可控的前缀校正项——而非用校正替换或与边际做凸插值。

PRESTO：前缀对齐打分

PRESTO 的核心是在扩散边际对数分数上叠加一个前缀条件化校正项，由 $\lambda$ 控制校正强度：

$$s(y_i) = \log q_d(y_i) \;+\; \lambda\, \log \rho_d(y_i \mid y_{

等价乘法形式：$q_d(y_i)\cdot \rho_d(y_i \mid y_{

  • $\lambda = 0$： 退化为只使用扩散边际分数 $\log q_d$——构树阶段前缀盲，路径排名不可靠。
  • $\lambda \gt 0$： 在边际之上引入自回归前缀校正 $\lambda \log \rho_d$；边际项始终保留，不被消除。
  • $\lambda$ 过大： 校正项可能压过扩散边际信号，导致树的多样性或覆盖率下降——但边际项不会归零。
为什么是叠加而非插值： 论文采用乘法形式 $q_d \cdot \rho_d^{\lambda}$，取对数后边际项系数恒为 1，$\lambda$ 只缩放校正项。这保证 $\lambda=0$ 时退化为纯边际（前缀盲），而 $\lambda \neq 0$ 时边际信号始终存在。可解释为 KL 正则化目标——在保持接近 $q_d$ 的同时向 $\rho_d$ 对齐。
关于最佳 $\lambda$： 论文消融显示适度的前缀校正通常优于完全关闭或过强校正，但最佳值依模型与实验设置而变化。页面下方的动画为示意，不宣称某个具体 $\lambda$ 值在所有设置中普适最优。

优先级树构建

有了可加分解的路径打分 $S$，树构建自然归约为优先级展开：维护待展开节点的前沿，每次展开打分最高的节点。关键在于子节点累计分数从父节点增量继承：

$$S(\text{child}) = S(\text{parent}) + \log q_d(\text{token}) + \lambda \log \rho_d(\text{token} \mid \text{prefix})$$

即：父节点累计路径分数 + 当前深度的局部增量 = 子节点累计分数。不要只用子节点当前 token 的局部分数重新排序而忽略父路径。

两种展开策略

策略前沿管理特点
Best-First Search (BFS)全局优先队列灵活，大预算下略优
Beam Search + Global Retention每层保留 top-B，跨层保留宽度受限的 BFS 近似
为什么默认用 Beam Search： 在小到中等预算下，BFS 与 Beam Search 接受长度接近；预算超过硬件阈值后验证从 memory-bound 转向 compute-bound，前向代价随预算线性增长。PRESTO 在 memory-bound 区间内运行，采用 Beam Search 为默认。

扩展到混合扩散 LLM（二次自投机）

Nemotron-Labs-Diffusion 提出二次自投机：单次前向传播中同时进行 AR 验证（验证上一轮起草树）和扩散起草（在尾部 mask 位置生成下一轮候选）。

线性自投机的结构性低效

若把一次扩散调用产生的多个位置预测组织成单条线性草稿，一旦中间某个 token 被验证器拒绝，该路径后续位置已经计算出的预测就无法继续被这条路径使用。这不是说所有计算都严格丢失，而是拒绝后该路径后缀失效的覆盖率问题。

PRESTO 的改进逻辑链

  1. 一次扩散调用产生多个位置的高概率候选。
  2. PRESTO 把这些候选组织成树，而非单条线性草稿。
  3. 当主分支被验证器拒绝时，其他共享前缀或替代分支仍可被验证器继续检查。
  4. 因此树结构提高了同一次扩散结果的候选覆盖率和复用机会，缓解"拒绝后整段后缀失效"的问题。

消融：$\lambda$ 敏感性

过小 $\lambda$ → 退化为纯边际打分（前缀校正不足）；过大 $\lambda$ → 校正项压过边际信号（多样性/覆盖率下降）。论文消融显示适度校正通常最优，最佳值依模型与实验设置而变化。熵自适应 $\lambda$ 仅带来边际改进，说明固定 $\lambda$ 在实践中已足够。

开销分析

目标模型验证占总延迟的 81%–97%，树构建操作（树构造、候选过滤、attention mask 准备）仅占 0.7%–4%——PRESTO 的系统开销可忽略。

总结与核心框架

一句话记忆： PRESTO = 保留扩散边际的全局信号（$\log q_d$ 始终在）+ 在边际之上叠加前缀校正（$\lambda \log \rho_d$）+ 优先级树展开最大化接受长度
组件解决的问题机制
前缀对齐打分构树阶段前缀盲$\log q_d + \lambda \log \rho_d$，叠加而非插值
优先级树展开线性起草只探索一条路径Beam/BFS + 父子增量累计分数
二次自投机扩展线性草稿拒绝后后缀失效树组织候选，提高覆盖率与复用

局限与展望

  • n-gram 只捕获短程词法兼容性——更丰富的前缀信号（如学习型）是未来方向
  • 主要在单请求解码设置下评估——扩展到 vLLM/SGLang 生产级服务是未来工作
  • 熵自适应 $\lambda$ 仅边际改进——可能需要学习型或目标感知调度
